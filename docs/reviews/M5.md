## Findings

The campaign's product is not the policy; it is the list of runtime defects the policy exposed. Every
one below was found by measurement after training had already been blamed, which is the pattern
§28.9's "harness-first" rule (M5-R1) exists to break. Each is closed unless marked.

### Blocker

- **B-1** `es-eval` — a suite's numbers depend on which other suites are in the document. The nominal
  suite of `evaluation-v8.toml` trimmed to one suite scores 0.625 on a checkpoint whose six-suite sweep
  scores 0.5625 on the same nominal seeds, with different cells succeeding; `--jobs` is excluded (byte
  identical at 4, 6 and 8). §10.4 says "every suite draws from its own stream, so adding one of these
  rows cannot move another's numbers", and every trimmed-document table from V11 onward relied on it.
  Open question 28. Not a wrong number — each run reproduces under its own document — but a stated
  invariant that does not hold, and the reason this review reports every figure beside the document it
  was measured under.

### Closed during M5 (each now a rule candidate for the spec)

- **F-1 envelope semantics** (V6, §9.3). The plane's dynamic stages bounded the servo's following
  error on one path and the plane's own commands on the other. Rule: velocity/acceleration/rate limits
  bound the plane's command chain; `envelope_reference.rs` pins it.
- **F-2 control period** (V11, §12.1). One recorded row was one physics step: the demo ran at 200 Hz
  against a 50 Hz document. Rule: the inference period is derived from `rate.control` and the physics
  timestep (`BatchDomains::single_env_at`), and a non-dividing pair is refused by name.
- **F-3 observation–action pairing** (V12, §13.2). The row carried the post-step state beside the
  action computed from the pre-step one. Rule: a record pairs the observation with the action computed
  from it; the frame and the trajectory are taken at the same instant.
- **F-4 trained function ≠ deployed function** (V13, §8.3). Single-sample lowering plus BatchNorm
  trained N=1 statistics and deployed running ones. Rule: a lowering is the same function in train and
  eval mode, asserted bit for bit; from-scratch backbones lower with GroupNorm.
- **F-5 the declared re-plan rate was a document nobody read** (V17, §9.2). Both loops inferred every
  control tick; rows 1.. of every chunk were dead. Rule: `es_env::replan_interval` on both paths;
  non-dividing refused.
- **F-6 the plane's clock** (V17, §9.4). Both loops handed `SafetyPlane` the simulation tick while its
  period is the control period. Rule: the plane's `now` is the control tick, stated in the API.
- **F-7 deadlines against the re-plan period** (V17, §9.4). A 5 Hz re-plan cannot meet a 40 ms
  `inference_budget`. Rule candidate: `DEP_0xx` — `inference_budget` below one re-plan period is a
  validation warning, since the runtime waits a full period by design.
- **F-8 the envelope as the measurement** (V18, §9.3). At `acceleration_max = 20` the plane clamped
  99.8 % of the policy's ticks and latched the fallback for a tenth of every run; every number from V13
  to V17 measured the plane. Rule: `envelope_violation_rate` and the latched fraction are reported beside
  `success_rate`, and the envelope is derived from the actuator (fixture comment), not from caution.
- **F-9 the import invented a measurement** (V19, §8.4). `import-lerobot` wrote the inference budget
  into `expected_latency_ms`, which `LRN-052` then refused once the budget exceeded the re-plan period.
  Rule: an import declares the bound, `min(budget, period)`; a measurement comes from `es bench`.
- **F-10 MJCF emitter drops** (B1/B1b, §17). `ls_iterations`, `eulerdamp`, geom `priority`,
  `inheritrange` and duplicate auto geom names. Rule: emitter round-trip parity is an oracle, not an
  assumption.

### Should-fix

- **S-1** `es-eval/src/runner.rs` — no inference-latency model; `es loop collect` delays every chunk by
  `expected_latency_ms` through `AsyncInference`, the evaluator executes at tick 0. Traces of one seed
  diverge at tick 1 (open question 24, ladder rung 5). A policy evaluated with zero latency is evaluated
  on a robot that does not exist.
- **S-2** `execution_hash` reads measured values at run time (`runtime`, `hardware_capability`): two
  bit-identical evaluations, one under GPU contention, carry different names (open question 26).
- **S-3** dataset ↔ predicate provenance. The demonstrations collected against `gripper > 0.6` and those
  against `> 0.85` sit side by side on the server and nothing in the tree marks one as retired; V19's
  packet named the wrong one and measured 0/16 by construction (open question 27). The `task_hash` the
  collection was taken under is already in the export; `dataset bake/export` and `import-lerobot` should
  refuse or flag a mismatch with the current document.
- **S-4** `es-telemetry` transport test is load-dependent (L15); accept `ECONNRESET` or serialise it.
- **S-5** the `es` CLI oracles (`expert_passes_the_evaluation_harness`, cadence parity, replays) run only
  on the oracle server; the GitHub oracle tier should run them with `ES_PYTHON` set.
- **S-6** `--jobs N` with the torch runtime is not byte-identical to `--jobs 1` (thread-count-dependent
  reductions, open question 16); the report should carry the thread cap it ran under.
- **S-7** the declared safety limits `es-safety` does not enforce (`ee_velocity_max`, contact, distances;
  L6, ladder rung 12) are still documented limits, not live ones.
- **S-8** `Cargo.lock` is gitignored, so `compiler_hash` does not reproduce a build (L11, rung 7).
- **S-9** the Learning IR's 16-row horizon and the lowered `[10, 6]` chunk of the IR-graph policy
  disagree with each other and with the documents that describe them; under a 10-tick re-plan a 16-row
  chunk keeps two chunks live and a 10-row one does not, and the two policies were compared across that
  difference (section 7.27).
- **S-10** the showcase renders at about 80 ms per frame and the PT tonemap has no oracle (V9).
- **S-11** `Feature::ContactPriority` is carried through the emitter without a capability flag.
- **S-12** the quadruped fixtures ship placeholder weights with no test that the bundle refuses to
  evaluate them as a policy.

### Nit

- `terms.py`/`grip.py`/`probe.py` live on the server, not in `python/es/`; the pre-step/post-step rule
  they must respect is documented in three places and enforced in none.
- `docs/design/visible-learning.md` is ~4,400 lines; the record outgrew the spec it serves.

## Verdict

**M5 gate: passed on the re-stated criteria.** An ACT that this project did not design and did not
train runs through its Observation IR, Deployment IR, Safety Plane and evaluation as the same function
to the last bit, and on the committed documents it clears the demo's acceptance on training and held-out
seeds with the plane clamping a fifth of its ticks and never falling back. That is §8.1's promise
discharged on a real artefact, which is what the owner said the project is for. What the milestone
cost — ten runtime defects found one at a time behind a policy that was blamed first — is the finding
that matters for the spec: none of F-1..F-10 was a learning problem, and the oracle-first rule (§1.4)
was honoured in form (every packet had a runnable oracle) and broken in substance (the oracle tested the
policy, not the harness) until V6. B-1 is the one open correctness item and it does not touch the
demo's record, which was measured under the full document. The safety invariants held throughout: the
plane was widened twice (INV-12: deadlines in V17, `acceleration_max` in V18) and never bypassed,
`validate` kept its signature (INV-13), no pickle entered (INV-16), no trait was added (INV-17).
