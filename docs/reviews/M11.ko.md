## 플랜 X가 하려던 것과 한 것

오너는 2026-09-23에 sim-to-sim(Isaac과 MuJoCo에서 학습된 정책의 I/O를 맞추는 것), vision RL을 위한
도메인 랜덤화, 틱별 시드와 SVGF로 처리하는 PT 노이즈를 요청했다. 오너는 Isaac Sim이 백엔드가 되는 것, 시각
랜덤화가 네 그룹 모두를 덮는 것, vision RL이 `Pt` 위에서 학습하는 것을 결정했고, 2026-09-24에는 X7 재실행이
픽셀 전용 행 네 개를 4 spp에서 덮도록 결정했다. 오라클 서버(Linux, RTX 4090)와 Windows RTX 3060 박스에서
측정했다:

- **디스패치 하나, 엔진 네 개(X1, I0, I1, R1).**
  - `es eval run`, `es loop collect`, `es_native.Rollout`은 `--backend`로 `mujoco-cpu`, `mjwarp`, `physx`(Isaac Sim 5.1,
    PhysX 107.3, CPU 또는 GPU 파이프라인)를 받는다. `newton`은 자신의 매핑 보고서로 거부된다.
  - MuJoCo와 MJWarp는 접촉 전까지 1e-7로 일치한다. MJWarp의 타원 원뿔은 오너가 스펙 17.2를 완화한 뒤 tier 2로 허용된다.
  - PhysX의 CPU와 GPU 재실행은 비트 단위다. MJWarp 재실행은 그렇지 않다.
- **어댑터 v2(X2).**
  - 무엇을 하는가: Isaac Lab이나 Playground 정책의 조인트 이름, 기본 자세, 항별 스케일, 액션 offset/scale,
    `last_action`이 번들로 컴파일되며, `ObsSource::PreviousAction`이 유일한 새 Task IR variant다.
  - 정확도: rsl_rl 레퍼런스 대비 1.2e-7, Playground 대비 7.6e-8.
  - 무엇을 거부하는가: 관측 클리핑에는 `Clamp` 노드가 없어 이름으로 거부된다.
- **모델 파라미터가 물리에 닿는다(X4).** `set_params`는 직접적인 `MjModel` 수정을 비트 단위로 재현한다, Linux == Windows.
  MJWarp는 이를 world별 모델 행을 통해 한다.
- **RL 루프 안의 픽셀(X3, X3b).**
  - `Rollout`은 각 env를 렌더하고, 그 프레임은 수집기의 것과 비트 단위로 같다.
  - `EnvBatchRenderer`는 env N개를 디스패치 하나에 담으며, env마다 world-space BVH 하나씩을 두고 타일은 단일 렌더와
    비트 단위로 같다.
  - 4090에서 64 spp 비용: env당 시간이 N = 16에서 62 ms에서 11.4 ms로 떨어진다.
  - 2^24 sample-bounce를 넘는 프레임은 행 단위 밴드로 나누어 추적해서, Windows 드라이버가 죽이지 않는다.
- **시각 랜덤화(X5, R2).**
  - 타깃: `light.{intensity,direction,color,ambient,radiance,sky}`, `geom.<n>.rgba`, `camera.<n>.pose.*`, `camera.<n>.fov`.
  - `Pt`에 방향광(`light.radiance`)이 생긴다. 추출된 fov는 에피소드의 내부 파라미터를 움직인다.
  - R2 이후, 수집기·평가기·`Rollout`은 추출 하나를 프레임 하나로 렌더한다.
  - 남은 `Cross` 내장 둘은 정확하게 측정됐다. 카메라의 `Cross`는 드라이버 하나에서 fuse되어 있었고 다시 작성됐다(X5).
- **PT 노이즈(X6, U6).**
  - `render.svgf`는 선언된 필드이고, 0 ULP GPU == CPU, 비용은 +3.9 ms/프레임.
  - 데모의 `Pt` 행에서 학습 시드 두 개씩, SVGF는 홀드아웃 성공률을 시드 폭보다 더 움직이지 않는다:
    U5 0.25 / 0.375, U6 0.375 / 0.0625.
  - SVGF는 반복적으로 최종 loss를 올린다: 두 시드 모두에서 0.0047 대 0.0021.
- **Sim-to-sim, 측정됨(I3).**
  - Isaac Lab에서 학습된 SO-101 reach 정책 세 개는 Isaac 자신의 홀드아웃 리셋에서 평균 0.76을 낸다. 어댑터 v2를 거쳐
    가져오면, `physx` CPU에서 평균 0.52, `physx` GPU에서 0.56, `mujoco-cpu`에서 0.56, `mjwarp` 실행 두 번에서
    0.58 / 0.46을 낸다.
  - 여기서 학습한 A0는 `mujoco-cpu`의 0.42에서 `physx`의 0.19 / 0.08로 떨어진다.
  - 원인 규명은 단일 원인을 찾지 못했다:
    - 평가기의 한 틱짜리 액션 지연이 Isaac 자신의 정책들에 0.15를 대가로 치르게 한다;
    - joint damping을 제거하면 `physx` 위의 모든 Isaac 정책이 0이 된다;
    - frictionloss는 MuJoCo에서 가장 크게 움직이는 요인이다.
- **`Pt` 위의 vision RL(X7, R3).**
  - R3는 CPU 바이트를 움직이지 않은 채 트레이너를 CUDA에서 돌게 만들어, 반복당 갱신 시간을 18.9초에서 0.42초로
    줄였다.
  - 픽셀 전용 행들은 상태에서 큐브의 자세를 뺀 채 돌았다: `Pt`와 `Rs`, 랜덤화 켬/끔, 시드 3개, 4,000회 반복,
    `Pt`는 사전에 쓰인 규칙대로 SVGF를 끈 채 4 spp에서.
  - **정책 열두 개 모두 모든 홀드아웃 스위트에서 0.00을 낸다.** 학습 리턴은 시드 폭보다 덜 움직였고
    엔트로피는 모든 실행에서 올라갔다.
  - 비용: `Pt`는 반복당 래스터라이저 비용의 2.0–3.3배로 렌더되며, 실행 한 번을 2.8시간 대신 3.4–4.1시간으로
    만든다.
  - Cross-render 전이는 측정할 수 없었는데, XIR-040이 그것을 거부하기 때문이다(S-2).
- **해시 체인의 장면 구멍(R4).** `Env::new`는 이제 Task IR이 콘텐츠 해시를 고정하지 않은 장면을 거부한다. I3는
  커밋된 `execution_hash` 아래서 수정된 장면 네 개를 돌린 적이 있었다. `es task generate --scene`은 이제 로드된
  장면의 해시를 쓰며, 커밋된 태스크 문서 14개는 이미 모두 자신의 장면과 일치했다.

### 고쳐야 할 것

- **S-1(I3, X7; M10 S-3, 여전히 열려 있음).** `envelope_violation_rate`는 모든 I3 평가 셀과 모든 X7 학습
  반복에서 1.00이며, 그 아래서 0.69–0.94에 이르는 Isaac 정책들도 예외가 아니다. 엔벨로프는 학습 중이거나
  가져온 모든 정책의 모든 스텝에서 무언가를 클램프한다. 가져온 정책들에게는 그것이 한 틱짜리 지연, damping
  격차와 나란히 있으며, 0.76 → 0.52 하락의 일부다. 픽셀 전용 PPO에게는 그것이 정체된 리턴의 첫 번째 용의자다.
  오너가 M8 이후 미뤄 온 그 지렛대가 이제 이 캠페인의 양쪽 절반을 모두 막고 있다.
- **S-2(X7).** cross-render 평가는 표현할 수 없다. 센서의 `render` 블록이 Task IR 안에 있어서, `Pt`와
  `Rs`는 `task_hash`에게 서로 다른 태스크이고, 한쪽의 Evaluation IR은 다른 쪽의 번들을 거부한다(XIR-040,
  12개 중 12개). 그 거부는 지금 쓰인 대로의 §10.4 아래서는 옳으므로, "어느 렌더러가 전이하는가"라는
  질문은 우회책이 아니라 설계 결정을 필요로 한다. 예를 들면: render 블록이 평가 쪽 조건이 되거나,
  `evaluation_hash`에 들어가는 선언된 render override가 되는 것.
- **S-3(I3).** 평가기(`es eval run`)는 정책의 액션을 한 틱 늦게 적용하는 반면, Isaac Lab은 지연 0으로
  학습한다. Isaac 자신의 정책들은 그 한 틱만으로 0.15를 잃는다. 어댑터도 Deployment IR도 소스의 지연을
  선언할 수 없어서, 가져온 정책은 언제나 자신이 학습되지 않은 조건 아래서 점수가 매겨진다.
- **S-4(X1, I3).** MJWarp는 하나의 `execution_hash` 아래서 실행 간 재현 가능하지 않다: reach A0
  0.5625 대 0.4375 / 0.4375, Isaac 시드 0은 0.9375 / 0.8125. tier 2가 이를 허용하지만, 서로 다른 수치
  둘이 같은 해시를 지니고, 보고서는 어느 tier가 그것을 냈는지 말하지 않는다.
- **S-5(X1).** es-env는 리셋 시 자유 조인트에 0 쿼터니언을 쓴다. MuJoCo는 이를 정규화하는 반면, MJWarp와
  PhysX는 반 바퀴로 읽는다. 두 어댑터 모두 이제 정규화한다. 소스에서 고치면 커밋된 모든 `.estraj`의
  tick-0 행이 움직이므로, 있는 그대로 남겨 둔다. 다음 백엔드는 이를 알아야 한다.
- **S-6(R2).** reach 배포에 `--expert`를 쓰면 수집기와 평가기의 상태가 tick 2에서 갈라지고(qpos ~1e-5),
  데모 배포는 마지막 틱까지 일치한다. 원인은 열려 있다. 프레임 패리티 오라클은 상태가 일치하는 틱만
  비교한다.
- **S-7(M10 S-1, 여전히 열려 있음).** `quadruped_eval_run_names_the_observation_gap`은 `ES_PYTHON` 아래서
  여전히 실패하고 `xtask ci`의 fail-fast 테스트 단계를 멈춘다. 이번에 다시 읽은 것: 잘 형성된 빈
  safetensors만으로는 충분하지 않은데, 런타임이 관측 갭에 닿기 전에 체크포인트를 로워링된 그래프에 맞춰
  검사하기 때문이다(텐서 8개 누락). 픽스처는 로워링된 shape의 텐서를 필요로 하거나, 테스트가 대신 그
  체크포인트 거부를 고정해야 한다.
- **S-8(X3b).** 4090에서 `cargo test -p es-render --test render`는 동시 `VkDevice` 약 15개에서 멈춘다.
  `--test-threads=1`로는 67초에 통과한다. 모든 서버 실행은 그 플래그를 쓴다; 원인(드라이버 한계인지, 새
  테스트 때문인지)은 알려져 있지 않다.

### 사소한 것

- `RenderOverrides::image_spec`는 `fx_f64 * focal`을 기록하는데, `drawn_frame`은 `fx_f32 * (focal as f32)`로
  투영한다: 수집기 사이드카에서 f32 1 ULP(R2).
- 수집기는 각 에피소드의 render 추출을 `RandomizationPlan::apply_render`로부터 다시 계산하는데, es-data의
  `FrameSink`가 상태만 보기 때문이다. 같은 함수이지만, `env.render_overrides`를 sink로 통과시키는 쪽이
  더 깨끗한 형태다(R2).
- 장면 불일치 거부는 메시지만 있고 코드는 없는 `EnvError::Task`다. 스펙에는 그에 대한 코드가 없다(R4).

  잃어버린다; `es-telemetry`의 `a_connection_past_max_clients_is_refused`는 한 번 ConnectionReset으로
  실패했다. 둘 다 단독으로는 통과한다.
- `check-scope`는 여전히 작업 트리만 읽는다(M10의 사소한 것). X7은 자신의 커밋된 diff를 손으로
  확인했다.
- 프로세스: 어떤 에이전트가 GPU가 필요 없는 단계에서도 GPU 락을 쥐고 있었고, 에이전트들이 중복된 로컬
  대기 루프를 쌓았다(한때 14개). 이제 지침은 GPU 단계마다 락 하나, 대기자 정확히 하나를 요구한다. 에이전트
  둘이 오래된 worktree 베이스에서 시작해 fast-forward했다.
- Isaac: Kit은 잡히지 않은 예외 뒤에도 exit 0을 낸다, 그리고 Isaac Lab의 `env.yaml`은 safe YAML이 아니다.

## 판정

**M11: 통과, 측정된 부정적 결과 하나와 함께.**

만들어진 것:
- sim-to-sim이 처음부터 끝까지 지어졌다. 정책 하나가 엔진 네 개 위에서 폐루프로 돌고, 엔진은
  해시 체인의 조건이다.
- Isaac Lab 정책의 I/O 관례는 정확히 번들로 컴파일되며, 추론 시점에는 프레임워크 고유의 것이 아무것도
  없다.
- 모든 시각·물리 랜덤화 타깃은 프레임이 어디서 렌더되든 프레임이나 물리에 비트 단위로 닿는다.
- PT 노이즈는 선언된 필드 두 개다. 해시 체인은 구멍 하나를 잃었다: 실행은 이제 자신이 로드하지 않은
  장면을 주장할 수 없다.

측정된 것:
- **sim-to-sim은 가능하지만 손실이 있다.** Isaac의 0.76은 여기서 약 0.55가 된다. 그 격차는 지연, joint
  damping, 마찰 모델링에 걸쳐 퍼져 있고, 엔벨로프가 그 전체에서 클램프한다.
- **틱별 시딩은 돕고 SVGF는 돕지 않는다.** 틱별 시드는 M10의 결과였다. SVGF의 효과는 학습 시드 두 개의
  폭 안에 있다.
- **픽셀 위의 vision RL은 오늘의 레시피와 엔벨로프 아래서 학습하지 않는다.** `Pt`든 `Rs`든, 랜덤화를
  켜든 끄든, 시드 세 개씩에서 0.00을 낸다. 기계장치는 동작하고, RL 지렛대는 오너의 결정이다(S-1).
