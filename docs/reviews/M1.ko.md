## 발견 사항

### Blocker (차단)

- [BLOCK] `tests/golden/observation/*.json` + `crates/es-policy/src/weights.rs:186` — 게이트 5와
  6에는 참조 오라클이 없다: golden은 그것이 검사하는 코드 자체가 생성하며, "ACT checkpoint"는 우리
  자신의 `weight_shapes`로부터 만들어지므로, 잘못된 half-pixel 컨벤션이나 전치된 키 매핑이 잡히는
  게 아니라 그대로 굳어진다(§1.4). 수정: 체크인된 스크립트로 torchvision/LeRobot로부터 golden을
  재생성할 것; 키가 LeRobot에서 온 체크포인트를 사용할 것.

### Should-fix (수정 권장)

- [SHOULD] `crates/es-safety/src/plane.rs:288-302` — `accept()`는 내용의 동일성으로부터 chunk의
  신선도(freshness)를 추론하므로, 동일한 chunk를 재발행하는 정책(정지 유지, 포화된 출력)에서는
  `last_chunk_tick`이 결코 갱신되지 않아 정상 동작 중인 정책에서도 `InferenceDeadline`이 걸린다 —
  수정: 신선도를 바이트가 아니라 호출자로부터(시퀀스 번호, 또는 `submit` vs `reuse`) 얻을 것.
- [SHOULD] `crates/es-telemetry/src/transport.rs:274` — 인증 토큰에 대해 variable-time `String`
  비교를 사용한다; handshake 읽기에 timeout이 없고(`:201`은 영원히 블록됨) 연결 수 제한도 없어
  (`:128-135`가 연결마다 스레드를 spawn함) 상대방이 스레드를 점유시키고 이를 프로빙할 수 있다 —
  수정: 양쪽의 `blake3::hash`를 비교하고, `Hello` 읽기 전에 `set_read_timeout`을 설정하며, 연결
  수를 제한할 것.
- [SHOULD] `crates/es-compile/src/bundle.rs:484` — `want.is_some() && want != got`는 hash slot을
  생략한 manifest가 §5.3 검사를 전혀 거치지 않고 열리도록 허용하며, `signature`(`:105`)는 아무것에
  의해서도 검증되지 않는다 — 수정: `BundleKind::Policy`에 대해 6개 슬롯이 모두 존재할 것을 요구할 것.
- [SHOULD] `crates/es-compile/src/bundle.rs:315-368` — `read`는 마지막 payload 이후의 바이트를
  무시하여 `:313`의 유일성(uniqueness) 주장을 거짓으로 만든다 — 수정: `if c.at != bytes.len()` →
  error.
- [SHOULD] `crates/es-ir/src/factory.rs:93,103` — 게이트 10의 "frozen"은 doc comment에 불과하다 —
  수정: 두 목록에 대해 하드코딩된 `blake3`를 단언하는 테스트를 추가하거나, `xtask verify-goldens`가
  소유하는 golden으로 만들 것.

### Nit (사소함)

- [NIT] `crates/es-policy/src/lower/torch.rs:115,150` — 사용자가 지정한 port 이름이 Rust `{:?}`를
  거쳐 생성된 Python 코드에 도달한다; 따옴표 탈출은 없지만(`"`/`\`는 이스케이프됨) `escape_debug`는
  제어 문자에 대해 `\u{a}`를 내보내며 이는 Python이 거부한다 — 수정: `lower_to_torch`에서 식별자로
  안전하지 않은 이름을 거부할 것.
- [NIT] `crates/es-compile/src/bundle.rs:271,273` — `u32::try_from(..).unwrap_or(u32::MAX)`는
  에러를 내는 대신 잘못된 entry count/name length를 기록한다 — 수정: `?` 하나가 일관된 처리
  방식이다.
- [NIT] `crates/es-env/src/rng.rs:75-76` — `Normal`은 `sqrt`/`cos`를 `es_math::approx`(f32)를
  통해 라우팅하므로, Gaussian draw는 `f64` `Distribution` 대비 ~1e-7의 상대 오차를 가진다 — 의도된
  것이며 문서화되어 있음; randomization 범위가 f64로 명시되어 있기 때문에 기록해 둔다.

## 판정

**M1 게이트: 통과하지 못함 — Blocker 1건.** 기계적으로 검사 가능한 게이트는 모두 green이며
(`cargo xtask ci`가 exit 0, 크레이트 18개 모두 예산 이내, layering과 golden 클린), Safety Plane이
이번 마일스톤에서 가장 강력한 부분이다: 게이트 8은 실제로 충족되었고 INV-11/12/13은 적대적으로
읽어도 성립한다. 실패하는 것은 §1.4다 — M1의 두 핵심 게이트는 구현 자신이 만들어낸 아티팩트에 대해
검사되므로, 회귀는 잡아내지만 잘못된 답은 잡아내지 못한다.
