## Findings

### Should-fix (all fixed before this review closed)

- **S-1 An aborted demonstration poisoned every later episode** (P-M14-R1). The collector's
  wrapper never cleared its `aborted` flag at an episode's start: one genuine out-of-reach
  failure (episode 13 of the edited program's collection) turned the next 186 episodes into
  one-frame failures. The same wrapper kept a stale `injected` flag, so every expert dataset so far
  marked the first frames of each episode after the first as human-driven; re-collected
  datasets now differ in the `intervention` column and the content hash. The original program
  never aborts, which is why no earlier run showed it — the first person to edit a block did.
- **S-2 A diverged training was invisible and ran to the end** (P-M14-R1). `NaN` is not JSON:
  `es train` and the telemetry wire dropped every progress line after the first NaN, so the light
  stayed green while 4,000 NaN steps, NaN checkpoints and a full evaluation followed. Now `null`
  on the wire, NaN in the editor, *broken* outranks *stopped*, and the trainer stops at the first
  non-finite loss.
- **S-3 The cycle trained on a collection that mostly failed** (P-M14-R1): 10 good
  demonstrations and 190 failed ones. The expert gate cannot catch it — it judges 16 evaluation
  episodes, the collection 200 others. The cycle now refuses, before the train stage, below half.
- **S-4 Attaching mid-collection counted only what was heard** ("2 of 200" when 25 were done) —
  fixed (`9ef9b24`).
- **S-5 The panels could not scroll** (the owner: "패널에 스크롤바좀 붙여줘", "아래 패널도 문제") —
  the dock gave no pane a scroll bar and egui's bar is invisible until hovered; fixed (`3df5386`).
- **S-6 A failure named by the wrong cause** (M13 follow-ups R4, R5): an attempt that put the
  cube in the bin, or held it over the bin, without opening the gripper read *too late* or *left
  outside*. Now *not released*; R4's first advice was itself wrong ("wait longer after opening"
  adds no release frames) and was corrected (`e88f920`).

### Nit

- **N-1** ②'s try is one episode. The design note (section 3) asks for "Check first": a few
  tries with a pass rule before ③ opens. Not built; a one-off try passed on a position the edited
  program could reach while the collection failed on most others.
- **N-2** ③'s Start is not refused while a try runs (Q4 decision 1).
- **N-3** ③ trains on the saved `teach.toml`; edits left unsaved in ② are not what trains
  (Q4 decision 3). Saving on leaving ② is the likely answer.
- **N-4** 🎲 moves to the next seed and starts a try at once; its hover text says the next try
  runs there.
- **N-5** The trainer's import check can fail with an empty message under memory pressure;
  the child's own last words should be kept, as P-M12-R6 did for the backend.
- **N-6** `es-editor-model` grows with every sub-project; S4 and S5 need a split plan first.

### Human decision

- **H-1 The template's grip wait.** 5 s (today's demonstrator, measured in re-plans since V11)
  holds 4.4 s of stillness in every demonstration; 1 s gave nominal 2/16 against 0/16, but all
  suites 4/96 against 6/96 on one training each — inside the known spread. Changing the
  template's default waits on one more training seed per arm.
- **H-2 Letting go is the thinnest part of the data.** The Task IR ends an episode the moment
  its success predicate holds, so every demonstration carries 27 frames of release whatever the
  program says, and about one attempt in five ends with the cube at the bin and the gripper shut
  in both runs. Options: (a) a demonstration block that pauses over the bin before releasing
  (plan Q's format can say it today; a measurement, no decision); (b) a success predicate that
  needs the cube to have settled after release, or a termination that records a few frames past
  success — both change the Task IR (a spec decision, the owner's).

## Verdict

S3 is implemented, and every piece of it ran for real with the owner watching: a block edited in
②, a try in 16 s, a collection and a cycle on the edited program. Those runs surfaced three
backend bugs no earlier run could reach and three editor gaps; all are fixed. The learning result
is unchanged in kind — the hint card does not pass — and the reason now has a name: the robot
does not let go.
