## Findings

### Blocker

- [BLOCK] `crates/es-math/src/reduce.rs:120-126` — non-finite poison is silently dropped and the
  result is order-dependent, breaking `DeterministicAcc`'s own commutativity contract (DET-011,
  spec §18.4). `add` writes `bins[0] += v` *before* `rescale_to(0)`; when the accumulator index
  is already `>= K` (any prior small value), the rescale zeroes all bins and the NaN/Inf
  vanishes. Verified against the real code: `add(1e-300); add(NAN)` → `0.0` while
  `add(NAN); add(1e-300)` → `NaN`. The existing test `non_finite_poisons`
  (`reduce.rs:309`) passes only because it deposits `1.0` first (index `-1`, so the rescale is a
  no-op). Fix: call `rescale_to(0)` before the `bins[0] += v`, or hold the poison in a separate
  field outside the bin array; extend the test to seed with a tiny value and assert both orders.

### Should-fix

- [SHOULD] `crates/es-ir/src/hash.rs:128-188,207-250` — `canonical_hash` is exactly a 1-dimensional
  Weisfeiler-Leman invariant (colour refinement + sorted node/edge multisets), which is provably
  incomplete, so non-isomorphic graphs can collide. The NodeId-independence claim at `hash.rs:201-206`
  *is* sound — ids never enter the encoding, so the Appendix B.7 relabelling invariant holds for
  every graph including colour ties. The overstatement is "semantic identity": counterexample
  confirmed against a faithful re-implementation of `refine`+`canonical_hash` — 4 identical `Const`
  and 4 identical `Add` (ports `a`/`b`), wired as one 8-cycle vs. two disjoint 4-cycles, produce an
  identical hash. Every node is regular in both directions so refinement never splits a cell.
  Fix: add one individualization-refinement round (pick the lowest-colour node in the largest
  non-singleton cell, recolour, re-refine, take the min over choices), or accept the ceiling and
  document it — but then add the counterexample as a `#[should_panic]`-free known-limitation test
  so it is not rediscovered as a silent reproducibility bug.
- [SHOULD] `crates/es-assets/src/mjcf/mod.rs:296-307` — `resolve` walks the class parent chain in an
  unbounded `while let`, with no cycle guard. `parse_default` (`mod.rs:437-441,462`) assigns
  `parent = Some(enclosing_name)`, so `<default class="a"><default class="a"/></default>` gives the
  class `a` itself as its own parent; any element with `class="a"` then loops forever, pushing to
  `chain` until OOM. MJCF is untrusted input. Fix: bound the walk by `self.classes.len()` and
  return `MjcfError::UnknownClass` (or a new cycle variant) when exceeded — or reject a nested
  `<default>` whose name already appears among its ancestors, which is what MuJoCo does.
- [SHOULD] `crates/es-assets/src/mjcf/mod.rs:460-465` — a repeated class name silently overwrites
  `entry.parent` while merging attributes, so the last `<default class="x">` wins the parent link
  and the earlier one's inheritance is lost without a diagnostic. MuJoCo rejects duplicate class
  names. Fix: warn (`Warning`) or error on a second declaration of an existing class.

### Nit

- [NIT] `crates/es-math/src/reduce.rs:33-35` — the ~1.3e8-term exactness ceiling is documented but
  never checked; past it the bin sums round and order independence lapses silently. Fix: a
  `u32` deposit counter plus `debug_assert!(count < 1 << 27)`, merged like the bins.
- [NIT] `crates/es-ir/src/hash.rs:53-55` — `seq` saturates a length over `u32::MAX` to `u32::MAX`
  rather than latching a diagnostic, so two absurdly large sequences would encode identically.
  Unreachable today; `self.fail(...)` is the consistent handling and costs one line.
- [NIT] `crates/es-ir/src/hash.rs:79-81` — `f32` is widened to `f64`, so an `f32` field and an
  `f64` field with the same value are interchangeable in the hash. Documented as deliberate;
  noting it only because it means a spec field narrowing `f64` → `f32` will not invalidate stored
  hashes even when it changes runtime behaviour.

## Verdict

**M0 gate: not passed — one blocker.** The composite `cargo xtask ci` also fails, but only in
`es-sensor`, which is out of scope and mid-write; every M0-scope step passes when run alone.

Against spec §28.7:

- Gate 1 (five IRs typed, validated, hashed): **met** for structure — schema, normalization,
  cycle and type checks all pass, and relabelling invariance is proved. `canonical_hash`
  collision resistance for non-isomorphic graphs is **unverified** (see the 1-WL finding).
- Gate 2 (MuJoCo CPU reference oracle): **met** — `PhysicsBackend` adapter over the Python
  subprocess, pendulum equivalence tests pass.
- Gate 3 (deterministic reduction / DET-011): **not met** — `BinnedAcc` is order-dependent on
  non-finite input.
- Gate 4 (verification harness routes through `cargo xtask`): **met** — context-budget, layering,
  spec-refs, goldens and scope all enforced from one entry point.
