## Findings

### Blocker

- [BLOCK] `crates/es-eval/src/domain_gap.rs:444` — the KS merge advances **one** index per tied value instead of past the whole tie, so two *identical* distributions with repeated values and unequal sample counts report a large `D`. Verified: `ks_statistic(&[1.0,1.0,1.0],&[1.0])` = 0.667; an identical binary channel (gripper, a flag) at 300 vs 100 samples = **0.333**, over the 0.3 default threshold. `es gap`'s per-dataset stride (`crates/es/src/cmd/gap.rs:115`) makes unequal n the normal case, and quantised encoder / discrete channels make ties the normal case, so gate 15's suspects list flags channels that do not differ. Fix: advance both cursors past every element equal to `min(sv, rv)` before evaluating `F_a − F_b`.

### Should-fix

- [SHOULD] `crates/es-eval/src/domain_gap.rs:174` — `to_json` is an `.expect`, and `serde_json` refuses NaN/Inf. `column_f64` (`crates/es/src/cmd/gap.rs:96`) never checks finiteness, so one NaN in a real parquet column panics `es gap` *after* it has printed the table — fix: drop or reject non-finite samples in `build_input`.
- [SHOULD] `crates/es/src/cmd/gap.rs:168` — `flat[local * dims..(local + 1) * dims]` slices a parquet column by the *declared* `elem_count`; a foreign dataset whose column is shorter than `n * dims` panics instead of erroring — fix: `get(..)` and a `DataError`.
- [SHOULD] `crates/es-splat/src/ply.rs:441` — the ascii path reserves ≈236 B per *declared* vertex before the per-line field-count check at `:463`, and `count` is bounded only by the non-blank line count (2 B/line): a ~118× memory amplification on a hostile ascii PLY (100 MB in, ~12 GB reserved). The binary path is bounded by `stride` and is fine — fix: size the reserve from `bytes.len() / props.len()`, or validate the first record before reserving.
- [SHOULD] `crates/es-data/src/intervention.rs:280` — `m[i]` indexes a mask sized from `meta.length` with `i` running over `ep.len()`; a dataset whose episode metadata disagrees with its parquet panics — fix: `m.get(i).copied().unwrap_or(false)`.
- [SHOULD] no CI gate on the `no_std` split — nothing under `.github/workflows/` or `xtask/` builds `--no-default-features --target thumbv7em-none-eabihf`. It passes today, but the whole point of W2 is a property that rots silently on the next `es-core` change.
- [SHOULD] `crates/es-eval/src/evidence.rs:456` — only `reports/*/report.json` is cross-checked against the chain. `evaluation.lock` carries its own `execution_hash` and is never parsed, so `EvidenceKind::Lock` evidence of a *different* run counts as covered whenever `case.json` declares the bundle's hash — fix: parse the lock in the same loop.
- [SHOULD] `crates/es-splat/src/align.rs:97` — `src_spread <= 0.0` catches coincident points only, but the doc at `:49` promises non-collinear input and "degenerate input is an error, never a silent identity". Collinear correspondences give a finite but arbitrary rotation about the line (no NaN — Jacobi still returns an orthonormal column) — fix: reject rank < 2, or correct the doc.
- [SHOULD] `crates/es-eval/src/domain_gap.rs:350` — when a channel's sim and real `dims` disagree, dim `d` compares sim column `min(d, sim.dims-1)` against real column `d`, i.e. two unrelated components — fix: report the mismatch instead of clamping.
- [SHOULD] `crates/es-splat/src/ply.rs:394,515,618` — `f64::exp` / `ln` on the activation path feed `SplatScene::asset_hash`, a §5.3 chain input, so a splat asset's content hash is not bit-reproducible across libms. `es-math` is already a dependency — fix: route through `es_math::approx`, or say so in the doc.
- [SHOULD] `crates/es-eval/src/evidence.rs:612` — `VerifyReport::ok()` is vacuously true for a case with zero requirements, and `es evidence verify` then prints "OK: every requirement is covered" over an empty table — fix: an empty `requirements` list is a diagnostic.

### Clean

- **INV-11/12/13.** `es-safety` names no policy, no tensor, no network under either feature set; `es-ir` is the only optional dep and it is layer 6. `SafetyPlane::from_config` is the one constructor, every field is private, there is no `enabled` flag and no `#[cfg(test)]` shortcut; `Envelope::sanitize` narrows (non-finite → 0, out-of-range soft → hard), `Fallback::stationary` degrades `RetractToHome` to `HoldPosition` rather than indexing an empty trajectory (`plane.rs:422`). `validate` still returns `SafeAction<NJ>`. The collector's intervener is a `PolicyRuntime` **wrapper** (`collect.rs:196`), so an injected human action is just another chunk through `emit_actions → validate`; there is no collect-mode branch.
- **INV-15/16/17.** `refuse_augmentation` runs after `ir.validate()` and correctly skips `training_only` now that `CpuPlan` lowers it to identity. No pickle anywhere. **No new traits** in any M3 file — `Registries` is a struct over the two allowed node factories, `EmbeddedCore`'s plug-ins are `fn` pointers, `DomainGap` / `Collector` are namespaces with a note saying so.
- **Determinism.** No `HashMap` in any M3 file; `BTreeMap`/`BTreeSet` throughout, merge-joined in sorted order. The only wall clock is `LoopStep::created` (`collect.rs:53`), and `content_hash` (`identity.rs:119`) hashes parquet bytes only, so `loop.jsonl` cannot reach a hash. `f64::total_cmp` with an index tie-break in `bind.rs:96`; fixed 16-sweep Jacobi and fixed 8-sweep hull projection rather than convergence loops; `libm::sqrt` on both sides of the `std` split so one code path serves both.
- **Panic surface.** No `unsafe` in any M3 crate (`forbid(unsafe_code)` on `es-safety`, `es-splat`). No bare `unwrap`/`expect` in non-test code except the two named above. Adversarial PLY headers: `element vertex 1e12` is caught by `Truncated` in both formats (binary is bounded by `count × stride ≤ available`, ascii by the line count); zero properties fails `MissingProperty("x")` before any allocation; a short ascii line is `BadFieldCount`; non-UTF-8 data decodes to `""` and errors; `read_le`'s slice contract is established once by the `Truncated` check.
- **Editor transactions.** `remove_node` drops the node, every incident edge, and the graph's `inputs`/`outputs` boundary refs, plus the three layout maps — no dangling refs. `apply` snapshots the whole `(graph, layout)` and restores it on either failure path, so a refused edit is invisible; undo/redo swap whole snapshots.
- **`action_source` from counter deltas.** `BatchDomains::single_env()` is hardcoded and `planes` is one element, so exactly one `validate` runs per `step_with_policy` and the delta is unambiguous. Multi-env is not reachable from this API.
- **Empty-sample domain gap.** `mean`/`std` return `0.0` below two samples and `quantiles` returns zeros, so an empty channel scores `D = 0` and is not flagged.
- **`ponytail:` deferrals: 10** (`eval.rs:235`, `loop.rs:122`, `gltf.rs:339`, `scene.rs:536`, `budget.rs:121`, `edit.rs:339`, `mjwarp.rs:198`, `ir_types.rs:13`, `splat/lib.rs:191`, `transport.rs:164`). Every one names both a ceiling and a concrete upgrade path.

## Verdict

**M3 gate: not passed — one blocker, and gate 14 is unmeasurable here.** The safety work is the
strongest part of this milestone: the `no_std` split is real (it builds for thumbv7em and allocates
nothing), `SafetyPlane::from_config` is a genuinely single construction path, and the collector
wires human interventions in as an ordinary policy chunk instead of carving a hole around
`validate`. `es-splat`, the editor's transactional edit model and the evidence bundle are all
careful, well-tested and honest about what they do not do. What fails is the one number gate 15 is
about: the KS statistic is wrong exactly where robot data lives — repeated values, unequal sample
counts — so `es gap` will flag channels that match. That is a five-line fix with an obvious oracle.
Everything else in the Should-fix list is a panic or a hole at a trust boundary, not a design
problem.
