## What plan W set out to do, and what it did

The owner took four decisions on 2026-09-22 after M9: fix `scene_hash` and re-measure the record
under the moved hashes, write the worker pool into the hash, run the five handover items as one
campaign, and queue server jobs one per resource. Measured, on the oracle server (Linux, RTX 4090,
16-core CPU) and the Windows RTX 3060 box:

- **The thread pool is in `runtime_hash` (W0a).** `--jobs 1` (torch's default 8 threads on the
  server's 8 physical cores) ≠ `--jobs 8`, and `--jobs 8` == `OMP_NUM_THREADS=2 --jobs 1` bitwise;
  `evaluation.lock` now prints `runtime_threads`. Two reports at two thread counts are now two
  hashes, as `evaluation-execution.md` 2.7 asked.
- **`scene_hash` is one number on both platforms (W0b).** The importers' `euler=` / `axisangle=` /
  `zaxis=` / `rpy` go through `es_math::approx`; the platform that had been wrong was **Windows**
  (glibc == musl on Linux), so every server number of plans V, M7, M8 and M9 was already under
  today's hash. Re-measured: the collect is byte-identical, reach A0 is bit-identical on three
  seeds (0.5625 / 0.3750 / 0.3125), and today's binary reproduces M7/U's report exactly from the
  committed checkpoint. The chain also refused, by name, the M5-era dataset under the moved
  `task_hash` — M5's S-3 guard firing for the first time on a hash moved on purpose.
- **The per-tick PT seed (W1a), row U5.** Held-out **0.25** (4/16), training seeds **0.50** (8/16),
  against U4's 0/16 and 1/16 on the same 103,881-frame collect and recipe, and W0b's rasterized
  U3″ 0/16 and 2/16 on the same regime. A pose-fixed grain was something the ACT could fit; moving
  it with the tick makes the `Pt` path learnable as it stands. The magnitude is one CUDA run (S-4).
- **The executed-action estimator (P-M9-R5): no.** 0.00 on three seeds at 4,000 and 10,000 against
  A0's 0.4167; the return falls, the entropy freezes, every evaluation tick violates the velocity
  bound. The Gaussian's density at a clamped point is not the probability of the action that
  earned the reward. `"sampled"` stays the default; the option stays in the vocabulary as a
  measured negative.
- **Mesh geoms load, hash by content and simulate (W2a).** Binary / ASCII STL and OBJ readers,
  `es_assets::mesh::load`, inline `<asset><mesh vertex face>` emission, `ContactMesh` declared on
  mujoco-cpu with the convex-hull quirk and withheld on MJWarp. The mesh box rests like the
  primitive box (7.5e-10 m apart after 2,000 steps; `legacy` == `exact` inertia on a convex box;
  the mass differs by the `f32` rounding of 0.05, 4.47e-8). Upstream Menagerie SO-101 (19 STL,
  362,996 triangles) loads in MuJoCo with every body mass equal to a direct upstream load; Panda's
  67 meshes decode and hash (its finger `<tendon>` is refused by the emitter by name). Every
  number is identical on Windows and Linux digit for digit.
- **Mesh geoms render (W2b).** One `Mesh` arm in the tessellator feeds the rasterizer, the path
  tracer and the CPU reference; the four new goldens match the GPU at 0 bytes / 0 ULP on both
  cards; the scene cache keys on the mesh's content hash. The CLI's shared loader and the editor's
  replay resolve meshes relative to the scene file.
- **Splits (W3a, W3b)** and **P-M10-R1** (the stale tick cache after `Env::reset`, the CRLF golden
  generator) as the gates table says.

## Findings

### Blocker

None.

### Should-fix

- **S-1 (M7 S-10, still open).** `quadruped_eval_run_names_the_observation_gap` fails under
  `ES_PYTHON` and stops `cargo xtask ci`'s fail-fast before the later stages. Read this time: the
  test packs the ASCII bytes `es-m6-b1…` as the bundle's weights, and with torch present the
  runtime's safetensors reader rejects them ("header claims 3558456367359292261 bytes" — those
  eight bytes read as a little-endian `u64`) before the observation gap the test is about is ever
  reached. A test fixture bug, not a runtime one: the placeholder must be a well-formed (empty or
  zero) safetensors blob, or the test must accept the refusal. It is the one red test in the
  workspace and it hides anything behind it.
- **S-2 (W0b, open question).** `es loop cycle`'s committed recipe (20,000 steps at batch 64) is
  34.6 epochs of V15's 36,960 frames and 12.3 of today's 103,881, because V11 made one control
  step one control period and the demonstrations grew 2.8× — U3″ scores 0.0 on today's own
  collect. The recipe is under-trained for the data its own collect stage now produces; U4, U5
  and U3″ all sit in that regime.
- **S-3 (P-M9-R5).** The envelope's meaning for a learning policy is still the lever. B is
  measured and negative; A (a wider position margin, only with a servo-spec reason), C
  (increments over the measured joint) and a clamp-aware estimator (the clipped-action policy
  gradient: the log of the Gaussian's tail mass for a clamped dimension — a trainer change that
  keeps INV-11..13) remain.
- **S-4 (W0b, W1a).** CUDA ACT training is not bitwise (8 ULP at step 5, 46 of 126 tensors differ
  at 20,000 steps), and U3's own retrain moved the headline from 0.5625 to 0.8750. Every
  single-run demo number carries ±0.3; U5's held-out 4/16 against 0/16 is inside that band on its
  own. The demo's rows need two training seeds the way reach needs three.
- **S-5 (W0b).** `es train` does not cap the trainer's thread pool the way `es eval run --jobs`
  caps the evaluator's: three concurrent PPO runs on 16 cores wrote no checkpoint in 60 minutes
  (S4e alone: 755 s). The server queue is the workaround; a `--threads` cap hashed like W0a's is
  the fix.
- **S-6 (W2b).** The `light_direction` suite is byte-identical to `nominal` on the `Pt` path (U4
  and U5) because the PT sensor has no directional light (`renderer.md` 10.4 option 2); the suite
  measures nothing there.

## Verdict

**M10: passed.** The two hash-chain holes M8 named are closed — the pool is a hash input and
`scene_hash` no longer depends on the host libm — and the re-measurement found the record sound:
the platform that was off was Windows, and every server number stood. The PT path's unexplained
0.0 has an explanation (a pose-fixed grain) and a one-field fix that moves it to the best of three
rows on the same data. The scene side now reaches real robots: meshes load, hash by content,
simulate identically on both platforms and render at 0 ULP. The one hypothesis tested on the RL
side (train on the executed action) is answered no, and the question it leaves is the one M9 left
— what the envelope means for a policy that is still learning. Two things temper the demo numbers:
the cycle recipe is under-trained for today's collect (S-2), and single CUDA runs carry ±0.3 (S-4).
