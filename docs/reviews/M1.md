## Findings

### Blocker

- [BLOCK] `tests/golden/observation/*.json` + `crates/es-policy/src/weights.rs:186` — gates 5 and 6
  have no reference oracle: the goldens are generated by the code they check and the "ACT checkpoint"
  is built from our own `weight_shapes`, so a wrong half-pixel convention or a transposed key map is
  enshrined, not caught (§1.4). Fix: regenerate goldens from torchvision/LeRobot via a checked-in
  script; use a checkpoint whose keys come from LeRobot.

### Should-fix

- [SHOULD] `crates/es-safety/src/plane.rs:288-302` — `accept()` infers chunk freshness from content
  equality, so a policy re-emitting an identical chunk (stationary hold, saturated output) never
  advances `last_chunk_tick` and `InferenceDeadline` trips on a healthy policy — fix: take
  freshness from the caller (a sequence number, or `submit` vs `reuse`), not from the bytes.
- [SHOULD] `crates/es-telemetry/src/transport.rs:274` — variable-time `String` compare on the auth
  token; with no handshake read timeout (`:201` blocks forever) and no connection cap (`:128-135`
  spawns a thread per connection) a peer can pin threads and probe it — fix: compare
  `blake3::hash` of both, `set_read_timeout` before the `Hello` read, cap connections.
- [SHOULD] `crates/es-compile/src/bundle.rs:484` — `want.is_some() && want != got` lets a manifest
  that omits its hash slots open with no §5.3 check at all, and `signature` (`:105`) is verified by
  nothing — fix: require all six slots present for `BundleKind::Policy`.
- [SHOULD] `crates/es-compile/src/bundle.rs:315-368` — `read` ignores bytes after the last payload,
  falsifying the uniqueness claim at `:313` — fix: `if c.at != bytes.len()` → error.
- [SHOULD] `crates/es-ir/src/factory.rs:93,103` — gate 10's "frozen" is only a doc comment — fix: a
  test asserting a hardcoded `blake3` over both lists, or a golden `xtask verify-goldens` owns.

### Nit

- [NIT] `crates/es-policy/src/lower/torch.rs:115,150` — user-supplied port names reach generated
  Python via Rust `{:?}`; no quote breakout (`"`/`\` are escaped), but `escape_debug` emits `\u{a}`
  for control chars, which Python rejects — fix: reject non-identifier-safe names in `lower_to_torch`.
- [NIT] `crates/es-compile/src/bundle.rs:271,273` — `u32::try_from(..).unwrap_or(u32::MAX)` writes a
  wrong entry count / name length rather than erroring — fix: one `?` is the consistent handling.
- [NIT] `crates/es-env/src/rng.rs:75-76` — `Normal` routes `sqrt`/`cos` through `es_math::approx`
  (f32), so a Gaussian draw carries ~1e-7 relative error against an `f64` `Distribution` —
  deliberate and documented; noted because randomization ranges are specified in f64.

### Clean

- INV-11: no `es_policy` reference in `es-safety`; `xtask layering` machine-checks it.
- INV-12: no skip/disable/bypass flag anywhere; `EmbeddedRuntime::tick` (`runtime.rs:169`) is the

- INV-13: `plane.rs:176-181` returns `SafeAction<NJ>`, no `Result`, and cannot panic —
  `config.rs:142-155,334` reject inverted limits and empty retract trajectories so every
  `f64::clamp` has `min <= max`, and `scrub` (`plane.rs:410`) is the single exit, forcing
  finite-and-inside-hard-limits on every path including the latch. I could not construct a

- INV-15: `Augment` has no arm in `CpuPlan::compile` and hits `other => unsupported`

- INV-16: no `pickle`/`torch.load` outside the assertions forbidding them (`torch_runtime.rs:519`).
- INV-17: 9 traits; the extras (`IrNode`, `Component`, `Column`, `QueryParam`) are multi-impl or

- Determinism: no `HashMap`/`thread_rng`/`rand::`, no f64 time accumulation; `Instant::now` appears

- `Env::step` purity: `EnvRng` is counter-addressed by `(seed, env, episode, stream)`
  (`rng.rs:29-44`), so env order, thread count and subset resets cannot change a draw; auto-reset

- Untrusted input: `bundle::read` is fully bounds-checked, the protocol caps frames at 64 MiB, and

## Verdict
