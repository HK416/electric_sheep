## 발견 사항

### Blocker (차단)

- [BLOCK] `crates/es-eval/src/domain_gap.rs:444` — KS merge가 tie 전체를 지나치는 대신 tie 값 하나당 인덱스를 **하나만** 전진시켜서, 반복값을 가지며 sample 수가 다른 두 *동일한* 분포가 큰 `D`를 보고한다. 검증함: `ks_statistic(&[1.0,1.0,1.0],&[1.0])` = 0.667; 동일한 binary channel(gripper, flag)이 300 대 100 sample일 때 = **0.333**으로, 기본 threshold 0.3을 초과한다. `es gap`의 dataset별 stride(`crates/es/src/cmd/gap.rs:115`)는 n이 다른 것을 일반적인 경우로 만들고, quantised encoder / discrete channel은 tie를 일반적인 경우로 만들어서, 게이트 15의 suspects list가 실제로는 다르지 않은 channel을 flag한다. 수정: `F_a − F_b`를 평가하기 전에 두 커서를 `min(sv, rv)`와 같은 모든 원소를 지나치도록 전진시킬 것.

수치다: KS statistic이 정확히 로봇 데이터가 사는 곳 — 반복값, 서로 다른 sample 수 — 에서 틀려서,
`es gap`이 일치하는 channel을 flag하게 된다. 이는 명확한 오라클을 가진 5줄짜리 수정이다. Should-fix
목록의 나머지 전부는 설계 문제가 아니라 trust boundary에서의 panic이나 구멍이다.

## 후속 패킷

- **P-M3-R1 — tie를 지나치는 KS.** 오라클: `([1.0;3], [1.0])`에 대해, 300 대 100 sample의 binary channel에 대해, 500 대 100의 10-level quantised channel에 대해 `ks_statistic`이 0임을 assert하는 `cargo test -p es-eval domain_gap` — 더불어 기존의 수계산된 케이스는 그대로 유지.
- **P-M3-R2 — `es gap`이 악의적인 dataset에서도 살아남는다.** 오라클: NaN column과 `n * dims`보다 짧은 column을 가진 fixture에 대한 `cargo test -p es cli`가 panic이 아니라 메시지와 함께 exit 1임을 assert.
- **P-M3-R3 — PLY reader의 reserve에 상한을 둔다.** 오라클: line당 토큰 하나로 `element vertex 500000`을 선언하는 1 MB ascii PLY를 import하는 `cargo test -p es-splat`가 `BadFieldCount`와 (`es_core::alloc_count`를 통해) 수 MB 미만의 reserve임을 assert.
- **P-M3-R4 — `no_std` 빌드를 CI 단계로 만든다.** 오라클: `cargo xtask ci`가 `cargo build -p es-safety -p es-runtime-embedded --no-default-features --target thumbv7em-none-eabihf`를 얻으며, target이 설치되어 있지 않으면 크게 SKIP함.
- **P-M3-R5 — stale lock은 coverage로 카운트되지 않는다.** 오라클: `reports/0/evaluation.lock`이 다른 run의 것인 bundle을 만드는 `cargo test -p es-eval evidence`가 requirement가 `stale`에 놓임을 assert.
- **P-M3-R6 — collinear correspondence는 error다.** 오라클: 한 line 위의 점 4개를 사용하는 `cargo test -p es-splat`가 `SplatError::DegenerateFit`을 assert.
- **P-M3-R7 — metadata가 어긋나도 panic하지 않는다.** 오라클: `meta` episode length가 자신의 parquet보다 짧은 dataset에 대해 `label`을 실행하는 `cargo test -p es-data`가 `DataError::Inconsistent`를 assert.
