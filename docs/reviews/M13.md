## Findings

### Should-fix (all fixed before this review closed)

- **S-1** The weakest suites were chosen without asking whether the collector can realise them
  (a `frame_drop` suite, or an `observation_delay` past the `stale_observation` watchdog, is
  refused by `es loop collect --perturb`). Fixed by follow-up R2: the check moved to
  `es_eval::perturb::unseen_age`, which the collector and `results::again` share.
- **S-2** "실패 위주로 다시 학습" started the run at once with the previous run's settings — for the
  hint card at *long*, 200 more demonstrations and 60,000 more steps without a second look.
  Fixed by R1: the button prepares ③'s start panel (what it practises, editable demonstrations
  and length, Cancel) and Start starts it.
- **S-3** Opening the editor on a run already training showed the finished stages as *waiting* and
  the plain picture instead of the training view: stage cards and the centre came only from
  `stage.begin`/`stage.end` heard since attaching. Found on the Z7 run with the owner watching;
  fixed (`b637725`: the phase state's running stage stands in).
- **S-4** ⑤'s "why it failed" led with "the safety device stopped it, 90" and "motion gaps, 90 —
  a faster computer helps": one fallback step and one chunk underrun at every attempt's first
  tick (a declared latency of one control period), successes included. Fixed by R3: a plane
  step counter is a cause only above 1 % of the attempt's steps; on the Z7 rows the list becomes
  never lifted 65, safety limit 43, lifted but left outside 16, in too late 9, fallback 4.

### Nit

- **N-1** ⑤ reads every timed-out attempt's trajectory when it opens a run (about 1 MB each). Not
  measured separately; a summary written at evaluation time would make it free.
- **N-2** The outcome region is the target at the scene's pose (right for a fixed bin).
- **N-3** An unperturbed collection draws every episode from one stream seeded by `seed`, a
  perturbed one uses per-episode seeds; the fresh-seed rule treats both as the range
  `[seed, seed + episodes)`, which is conservative for the first.
- **N-4** `--from merge` is not a resume point, and `--from train` re-checks the merge roots.
- **N-5** The log pane is empty for a run the editor attached to rather than started.
- **N-6** Worktree agents sharing one `CARGO_TARGET_DIR` overwrote each other's same-named
  binaries (an xtask built in another worktree checked the wrong tree; a cli test launched
  another worktree's `es.exe`). Each concurrent agent now gets its own target directory, and the
  wave's CI runs only when no agent builds.

### Human decision

- **H-1** The hint card does not pass even at *long*. Z7 measured the M10 review's open S-2
  ("the cycle recipe's step count"): 60,000 steps — 37 epochs of today's data, U3's own 34.6 of
  V15's — scores nominal 0/16, as 20,000 did. So the step count is not the lever; the
  demonstrations are (every one holds still for 4.4 s, 43 % of the episode, between closing the
  gripper and lifting). The next run (plan Q's Q5 follow-up) measures a 1 s wait. Whether the
  template's default wait changes waits on that number.
- **S-7 of M12** (the envelope for a learning policy) is much less pressing on this card than the
  short run suggested: the plane changes 5–12 % of steps per suite at *long*, not 99.6 %.

watching; the four should-fix findings that run surfaced are fixed. The learning result is a
finding about the demonstrations, not about S2. Open: one real "train again" run.
