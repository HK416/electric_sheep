## 발견 사항

### Blocker (차단)

- **B-1** `es-env/src/env.rs:370` — `bind_ports`가 `self.ports`를 **제자리에서(in place), 전혀 비우지 않고**
  다시 채우는 반면, `es-env/src/control.rs:203-205`는 같은 공유 map에 `stage.index`/`ticks`/`done`을 쓴다.
  env *e*에 대해 `episode::evaluate`(`env.rs:400`)와 첫 진입 `Branch`(`control.rs:118` → `:236`, descent 시
  한 번 평가됨) 둘 다 `write_ports`가 env *e−1*을 위해 남긴 값을 읽는다 — env 0의 경우 이전 step의 env
  *n−1* 값이다. `stage.*`에 대한 모든 `Terminate`/`Branch`는 **다른 env**의 함수가 된다. 테스트에서는
  보이지 않는다: `FakeBackend`는 7개 env 전부를 lockstep으로 유지한다(`control.rs:371`). 수정:
  `bind_ports`에서 세 `stage.*` key를 clear하거나, executor에 env별 scratch를 줄 것.
- **B-2** `es-eval/src/evidence.rs:378` — `signing_digest`는 `entries`만 hash하므로 **manifest는 signature
  밖에** 있다: signed bundle에서 `manifest.kind`와 `manifest.hashes`(선언된 execution-hash chain)를 다시
  써도 여전히 `Valid`로 검증된다; `verify`는 bundle 자신의 `manifest.hashes`를 전혀 cross-check하지
  않는다(`:550`은 `policy.manifest.hashes`, 즉 다른 bundle을 확인한다). digest는 또한
  `name || blake3(payload)`이며 **length prefix가 없어서**(`:380-382`), payload hash의 byte 몇 개만
  갈아내면 서로 다른 두 `(name, hash)` 집합이 동일하게 직렬화될 수 있다. `:373-376`은 과도한 주장을 한다.

### Human decision (사람의 판단 필요)

- **ReSTIR tolerance.** 관측된 max ULP는 10; assertion은 ULP가 아니라 image-space `1e-5`(`render.rs:345`)다.
  구조적 문제: `restir.slang:69-77`은 순차적으로 누적된 `f32`에 대해 `rand * w_sum < weight`로 survivor를
  고르므로, `p_hat`(`:80-92`)의 1-ULP 변화가 *다른 light sample*로 flip된다 — 이는 discrete한 jump이므로
  threshold를 완화해도 절벽이 옮겨갈 뿐이다. Order-independence를 원하면 exact accumulator
  (`es_math::BinnedAcc`가 존재함)나 정수 prefix sum을 쓰는 fixed-point weight가 필요하다. bitwise를 위해
  비용을 치르거나, 이 tolerance를 ReSTIR의 contract로 기록할 것.
- **Tier-1 denorm rule.** 이 device는 `ftz=false`/`denorm_indep=All`을 보고하므로 mode가
  드롭된다(`caps.rs:162-180`). 일부 device는 flush하는 fleet 전반에 걸친 §3.5 tier 1은 명문화된 규칙이
  필요하다.
- **Task IR `schema_version` 1 → 2**(S-13): acceptance rule도 migration도 없다; v1 파일이 hash를 유지하는
  것은 오직 파일 자신의 field가 hash되기 때문일 뿐이다.
- **ACT lowering이 IR을 우회한다.** `lerobot.rs:467`은 `LearningGraph`가 아니라 `ActConfig`를 받아서,
  normalization을 생성된 Python으로 내보낸다(`:445-458`, `:578-580`); IR이 소유하는 경로는
  `lower/torch.rs:769-805`에 존재한다. 어느 쪽이든 gate 5는 bitwise로 통과한다.
- **Newton 5.9e-4** vs MJWarp 7.4e-8 — 그 tier로 받아들이거나, gate할 것. (`es backend compare`는
  blocked mapping을 `SKIPPED`와 exit 1로 드러내긴 한다, `cmd/backend.rs:221-228,269`.)
- **Gate 14**는 여전히 robot cell, HIL rig, 실제 카메라가 필요하다.

## 판정

**M4 게이트: 통과하지 못함 — Blocker 2건, 둘 다 함수 하나짜리 수정.** GPU 작업은 이 저장소에서 가장
강력한 부분이다: float-controls는 정말로 query이고, SPIR-V patch는 `NoContraction`이 적용됨을 증명하는
테스트를 가진 post-pass이며, gate 3은 실제 하드웨어에서 0/4096 mismatch이고, observation pipeline은 50개
resize 크기 전체에서 CPU-to-GPU가 bit-equal이며, gate 5는 진짜 LeRobot checkpoint에 대해 `max_abs 0e0`으로
closed된다. 새 trait 없음(INV-17 clean), hash 대상 경로에 `HashMap` 없음, Rust에 pickle 없음, IR-C는 action
경로를 건드리지 않으며(reward와 termination만 gate하므로 INV-12/13이 유지됨), `es-gpu`의 `unsafe` 39곳
모두 SAFETY 주석을 달고 있다. 실패하는 부분은 좁다: IR-C가 env 전체에 걸쳐 port map 하나를 공유하므로,
M4가 env loop에 추가하는 그 한 가지가 두 env가 서로 어긋나는 순간 잘못되어 버린다; 그리고 새 signature는
payload는 인증하지만 그것을 지칭하는 manifest는 인증하지 않아서 gate 17로서는 거꾸로다. 나머지는
trust-boundary hardening이다 — crash 가능한 `.usda` parser, 상한 없는 MCP server, 하위 디렉터리 include를
놓치는 cache key — 그리고 GPU 없는 박스가 green을 보고하게 만드는 SKIP 구멍. `ponytail:` 유예 사항:
14건(M3에서는 10건), 각각 ceiling과 upgrade 경로를 명시.
