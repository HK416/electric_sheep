## Findings

### Blocker

- **B-1** `es-env/src/env.rs:370` — `bind_ports` refills `self.ports` **in place, never clearing it**, while
  `es-env/src/control.rs:203-205` writes `stage.index`/`ticks`/`done` into that same shared map. For env *e*,
  both `episode::evaluate` (`env.rs:400`) and the first-entry `Branch` (`control.rs:118` → `:236`, evaluated
  once at descent) read what `write_ports` left for env *e−1* — for env 0, env *n−1*'s from the previous step.
  Any `Terminate`/`Branch` over `stage.*` is a function of a **different env**. Invisible to the tests:
  `FakeBackend` keeps all 7 envs in lockstep (`control.rs:371`). Fix: clear the three `stage.*` keys in
  `bind_ports`, or give the executor per-env scratch.
- **B-2** `es-eval/src/evidence.rs:378` — `signing_digest` hashes only `entries`, so the **manifest is outside
  the signature**: `manifest.kind` and `manifest.hashes` (the declared execution-hash chain) can be rewritten
  on a signed bundle and it still verifies `Valid`; `verify` never cross-checks the bundle's own
  `manifest.hashes` (`:550` checks `policy.manifest.hashes`, a different bundle). The digest is also
  `name || blake3(payload)` with **no length prefix** (`:380-382`), so two different `(name, hash)` sets can
  serialize identically once a few bytes of a payload hash are ground out. `:373-376` overclaims.

### Human decision

- **ReSTIR tolerance.** Observed max ULP 10; the assertion is image-space `1e-5` (`render.rs:345`), not ULP.
  Structural: `restir.slang:69-77` picks the survivor with `rand * w_sum < weight` against a sequentially
  accumulated `f32`, so a 1-ULP change in `p_hat` (`:80-92`) flips to a *different light sample* — a discrete
  jump, so loosening the threshold only moves the cliff. Order-independence needs an exact accumulator
  (`es_math::BinnedAcc` exists) or fixed-point weights with an integer prefix sum. Pay for bitwise, or record
  the tolerance as the ReSTIR contract.
- **Tier-1 denorm rule.** This device reports `ftz=false`/`denorm_indep=All`, so the mode is dropped
  (`caps.rs:162-180`). §3.5 tier 1 across a fleet where some devices flush needs a written rule.
- **Task IR `schema_version` 1 → 2** (S-13): no acceptance rule, no migration; v1 files keep their hashes only
  because the file's own field is hashed.
- **ACT lowering bypasses the IR.** `lerobot.rs:467` takes an `ActConfig`, not a `LearningGraph`, and emits
  normalization as generated Python (`:445-458`, `:578-580`); the IR-owned path exists at
  `lower/torch.rs:769-805`. Gate 5 passes bitwise either way.
- **Newton at 5.9e-4** vs MJWarp at 7.4e-8 — accept at that tier, or gate it. (`es backend compare` does
  surface a blocked mapping as `SKIPPED` plus exit 1, `cmd/backend.rs:221-228,269`.)
- **Gate 14** still needs a robot cell, a HIL rig and real cameras.

## Verdict

**M4 gate: not passed — two blockers, both one-function fixes.** The GPU work is the strongest thing in the
repo: float-controls really is a query, the SPIR-V patch is a post-pass with a test proving `NoContraction`
lands, gate 3 is 0/4096 mismatched on real hardware, the observation pipeline is bit-equal CPU-to-GPU across
50 resize sizes, and gate 5 closes against a genuine LeRobot checkpoint at `max_abs 0e0`. No new traits
(INV-17 clean), no `HashMap` on a hashed path, no pickle in Rust, IR-C leaves the action path alone (it gates
reward and termination only, so INV-12/13 hold), and all 39 `unsafe` sites in `es-gpu` carry SAFETY comments.
What fails is narrow: IR-C shares one port map across envs, so the one thing M4 adds to the env loop is wrong
as soon as two envs disagree; and the new signature authenticates the payload but not the manifest that names
it, backwards for gate 17. The rest is trust-boundary hardening — a crashable `.usda` parser, an uncapped MCP
server, a cache key that misses subdirectory includes — plus the SKIP hole that lets a GPU-less box report
green. `ponytail:` deferrals: 14 (10 at M3), each naming a ceiling and an upgrade path.
