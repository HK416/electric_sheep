## 발견 사항

### Blocker (차단)

- [BLOCK] `crates/es-math/src/reduce.rs:120-126` — non-finite 오염값이 조용히 소실되고 결과가
  순서에 의존하게 되어, `DeterministicAcc` 자체의 교환법칙 계약(DET-011, spec §18.4)을
  깨뜨린다. `add`는 `rescale_to(0)` *이전에* `bins[0] += v`를 기록한다; 누산기 인덱스가
  이미 `>= K`인 상태(사전에 작은 값이 하나라도 들어온 경우)면 rescale이 모든 bin을
  0으로 만들어 NaN/Inf가 사라진다. 실제 코드로 검증함: `add(1e-300); add(NAN)` → `0.0`인
  반면 `add(NAN); add(1e-300)` → `NaN`. 기존 테스트 `non_finite_poisons`
  (`reduce.rs:309`)는 `1.0`을 먼저 넣기 때문에만(인덱스 `-1`이라 rescale이 no-op) 통과한다.
  수정: `bins[0] += v` 이전에 `rescale_to(0)`를 호출하거나, 오염값을 bin 배열 밖의
  별도 필드에 보관할 것; 테스트도 작은 값으로 시드한 뒤 양쪽 순서를 모두 단언하도록
  확장할 것.

### Should-fix (수정 권장)

- [SHOULD] `crates/es-ir/src/hash.rs:128-188,207-250` — `canonical_hash`는 정확히
  1차원 Weisfeiler-Leman 불변량(색상 정제 + 정렬된 노드/엣지 다중집합)이며, 이는
  증명 가능하게 불완전하므로 서로 동형이 아닌 그래프끼리 충돌할 수 있다.
  `hash.rs:201-206`의 NodeId-독립성 주장 자체*는* 타당하다 — id가 인코딩에 전혀
  들어가지 않으므로, 색상 동률(tie)을 포함한 모든 그래프에 대해 부록 B.7의 relabelling
  불변성이 성립한다. 과장된 부분은 "의미론적 동일성" 쪽이다: `refine`+`canonical_hash`를
  충실히 재구현하여 반례를 확인함 — 동일한 `Const` 4개와 동일한 `Add`(포트 `a`/`b`) 4개를
  하나의 8-사이클로 배선한 경우와 서로 분리된 4-사이클 두 개로 배선한 경우가 동일한
  해시를 낸다. 양방향 모두에서 모든 노드가 regular이므로 정제 과정이 어떤 셀도 분할하지
  못한다. 수정: individualization-refinement 라운드를 한 번 추가하거나(가장 큰
  non-singleton 셀에서 최저 색상 노드를 골라 재색칠 후 재정제, 선택지들의 최솟값을 취함),
  아니면 이 한계를 그대로 받아들이고 문서화하되 — 그 경우 이 반례를 조용한 재현성
  버그로 재발견되지 않도록 `#[should_panic]` 없는 known-limitation 테스트로 추가할 것.
- [SHOULD] `crates/es-assets/src/mjcf/mod.rs:296-307` — `resolve`는 클래스 부모 체인을
  사이클 가드 없이 무한정 `while let`로 순회한다. `parse_default`
  (`mod.rs:437-441,462`)는 `parent = Some(enclosing_name)`을 대입하므로,
  `<default class="a"><default class="a"/></default>`는 클래스 `a`에게 자기 자신을
  부모로 준다; 이후 `class="a"`를 가진 임의의 엘리먼트가 OOM이 날 때까지 `chain`에
  계속 push하며 무한 루프에 빠진다. MJCF는 신뢰할 수 없는 입력이다. 수정:
  `self.classes.len()`으로 순회를 제한하고 초과 시 `MjcfError::UnknownClass`(또는 새
  cycle variant)를 반환할 것 — 혹은 MuJoCo가 그러듯, 이름이 조상 목록에 이미 존재하는
  중첩 `<default>`를 거부할 것.
- [SHOULD] `crates/es-assets/src/mjcf/mod.rs:460-465` — 클래스 이름이 중복되면 속성을
  병합하는 과정에서 `entry.parent`가 조용히 덮어써져, 마지막 `<default class="x">`가
  부모 링크를 차지하고 앞선 선언의 상속 관계는 진단 없이 사라진다. MuJoCo는 중복
  클래스 이름을 거부한다. 수정: 기존 클래스의 두 번째 선언에 대해 경고(`Warning`)를
  내거나 에러를 낼 것.

### Nit (사소함)

- [NIT] `crates/es-math/src/reduce.rs:33-35` — 약 1.3e8개 항의 정확성 한계가 문서화되어
  있지만 실제로 검사되지는 않는다; 이를 넘어서면 bin 합산이 반올림되어 순서 독립성이
  조용히 깨진다. 수정: `u32` deposit 카운터와 `debug_assert!(count < 1 << 27)`를 bin과
  함께 병합할 것.
- [NIT] `crates/es-ir/src/hash.rs:53-55` — `seq`는 길이가 `u32::MAX`를 넘으면 진단을
  남기는 대신 `u32::MAX`로 saturate하므로, 터무니없이 큰 두 시퀀스가 동일하게
  인코딩될 수 있다. 현재는 도달 불가능한 경로이며, `self.fail(...)`이 일관된 처리
  방식이고 한 줄이면 된다.
- [NIT] `crates/es-ir/src/hash.rs:79-81` — `f32`가 `f64`로 확장되므로, 같은 값을 가진
  `f32` 필드와 `f64` 필드가 해시상 서로 구분되지 않는다. 의도된 사항으로 문서화되어
  있음; 다만 스펙 필드를 `f64` → `f32`로 좁히는 변경이 런타임 동작을 바꾸는 경우에도
  저장된 해시를 무효화하지 않는다는 점을 짚어둔다.

## 판정

**M0 게이트: 통과하지 못함 — Blocker 1건.** 합성 명령 `cargo xtask ci`도 실패하지만
`es-sensor`(범위 밖, 작성 중)에서만 실패하며, M0 범위의 모든 단계는 개별 실행 시
통과한다.

spec §28.7 기준:

- Gate 1 (5종 IR이 타입화, 검증, 해시화됨): 구조 측면에서는 **충족** — 스키마,
  정규화, 사이클, 타입 검사가 모두 통과하고 relabelling 불변성이 증명되었다.
  동형이 아닌 그래프에 대한 `canonical_hash`의 충돌 저항성은 **미검증**이다(1-WL
  발견 항목 참조).
- Gate 2 (MuJoCo CPU 참조 오라클): **충족** — Python subprocess 위에 구축된
  `PhysicsBackend` 어댑터, pendulum 동등성 테스트 통과.
- Gate 3 (결정적 reduction / DET-011): **미충족** — `BinnedAcc`가 non-finite 입력에
  대해 순서 의존적이다.
- Gate 4 (검증 harness가 `cargo xtask`를 통해 라우팅됨): **충족** — context-budget,
  layering, spec-refs, goldens, scope가 모두 하나의 진입점에서 강제된다.
