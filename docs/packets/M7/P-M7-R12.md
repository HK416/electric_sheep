## the question

`es loop cycle --telemetry` publishes collect, the expert gate, training and the evaluation on one
socket, and `LiveRun` keys its rows by cell name. Seen on the local cycle demo (2026-09-21): the
policy evaluation's `nominal-00..03` landed in the expert gate's rows of the same name, showing the
gate's `success_rate 1.0` while the policy's cell was still running (R16). A viewer that attaches
after a `cell.begin` has gone by never gets a row for that cell, because only `cell.begin` creates
one (R12). The protocol is frozen (`crates/es-telemetry/src/protocol.rs`), so there is no replay to
ask for. **What is the fold rule that gives one row per `(stage, cell)` and a row for every cell the
wire ever names, with the on-disk fold (`RunView`) and E4's oracle unchanged?**

## spec

* **The row's identity is `(stage, cell)`.** `stage` is the event's own `stage` field when it has one
  (E7 put it on every stream-1 event), else the name of the last `stage.begin` seen, else empty for a
  run that is one command. Rows are ordered by the stage's *arrival* index and then by cell name —
  not by the stage's name, since `eval` sorts before `expert-gate` and that is not the order a cycle
  runs in. Stream-2 samples and stream-4 images carry no name and no stage; they belong to the open
  `(stage, cell)`, as today.
* **The table shows the stage.** `CellRow` gains `stage: String` (empty for a run read off disk, so
  `RunView::cells()` and E4's fixture oracle are unchanged), and the Run tab draws a `stage` column
  only when the run has stages (`stages()` non-empty). `select` / `selected_cell` / `timeline` are
  keyed the same way — the smallest change that keeps `app.rs` deciding nothing; a composite string
  key is acceptable if it is built in one place in `live_run.rs`.
* **A late viewer's row (R12).** A stream-2 sample that arrives with no open cell is kept in a
  pending list, not dropped and not guessed. The next `cell.end` / `episode.end` claims the pending
  samples as its records, creates the row from the event's own fields (`frames` / `steps`,
  `outcome`, `traj`) and marks it **joined late**. A `cell.begin` / `episode.begin` that arrives
  while samples are pending discards them (in a well-ordered stream that cannot happen; if it does,
  the samples belong to a cell nobody will ever name). `a_tick_outside_any_cell_is_dropped_not_guessed`
  keeps its meaning: the run is still empty — no row exists — until an end event names the cell.
* **"Joined late" is a string-table key** in `crates/es-editor/i18n/en.toml` and `ko.toml` (E6's
  rule: no text a person reads lives in a source file), drawn beside the cell name in the Run tab,
  and counted in `status()` ("… 2 joined late").
* **The stage strip is unchanged.**

## oracle

1. `cargo test -p es-editor live_run_keys_rows_by_stage_and_cell` — `stage.begin expert-gate`,
   `cell.begin nominal-00` (+ 3 ticks), `cell.end`, `suite.end` with `success_rate 1.0`,
   `stage.end`; `stage.begin eval`, `cell.begin nominal-00` (+ 2 ticks) → **two rows**, stages
   `expert-gate` then `eval` in that order, the first's `success_rate` from the gate's `suite.end`,
   the second's metrics empty while it runs; `status()` names `eval / nominal-00` as running;
   `timeline` of each row has its own tick count (3 and 2).
2. `cargo test -p es-editor a_cell_that_began_before_attach_still_gets_a_row` — 3 ticks then
   `cell.end nominal-01 { frames = 3, outcome = Timeout, traj = true }` with no `cell.begin` → one row,
   joined late, `frames == 3`, timeline has 3 rows; a `cell.begin nominal-02` afterwards is an
   ordinary row and is not marked; `status()` counts one joined late.
3. `cargo test -p es-editor live_run_folds_streams_into_run_rows` (E4's oracle 3) and
   `live_run_folds_collect_episodes_like_cells` (E7's oracle 4) unchanged and green — the on-disk
   fold and the single-command fold are not moved by this packet.
