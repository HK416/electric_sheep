# M7 R12/R16 — 라이브 표의 행이 `(stage, cell)`로 키가 매겨지고, 늦게 붙은 뷰어도 모든 행을 얻는다

스펙: §23.1(에디터는 클라이언트이지 호스트가 아니다), §23.3(실행 중에 사람이 확인하는 것),
§28.10 규칙 3(`app.rs`에서는 아무것도 결정되지 않는다; 모든 패널은 먼저 헤드리스
view-model을 갖는다), §28.11 웨이브 0. 리뷰: `docs/reviews/M7.md` addendum, R12와 R16. 이
패킷이 고치는 패킷: `E4-live-telemetry.md`, `E7-live-loop.md`. 확장할 설계 노트:
`docs/design/editor-shell.md` 16절(사이클의 행들을 위한 폴드 규칙); 한국어 자매 문서는 같은
커밋에.

## 질문

`es loop cycle --telemetry`는 collect, 전문가 게이트, 학습과 평가를 소켓 하나 위에 발행하고,
`LiveRun`은 자신의 행을 셀 이름으로 키를 매긴다. 로컬 사이클 시연(2026-09-21)에서 본 것:
정책 평가의 `nominal-00..03`이 같은 이름의 전문가 게이트 행에 떨어져, 정책의 셀이 아직 돌고
있는 동안 게이트의 `success_rate 1.0`을 보여줬다(R16). `cell.begin`이 지나간 뒤에 접속한
뷰어는 그 셀의 행을 영영 얻지 못한다, `cell.begin`만이 행을 만들기 때문이다(R12). 프로토콜은
동결되어 있으므로(`crates/es-telemetry/src/protocol.rs`), 요청할 리플레이가 없다. **디스크상의
폴드(`RunView`)와 E4의 오라클을 바꾸지 않고, `(stage, cell)`당 행 하나와 와이어가 이름을 부른
모든 셀에 대한 행 하나를 주는 폴드 규칙은 무엇인가?**

## 사양

* **행의 아이덴티티는 `(stage, cell)`이다.** `stage`는 이벤트 자신의 `stage` 필드가 있을
  때는 그것이고(E7이 모든 스트림-1 이벤트에 그것을 두었다), 없으면 마지막으로 본
  `stage.begin`의 이름이고, 명령 하나뿐인 실행이면 빈 문자열이다. 행은 stage의 *도착*
  인덱스로, 그다음 셀 이름으로 정렬된다 — stage의 이름으로가 아니다, `eval`이
  `expert-gate`보다 앞에 정렬되고 그것이 사이클이 도는 순서는 아니기 때문이다. 스트림-2
  샘플과 스트림-4 이미지는 이름도 stage도 나르지 않는다; 그것들은 오늘처럼 열린
  `(stage, cell)`에 속한다.
* **표가 stage를 보여준다.** `CellRow`가 `stage: String`을 얻는다(디스크에서 읽은 실행에는
  비어 있으므로 `RunView::cells()`와 E4의 픽스처 오라클은 바뀌지 않는다), 그리고 Run 탭은
  실행이 stage를 가질 때만(`stages()`가 비어 있지 않을 때) `stage` 열을 그린다. `select` /
  `selected_cell` / `timeline`은 같은 방식으로 키가 매겨진다 — `app.rs`가 아무것도 결정하지
  않게 유지하는 가장 작은 변경이다; 합성 문자열 키는 `live_run.rs`의 한 곳에서 만들어진다면
  받아들여진다.
* **늦게 붙은 뷰어의 행(R12).** 열린 셀 없이 도착한 스트림-2 샘플은 버려지지도 추측되지도
  않고 대기 목록에 보관된다. 다음 `cell.end` / `episode.end`가 그 대기 중인 샘플들을 자신의
  레코드로 주장하고, 이벤트 자신의 필드(`frames` / `steps`, `outcome`, `traj`)로부터 행을
  만들고 **늦게 합류**로 표시한다. 샘플이 대기 중일 때 도착하는 `cell.begin` /
  `episode.begin`은 그것들을 버린다(잘 정렬된 스트림에서는 이것이 일어날 수 없다; 일어난다면,
  그 샘플들은 아무도 결코 이름 붙이지 않을 셀에 속한다). `a_tick_outside_any_cell_is_dropped_not_guessed`는
  그 의미를 유지한다: 끝 이벤트가 셀을 이름으로 지목하기 전까지는 실행은 여전히 비어 있다 —
  행이 존재하지 않는다.
* **"Joined late"는 문자열 표의 키다** `crates/es-editor/i18n/en.toml`과 `ko.toml`
  안에(E6의 규칙: 사람이 읽는 텍스트는 소스 파일이 아니라 한 곳에 산다), Run 탭에서 셀 이름
  옆에 그려지고, `status()`에서 셈해진다("… 2 joined late").
* **stage 스트립은 바뀌지 않는다.**

## 오라클

1. `cargo test -p es-editor live_run_keys_rows_by_stage_and_cell` — `stage.begin expert-gate`,
   `cell.begin nominal-00`(+ tick 3개), `cell.end`, `success_rate 1.0`의 `suite.end`,
   `stage.end`; `stage.begin eval`, `cell.begin nominal-00`(+ tick 2개) → **두 행**, stage는
   `expert-gate` 다음 `eval` 순서, 첫 행의 `success_rate`는 게이트의 `suite.end`에서, 두
   번째 것의 메트릭은 도는 동안 비어 있음; `status()`는 `eval / nominal-00`을 running으로
   이름 붙임; 각 행의 `timeline`은 자기만의 tick 수(3과 2)를 가짐.
2. `cargo test -p es-editor a_cell_that_began_before_attach_still_gets_a_row` — tick 3개 뒤
   `cell.begin` 없이 `cell.end nominal-01 { frames = 3, outcome = Timeout, traj = true }` →
   행 하나, 늦게 합류, `frames == 3`, timeline은 3행; 그 뒤의 `cell.begin nominal-02`는
   평범한 행이고 표시되지 않음; `status()`는 늦게 합류 하나를 셈함.
3. `cargo test -p es-editor live_run_folds_streams_into_run_rows`(E4의 오라클 3)와
   `live_run_folds_collect_episodes_like_cells`(E7의 오라클 4)는 바뀌지 않고 green이다 —
   디스크상의 폴드와 단일 명령 폴드는 이 패킷으로 움직이지 않는다.
4. 로컬 사이클: `target/plan-u/demo/drive-cycle.ps1`로 구동되는
   `target/plan-u/demo/cycle.toml`에 에디터가 붙으면 12 collect + 4 gate + 4 eval 행이
   별개의 행으로 보인다. CI로 판정할 수 없음(§1.4): 스크린샷의 경로를 소유자의 확인으로서
   설계 노트에 적어라, 그리고 E7 시연의 기록된 프레임 캡처가 `target/plan-u/` 아래 있다면
   대신 테스트에서 그것을 재생하라.
5. `cargo xtask ci`; `cargo xtask check-scope docs/packets/M7/P-M7-R12.md`.

## 수용 기준

오라클 1–3과 5는 green; 4는 적힌 대로. `editor-shell.md` 16절이 짧은 하위 절로 세 폴드
