# M10 W2b — the rasterizer, the path tracer and the CPU reference draw mesh geoms

Spec: §15 (one tessellator feeds both paths and the CPU reference), §3.4 (the geometry the GPU
receives is the geometry the reference traverses, bit for bit), §1.4 (goldens are CI read-only;
additions allowed), §28.13 rule 2 and wave 2, INV-17. Design note: `renderer.md` 2.1 (the shape
table's `Mesh` row) and the tessellation paragraph (`scene.rs` constants are not knobs). Depends
on **W2a** (`SceneDesc.meshes`, `es_assets::mesh::load`, `mesh_box.xml`). Type B.

## the question

`TriScene::from_scene` refuses `Shape::Mesh` because "`SceneDesc` carries an `AssetRef`, not
vertices". W2a put the vertices on `SceneDesc`. **With one new arm in the tessellator, do the
rasterizer, the path tracer and the CPU reference draw a mesh geom from the same triangles, does
every existing golden stay byte-identical, and does the one scene loader every CLI path shares
carry the meshes without `es-env` changing?**

## spec

* `crates/es-render/src/scene.rs`: `tessellate(geom)` → `tessellate(geom, scene)`; the
  `Shape::Mesh { asset }` arm reads `scene.meshes.get(&asset)` and emits `indices` in chunks of
  three as `[Vec3; 3]` (`f64::from(f32)`, exact widening; the geom pose is still applied per
  frame in `f64` by `push_geom`, then `to_f32`); an absent asset →
  `UnsupportedShape { shape: "Mesh (asset not loaded: es_assets::mesh::load)" }`. `HeightField`
  stays refused. `SceneCache.local`'s key becomes `(Shape, [u8; 32])` with the asset's `hash` for
  `Mesh` and zeros otherwise, so two scenes sharing a geom id with different mesh content cannot
  alias. `from_scene_with_poses`, `tri_scene`, `upload_scene` signatures unchanged; the CPU
  reference (`cpu.rs`) and the BVH consume the same `TriScene`, so CPU/GPU parity is automatic.
  `renderer.rs:302`'s "primitives only" doc and `renderer.md` 2.1's row are updated.
* Plumbing: `es::cmd::backend::load_scene` (`crates/es/src/cmd/backend.rs:125-141` — the one
  helper `es loop collect`, `es eval run`, `es video showcase` and `es backend` share) and
  `replay_view::load_scene` (`crates/es-editor/src/model/replay_view.rs:514-532`) call
  `es_assets::mesh::load(&mut scene, path.parent())` after the MJCF / URDF parse. `EnvRenderer`
  clones the scene with its meshes, so **no `es-env` source change**; the editor's replay is
  three lines.
* Goldens: `mesh_box_rs_rgb8`, `mesh_box_rs_depth`, `mesh_box_rs_seg`, `mesh_box_pt1spp` at 64×64
  from the CPU reference, `mesh_box.xml` loaded through `parse_mjcf` + `mesh::load` with a fixed
  `CameraView` (the `cornell_camera` pattern), generated by the existing `generate_goldens`
  (`crates/es-render/tests/render.rs:281`) extended with a `MESH_GOLDENS` table under
  `ES_GENERATE_GOLDENS=1`; sidecars name `es_render::cpu` as the generator. Generated on the
  RTX 3060 box, reproduced on the RTX 4090 (a two-line server run, after the CPU queue is free).

## oracle

1. `cargo test -p es-render` — `scene::tests::mesh_tessellates_from_the_scene_store` (a
   hand-built tetrahedron in `scene.meshes` → 4 triangles, dense segmentation ids, normals from
   winding), `mesh_without_store_is_refused_by_name` (the renamed `mesh_and_height_field_are_refused_by_name`),
   `curved_shapes_upload_the_vertices_the_cpu_reference_traverses` extended with a mesh geom,
   `scene_cache_keys_on_mesh_content` (same id, different hash → different triangles).
2. `cargo test -p es-render --test render` — `cpu_reference_reproduces_the_mesh_goldens_bit_for_bit`;
   with a GPU (SKIP otherwise): `gpu_rasterizer_matches_the_mesh_goldens` (rgb8 and seg bitwise,
   depth at the measured ULP the existing goldens use), `gpu_path_tracer_matches_the_cpu_on_the_mesh_box`
   (1 spp bitwise), `cached_tessellation_is_bit_identical` run on `mesh_box`.
3. `cargo test -p es-env --features render --test render_loop mesh_box_renders_through_env_renderer`
   (GPU): `EnvRenderer::new` with `cam`; a posed frame equals `from_scene_with_poses`'s frame
   bitwise.
4. `cargo test -p es --test cli` and `cargo test -p es-editor` unchanged (primitives;
   `so101_frame0` golden byte-identical); `cargo build -p es-editor`.
5. `cargo xtask verify-goldens` (additions only); the four goldens reproduced on the server;
   `cargo xtask ci`; `cargo xtask check-scope docs/packets/M10/W2b-mesh-render.md`.

## acceptance

Oracles 1–5; every existing golden byte-identical; `renderer.md` 2.1 with its Korean sibling;
the follow-ups named: SO-101 upstream (~350 k triangles) ms/frame under the nine-metric set,
a `tri_scene` dry run in `EnvRenderer::new` if a missing mesh should fail at construction rather
than at the first frame.

## forbidden

`es-assets`, `es-physics-backend` changes (W2a); the tessellation constants (`scene.rs:22-26`);
editing an existing golden; changing `from_scene_with_poses` / `tri_scene` / `upload_scene`
signatures; `HeightField`; a mesh-specific shading path; any `HashMap`; `docs/ARCHITECTURE*.md`.
