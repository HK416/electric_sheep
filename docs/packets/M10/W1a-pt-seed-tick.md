# M10 W1a — the path tracer's sample seed varies per tick, and U4 is run again as U5

Spec: §6 (the clause added 2026-09-22: `render.seed = "fixed" | "tick"`; `fixed` = absent =

## the question

`RenderConfig::seed` is a constant and the observation path has no accumulation, so `frame == 0`
on every call and the PT sample keys are a pure function of `(pixel, pose)`: 64 spp leaves a fixed
texture per pose, and U4's policy — loss 0.0045, below U3's 0.0067 — scores 0 of 16 held-out and
1 of 16 on its own training seeds. **If the sensor can declare `seed = "tick"`, so the same pose
carries different grain at different ticks while every `(episode, tick)` stays bit-reproducible
between the collector and the evaluator, does the PT policy learn the task instead of the grain
— row U5 beside U3's 0.5625 and U4's 0.0?**

## spec

* `es_ir::task::SensorRender` gains `seed: SeedStream` (`Fixed` default | `Tick`),
  `#[serde(default, skip_serializing_if = "SeedStream::is_fixed")]`, TOML `seed = "tick"`.
  `SensorRender::canonical` writes a `seed` entry **only when `Tick`**, after the existing
  fields — `is_default()` includes it — so the committed `task.toml` (`Rs`) and the regenerated
  `task-pt.toml` (`Pt`, seed absent) keep their `task_hash`es; a test pins both.
* `es_env::render::EnvRendererCfg` gains the pass-through `seed_stream`; `sensor_cfg` copies it
  from the sensor; `render_config` leaves `RenderConfig::seed` at its default. `EnvRenderer::frame`
  (`crates/es-env/src/render.rs:305-334`): when `Tick`, before rendering, the renderer's seed is
  set to `rng::fmix32(cfg.seed ^ tick)` (the mixer `crates/es-render/src/rng.rs` already
  exports; if it is private, make it `pub`) where **`tick` is the episode-relative tick** — the
  count `events.json` and the collector's stream-2 carry since M7/R1, read from the same place
  they read it, not `EnvRenderer::frame`'s file counter (which runs across episodes) and not
  `StateView.tick` unless it is shown to reset at `begin_episode`. The renderer gets a
  `set_seed(u32)` (or `render` takes the seed) that rewrites the `p[13]` slot; the CPU
  reference reads the same `cfg.seed`, so CPU/GPU parity holds unchanged. `es video showcase`'s
  scene camera goes through `sensor_cfg` and therefore follows the document.
* Documents (the R5 five-document pattern, generated by `generate_pt_fixtures` extended):
  `tests/fixtures/visible-learning/task-pt-tick.toml` (= the regenerated `task-pt.toml` +
  `seed = "tick"`), `observation-pt-tick.toml`, `evaluation-pt-tick.toml`; on the server
  `observation-augmented-pt-tick.toml` and the train-seeds Evaluation IR; `training-u5.toml`
  (= `training-u4.toml`'s recipe on the new dataset and bundle, paths under
  `~/artifacts/plan-w/w1a/`). Hashes recorded in 7.37.
* **Server (GPU queue `~/artifacts/plan-w/queue/gpu.lock`, `~/artifacts/plan-w/w1a/`, tree
  `~/Projects/es-w1a`, `w1a.sh` under `nohup` with stage markers, ≈ 4.2 h):**
  0. *Reading (b) first, one minute:* one PT episode (seed 1) collected with `--frames` under
     `task-pt-tick`, and the same seed evaluated with `--frames`: the frames at tick 0 (the
     reset pose, identical state) are bit-identical — the collector/evaluator parity T7 proved

  Row U5 in `visible-learning.md` 7.37 beside U3 (0.5625) and U4 (0.0 / 0.0625): `success_rate`,

## oracle

1. `cargo test -p es-ir committed_task_hashes_are_unmoved_by_seed_stream` — `task.toml` and
   `task-pt.toml` hashes pinned; `seed = "fixed"` spelled out hashes as absent; `seed = "tick"`
   moves the hash; an unknown value is refused by name.
2. `cargo test -p es-env --features render pt_seed_varies_per_tick_and_is_reproducible` (GPU;
   SKIP with a reason without one): on the demo scene, one pose rendered at ticks 0 and 1 under
   `Tick` gives different bytes; the same `(pose, tick)` twice gives bit-identical bytes; under
   `Fixed` the bytes equal the ones rendered before the change (pinned inside the test by
   rendering with the seed slot untouched).
3. `cargo test -p es-render` — CPU reference and GPU agree on a 1 spp PT frame after
   `set_seed`; the existing PT goldens (`cornell_pt1spp` …) untouched.
4. Server stage 0 (parity), then stages 1–3; row 7.37 written; `renderer.md` 12.8.
5. `cargo xtask ci`; `cargo xtask check-scope docs/packets/M10/W1a-pt-seed-tick.md`.
