# P15 — 시간 모델 타입

Spec: §18.1 (정수 틱, 타입으로 강제되는 부동소수점 시간 누적 금지), §3.4,
§28.2 Wave 2. 검토 등급 A.

## context (범위)

```
crates/es-core/src/time.rs
crates/es-core/src/lib.rs
docs/packets/M0/P15.md
```

## spec (사양)

- `PhysTick(u64)` — 물리 틱 카운터. 검사형(checked) / 포화형(saturating) 틱
  연산, `Ord`, serde.
- `TickRate` — 정확한 유리수 Hz(`num / den`, 둘 다 0이 아님).
  `TickRate::hz(1000)`, `TickRate::rational(num, den)`. 어디에도 `f64` 필드는
  없다.
- `SimTime { tick, rate }` — 시간은 *항상* 틱 개수와 rate의 조합이다. `f64`는
  오직 경계인 `as_secs_f64()`에서만 등장하며, 이는 정확한 정수 부분과 소수
  나머지로 분리하여 정확히 표현 가능한 시간이 정확하게 유지되도록 한다.
- 틱에 대한 `Duration` 유사 연산(`add_ticks`, `checked_sub`, `ticks_since`).
- 이 타입들로는 `f64` 초를 누적하는 것이 불가능하다 — `+= f64`가 존재하지
  않는다.

## oracle (오라클)

```
cargo test -p es-core --lib time::
```

## acceptance (수용 기준)

- `SimTime::new(PhysTick(1_000_000), TickRate::hz(1000)).as_secs_f64() ==
  1000.0`이 정확히 성립한다.
- `as_nanos()`는 1e9를 나누는 rate에 대해 정확하다(1 kHz ->
  1_000_000_000_000 ns).
- `PhysTick`, `TickRate`, `SimTime`에 대한 serde 왕복.
- `TickRate::rational(n, 0)`은 패닉이 아니라 오류다.

## forbidden (금지)

`context` 밖의 어떤 파일도 안 된다. 어떤 타입에도 `f64`를 저장하지 않는다.
벽시계(wall-clock) / `Instant` 접근 금지.
