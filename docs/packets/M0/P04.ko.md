# P04 — `check-scope` (diff ↔ 패킷 범위)

Spec: §1.2 (작업 패킷: `context`/`spec`/`oracle`/`acceptance`/`forbidden`), §1.7
(실패 모드 표: "조용한 범위 확장" → `xtask check-scope`가 diff를 패킷 범위와 대조).

## context (범위)

```
xtask/src/scope.rs
xtask/src/main.rs
docs/packets/M0/P04.md
```

## spec (사양)

`cargo xtask check-scope <packet.md>`는 패킷 파일 하나를 읽어 그 `## context`
표제 아래의 glob 목록을(펜스 코드 블록이든 `-`/`*` 불릿 목록이든, 줄당 glob 하나,
인라인 백틱은 제거) 추출하고, 작업 트리가 현재 차이 나는 모든 파일이 적어도 하나의
glob으로 덮이는지 검사한다:

- 변경된 파일 = `git diff --name-only HEAD`(`HEAD` 기준 staged + unstaged)와
  `git status --porcelain --untracked-files=all`의 추적되지 않는 파일의 합집합이다.
- glob 문법은 패킷 파일들이 실제로 사용하는 `.gitignore`의 부분집합이다:
  `**`(`/`를 가로지르는 것을 포함해 임의 깊이), `*`(`/`가 아닌 문자의 임의 연속),
  `?`(`/`가 아닌 문자 하나), 그 외에는 리터럴 문자. 중괄호나 대괄호 클래스는 없다
  — 어떤 패킷도 그것을 필요로 하지 않는다.
- 어떤 glob에도 매칭되지 않는 변경 파일은 검사를 실패시키며 `out of scope:
  <path>`로 출력된다.

`parse_context_globs`와 `path_matches_any`(glob → regex)는 순수 함수이며 git을
건드리지 않고 단위 테스트된다; `run()`은 얇은 `git` 셸 래퍼다.

## oracle (오라클)

```
cargo test -p xtask scope::
cargo xtask check-scope docs/packets/M0/P04.md
```

## acceptance (수용 기준)

- 단위 테스트는 다음을 다룬다: 펜스 블록 파싱, 불릿 목록 파싱, 중첩 경로에
  매칭되는 `**`, 자기 자신에만 매칭되는 리터럴 파일명, `/`를 건너지 않는 단일 `*`.
- `## context`가 실제 diff를 덮는 패킷에 대해 `check-scope`를 실행하면 통과한다;
  덮지 못하는 패킷에 대해서는 실패하고 문제가 된 경로(들)를 명시한다.

## forbidden (금지)

- `glob`이나 `globset` 크레이트는 사용하지 않는다 — 위의 네 토큰 부분집합은
  `regex`(이미 P02/spec-refs의 의존성)로 손수 구현할 만큼 짧다.
- `.gitignore` 스타일의 부정(`!pattern`)은 특별 취급하지 않는다 — 이 저장소의
  어떤 패킷도 그것을 필요로 하지 않는다.
- `crates/**` 아래는 수정하지 않는다.
