## spec (사양)

- `import_gltf(bytes: &[u8], base_dir: Option<&Path>) -> Result<GltfImport, GltfError>`는
  `.gltf`(데이터 URI로 내장된 버퍼를 가진 JSON, 또는 `base_dir` 기준으로 해석되는 외부
  파일)와 `.glb`(바이너리 컨테이너, BIN 청크 내 버퍼) 양쪽을 읽는다. 내장/데이터 URI
  버퍼만 있는 `.gltf`에서는 파일을 열지 않는다; `base_dir`는 외부 URI가 있을 때만 필요하다.
- `GltfImport { scene: SceneDesc, meshes: Vec<MeshData>, materials: Vec<MaterialData>,
  warnings: Vec<Warning> }`. `MeshData { id, name, positions, normals, uvs, indices,
  material }`와 `MaterialData { id, name, base_color, metallic, roughness, emissive,
  textures }`는 spec 15.1이 mesh/material 자산에 요구하는 payload를 담는다; 이들의 `id`는
  `scene.assets` 내 대응하는 `AssetRef`와 일치하므로 호출자가 둘을 조인할 수 있다.
- glTF에는 joint 개념이 없다: 모든 노드는 정적 `Body`가 된다(`parent`는 이미 별도의 joint
  없이도 "fixed to parent"를 의미한다); mesh 노드는 primitive당 하나의 `Geom`이 되며,
  `contype`/`conaffinity`는 `0`이다(glTF는 충돌 의도를 담지 않으므로 임의로 만들어내지
  않는다).
- 축 변환(spec 3.1): glTF는 오른손 Y-up이고, spec 3.1은 오른손 Z-up X-forward다. 고정
  쿼터니언인 `AXIS_FIX`가 모든 position과 vertex/normal을 회전시키고 모든 orientation을
  켤레(conjugate) 처리한다(`q' = FIX*q*FIX^-1`); 노드별 변환이 트리를 두 번 순회하지
  않고도 계층 구조 전체에서 올바르게 합성되는 이유를 포함해 모듈 문서에 기술되어 있다.
- 스케일: 균등(uniform) 노드 스케일은 해당 노드의 mesh vertex position에 바로 반영(bake)
  된다. 비균등(non-uniform) 스케일은 적용하지 않은 채로 두고 `Warning`으로 기록한다
  (normal에 대한 역전치(inverse-transpose) 보정이 필요한데 이 임포터는 이를 구현하지
  않는다) — 조용히 버려지는 일은 없다.
- 안정 id는 `crate::mjcf` 스킴을 따른다: `scene_id("body", <node path>)`이며, 경로는
  루트로부터 이어지는 노드 이름 체인을 "/"로 이어붙인 것이다; 파일이 이름을 남기지 않은
  노드/mesh는 `node_<index>` / `mesh_<index>`가 된다. 순회 순서는 문서 순서다
  (`Document::nodes()`, 인덱스 우선); 자식으로만 도달 가능한 노드는 그 부모가 재귀적으로
  방문할 때 함께 방문된다.
- mesh의 `AssetRef::hash`는 소스 바이트가 아니라 *디코딩된* vertex/index 배열에 대한
  `blake3` 값이다: 동일한 지오메트리라면 `.gltf` 데이터 URI로 표현되든 `.glb` 바이너리
  청크로 표현되든 동일하게 해시된다.
- `GltfError`는 `thiserror` enum이다(parse/validation 오류, 누락된 BIN 청크, 잘못된 데이터
  URI, 디코딩 길이가 선언된 길이와 다른 버퍼, 읽을 수 없는 외부 파일, `POSITION`이 없는
  primitive, 노드 순환) — 형식이 잘못된 입력은 항상 타입이 있는 오류이며 결코 panic이
  아니다.

## acceptance (수용 기준)

- 2노드 계층(`tests/fixtures/gltf/hierarchy.gltf`)이 라운드트립된다: body pose는 손으로
  계산한 축 변환 translation/rotation과 일치하고, 이름 없는 자식은 id `body/root/node_1`을
  얻으며, 그 mesh geometry는 축 변환되어 있다.
- 같은 문서를 `.glb`로 재구성해도(테스트에서 동일한 JSON + raw 바이트로 빌드) `.gltf`
  데이터 URI 버전과 동일한 mesh `AssetRef::hash`를 낸다.
- 비균등 노드 스케일(`nonuniform_scale.gltf`)은 정확히 하나의, "non-uniform"을 언급하는
  `Warning`을 발생시키고 mesh position은 스케일이 적용되지 않은 채로(단, 축 변환은 된
  채로) 남는다.
- 선언된 `byteLength`와 디코딩된 바이트 수가 다른 버퍼(`malformed_truncated.gltf`)는
  panic이 아니라 `GltfError::BufferLength`를 반환한다.

입력이지 golden 출력이 아니다). trait 추가(`INV-17`). 어디에서든 `HashMap` / `HashSet`
사용(spec 3.4). 이미지 픽셀 데이터 렌더링 또는 디코딩 — texture의 `AssetRef`는, 나중
패킷이 실제로 이미지 바이트를 읽기 전까지는, 다른 곳의 `AssetRef::from_path`와 마찬가지로
경로로만 식별된다.
