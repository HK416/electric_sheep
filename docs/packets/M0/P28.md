# P28 — TOML / `.esgraph` serialization + `.eslayout` sidecar round-trip

Spec: spec 14.1 (authoring frontends agree on the canonical IR), spec 14.3 (save format table:
`*.toml`, `*.esgraph`, `*.eslayout`, `bundle.eslock`), spec 4.2 rule 7 (`es-ir` knows no UI
types; layout lives in `.eslayout` sidecars), spec 23.2 (graph editor view — read for what a
layout sidecar must hold, not implemented here).

## context

```
crates/es-ir/src/serial.rs
crates/es-ir/tests/serial_*.rs
docs/packets/M0/P28.md
```

## spec

- `IrKind { Task, Observation, Learning, Deployment, Evaluation }` and a tagged envelope
  `IrFile<T> { es_schema, kind, body }` so a `.toml`/`.esgraph` file self-identifies (spec
  14.1: `es run task.toml` / `task.esgraph` must agree).
- Generic `write_toml<T: Serialize>` / `parse_toml<T: DeserializeOwned>`, plus one
  `{ir}_to_toml` / `{ir}_from_toml` pair per IR (`task_to_toml`/`task_from_toml`, and the same
  for `observation`, `learning`, `deployment`, `evaluation`). `{ir}_from_toml` returns
  `SerialError::KindMismatch` if the file's `kind` does not match.
- TOML has no way to forbid `nan`/`inf` (the format accepts them as bare literals); `write_toml`
  rejects any non-finite float with `SerialError::NonFiniteFloat`.
- `Graph<N>::nodes` is `BTreeMap<NodeId, N>`. `NodeId`'s derived `Serialize` writes a bare
  `u32`, and TOML tables require string keys, so `toml::to_string` on `TaskIr` / `ObservationIr`
  / `LearningGraph` as-is fails with "map key was not a string". Fixed **inside this file only**
  (not by touching `graph.rs`, `task.rs`, `observation.rs` or `learning.rs`, which other packets
  own): a private `GraphToml<N>` mirror re-keys `nodes` to a decimal string, and a per-IR TOML
  mirror (`TaskIrToml`, `ObservationIrToml`, `LearningGraphToml`) swaps in `GraphToml` for the
  `graph`/`nodes` field. `DeploymentIr` and `EvaluationIr` have no `NodeId`-keyed map and
  serialize directly, no mirror needed.
- `Layout { positions: BTreeMap<NodeId, [f32; 2]>, collapsed: BTreeSet<NodeId>, notes:
  BTreeMap<NodeId, String> }` — the `.eslayout` sidecar (spec 14.3, spec 23.2 node
  positions/collapse state/notes) and **the only place layout exists** (rule 7). Its two
  `BTreeMap`s hit the same `NodeId`-key problem, so `Layout` gets a hand-written
  `Serialize`/`Deserialize` through the same string-keyed mirror instead of a derive.
- `AnyIr { Task(TaskIr), Observation(ObservationIr), Learning(LearningGraph),
  Deployment(DeploymentIr), Evaluation(EvaluationIr) }` tags a decoded IR by which of the five
  it is (mirrors `IrKind`, no new trait). `write_esgraph(&AnyIr, Option<&Layout>) ->
  Result<(String, Option<String>)>` writes the `.esgraph` body and, if given, the `.eslayout`
  sidecar as two independent strings; `parse_esgraph(graph_toml, Option<layout_toml>) ->
  Result<(AnyIr, Option<Layout>)>` reads them back. The layout never reaches the IR: the
  `.esgraph` string is identical with or without a layout attached, and `parse_esgraph` decodes
  the IR from `graph_toml` alone.
- `SerialError` is a plain enum (`Ser`, `De`, `NonFiniteFloat`, `BadNodeId`, `KindMismatch`)
  with a hand-written `Display`/`Error`, since `es-ir`'s `Cargo.toml` does not depend on
  `thiserror` and this packet does not edit `Cargo.toml`.

## oracle

```
cargo test -p es-ir serial
```

## acceptance

- `parse_{ir}_toml(write_{ir}_toml(ir)) == ir` for a hand-built fixture of all five IRs, and
  each IR's `*_hash()` is unchanged after the round trip (`serial_*_round_trips_and_keeps_hash`).
- A `Layout` with arbitrary positions/collapsed/notes leaves the `.esgraph` string and the
  decoded IR's hash unchanged, whether attached or not
  (`serial_layout_never_changes_the_ir_or_its_hash`).
- Parsing a file of one `IrKind` as another errors with `KindMismatch`, not a generic parse
  failure (`serial_mismatched_kind_is_an_error`).
- Writing a value containing `NaN` or `±inf` anywhere fails with `NonFiniteFloat`
  (`serial_non_finite_float_is_rejected_on_write`).

## forbidden

Any file outside `context` — in particular `graph.rs`, `task.rs`, `observation.rs`,
`learning.rs`, `deployment.rs`, `evaluation.rs`, `hash.rs`, `lib.rs`, `Cargo.toml` (all owned by
concurrent packets). Depending on the `testing` module's fixture/proptest helpers (renamed by an
in-flight packet) — fixtures here are hand-built. Implementing the graph-editor UI itself (spec
23.2 is read-only context for what `Layout` must hold). Adding a new trait — `AnyIr` is a plain
enum, not an extension point.
