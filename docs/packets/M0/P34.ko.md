# P34 — URDF 임포터 + `package://` 해석

사양: spec 3.1 (Z-up SI 규약, 쿼터니언 xyzw `w >= 0` — URDF는 이미 이를 만족하므로 축 변환
없음), spec 17.2 (백엔드 시맨틱 매핑 — `<transmission>`은 변환 모델이 아니라 선언된
액추에이터), spec 18.2 (액추에이터), spec 5.3 (`asset_hash -> scene_hash`).
Spec 28.2 Wave 4, `P34 URDF + package://`. 검토 등급 A. P30(`SceneDesc`)을 기반으로 하며
MJCF용으로 P32/P33이 정한 id / 속성 파싱 방식을 따른다.

## spec (사양)

- `pub fn parse_urdf(xml: &str, resolver: &PackageResolver) -> Result<Import, UrdfError>`.
  `mjcf::parse_str`와 동일한 `Import { scene, warnings }` 형태를 갖는다.
- `<link>`: `<inertial>`(`mass`, `origin xyz/rpy`, `ixx..izz`)은 `BodyInertial`로 변환된다.
  각 `<visual>` / `<collision>`의 `<geometry>`(`box size`, `cylinder radius/length`, `sphere
  radius`, `mesh filename/scale`)는 `<origin xyz rpy>`와 함께 `Geom`이 되며, `visual_only`로
  둘을 구분한다.
- `<joint type="...">`: `fixed` → `JointKind::Fixed`, `floating` → `Free`, `revolute` /
  `continuous` → `Hinge`(`continuous`는 range를 갖지 않음), `prismatic` → `Slide`, `planar` →
  `UrdfError::Unsupported`. `<origin>`은 부모에 대한 자식 바디의 상대 pose가 된다. `<axis>`와
  조인트 anchor는 자식 바디 프레임 기준이다(URDF의 조인트 프레임이 곧 자식 링크의 origin이므로
  `anchor = 0`). `<limit lower/upper>` → `range`; `effort`는 이를 참조하는 `<transmission>`의
  `force_range`에 반영되고, `velocity`는 `SceneDesc`에 대응 필드가 없어 경고로 처리된다.
  `<dynamics damping/friction>` → `damping` / `friction_loss`. `<mimic>`은 오류가 아니라
  경고(미지원)로 처리된다.
- `<transmission>`은 `<actuator>` 자식 하나당 하나의 `Actuator`(`ActuatorKind::Motor`,
  `gear[0] = mechanicalReduction`, 기본값 1.0)가 되어 이름이 지정된 조인트를 대상으로 한다.
  알 수 없는 조인트를 참조하는 transmission은 `UrdfError::UnknownJoint`이다.
- RPY → 쿼터니언 변환: 고정축(외재적) X, 다음 Y, 다음 Z 순서 — `q = qz * qy * qx` — 이후
  `w >= 0`으로 정규화한다(spec 3.1). 축 재매핑은 없다: URDF는 이미 오른손 좌표계 Z-up SI이다.
- 기구학적 트리(kinematic tree): 모든 링크는 `Body`이다. 어떤 조인트의 `<child>`도 아닌
  링크가 루트이다(`parent == None`). 그러한 링크가 0개이거나 2개 이상이면 추측하지 않고
  `UrdfError::NoRoot` / `MultipleRoots`로 처리한다. 두 조인트가 동일한 링크를 `<child>`로
  주장하면 `MultipleParents`이다.
- `<gazebo>`, `<material>`(robot 레벨) 및 그 밖의 인식되지 않는 요소는 파싱 실패가 아니라
  `Warning`이 된다.
- `PackageResolver { pub roots: BTreeMap<String, PathBuf> }`: `resolve("package://pkg/x") ->
  Result<PathBuf, UrdfError>`는 `pkg`의 root와 나머지 경로를 결합하거나, 보유 중인 모든
  root를 나열하는 `UnknownPackage { package, known }`를 반환한다. `file://`와 일반 경로는
  그대로 통과한다. `PackageResolver::from_env()`는 `ROS_PACKAGE_PATH`(Windows에서는 `;`
  구분, 그 외에는 `:` 구분)를 읽어 각 디렉터리를 재귀적으로 탐색하며 `package.xml`을 찾아 그
  `<name>`을 읽는다 — 그 자체가 패키지인 디렉터리는 더 이상 탐색하지 않는다. 참조된 메시의
  `AssetRef.hash`는 *해석된 경로 문자열*의 `blake3`이다: 실제로 파일이 읽히면 P31(또는 이후
  패킷)이 이를 콘텐츠 해시로 대체한다. 단위가 아닌 `<mesh scale>`은 경고이다: `Shape::Mesh`는
  아직 scale 필드를 갖지 않는다.

## acceptance (수용 기준)

- `arm2.urdf`: 바디 3개, `base_link`가 루트(`parent == None`), 질량/limit/rpy가 픽스처의
  리터럴 값과 일치하며, `shoulder`의 range는 정확히 `[-pi/2, pi/2]`이다.
- `mixed_joints.urdf`: `fixed` / `continuous` / `prismatic`가 모두 올바른 `JointKind`로
  매핑된다(픽스처가 limit을 생략했음에도 `continuous`는 `range == None`이다). transmission의
  actuator는 조인트의 `effort`로부터 `gear[0] == 50`과 `force_range == Some((-10, 10))`을
  가지며, `package://robo_pkg/...` 메시는 중복 제거된 하나의 `AssetRef`로 해석되고,
  `<gazebo>`는 파싱을 실패시키지 않고 `warnings`에 나타난다.
- `two_roots.urdf`는 `UrdfError::MultipleRoots`로 실패하고, `malformed.urdf`는
  `UrdfError::Xml`로 실패하며, 둘 다 패닉하지 않는다.
- 문서 내 `<link>` / `<joint>` 요소의 순서를 바꿔도 `scene_hash()`는 변하지 않는다(id는
  순서가 아니라 이름에서 파생되기 때문 — spec 5.3).
- `PackageResolver::resolve`와 `::from_env`는 임시 디렉터리를 대상으로 단위 테스트된다:
  해석 성공, 알 수 없는 패키지가 자신이 보유한 root를 나열하는 경우, `from_env`가
  `ROS_PACKAGE_PATH`를 읽어 `package.xml`의 `<name>`을 찾는 경우.
