# P17 — 풀 + bump 아레나 + 무할당 단언

Spec: §3.4 (결정적이고 할당 없는 핫 루프), §28.2 Wave 2. 검토 등급 B.

## context (범위)

```
crates/es-core/src/pool.rs
crates/es-core/src/arena.rs
crates/es-core/src/alloc_count.rs
crates/es-core/src/lib.rs
docs/packets/M0/P17.md
```

## spec (사양)

- `Pool<T>` — 프리 리스트와 세대(generational) `Handle<T>`를 가진
  밀집(dense) `Vec` 슬롯; `insert / get / get_mut / remove / contains /
  len`. 오래된 핸들은 결코 해석되지 않는다. `Handle<T>`는 `T`와 무관하게
  `Copy + Ord`다.
- `BumpArena` — 용량은 생성 시 고정된다(포인터가 안정적이며 숨겨진 확장
  할당이 없다), 16바이트 정렬된 백킹 저장소, `&self`를 통한 `alloc<T: Copy>`
  / `alloc_slice<T: Copy>`, 그리고 `reset(&mut self)` — `&mut self`가
  reset을 안전하게 만드는 이유는, 그 시점에는 넘겨준 모든 참조가 이미
  죽었기 때문이다.
- `AllocCounter<A>` — 스레드별 할당 횟수를 세는 `GlobalAlloc` 래퍼로,
  `cfg(test)` 또는 `alloc-count` 기능 아래에서 `#[global_allocator]`로
  설치된다.
- `assert_no_alloc(f)` — `f` 내부에서 전역 할당자가 호출되면 패닉한다;
  카운터가 설치되지 않은 경우에는 아무 일도 하지 않는다.

## oracle (오라클)

```
cargo test -p es-core --lib -- pool:: arena:: alloc_count::
```

## acceptance (수용 기준)

- `assert_no_alloc(|| arena.alloc(...))`은 통과한다;
  `assert_no_alloc(|| Vec::<u8>::with_capacity(1))`은
  패닉한다(`#[should_panic]`).
- Pool: `remove` 이후 오래된 핸들은 `None`을 준다; 슬롯 재사용은 세대를
  증가시킨다.
- Arena: `used()`는 정렬 패딩을 반영하고, 용량 초과 할당은 패닉하며,
  `reset()`은 `used()`를 0으로 되돌리고 동일한 메모리를 재사용한다.

## forbidden (금지)

`context` 밖의 어떤 파일도 안 된다. 아레나 확장 금지. `// SAFETY:` 주석 없이
`arena.rs` / `alloc_count.rs` 밖에서 `unsafe` 사용 금지. 범용 할당자 추상화
트레이트 금지(INV-17).
