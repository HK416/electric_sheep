Spec: §1.4 (오라클 우선 원칙 — "골든은 CI 읽기 전용"), §1.7 (실패 모드 표: "테스트 고치기").

## context

```
xtask/src/goldens.rs
xtask/src/main.rs
docs/packets/M0/P03.md
```

## spec

`tests/golden/**` holds reference fixtures (golden images/tensors, §1.4) that a passing
test must match, never the other way around — an agent must not "fix" a failing test by
editing the golden file to match its own output. `cargo xtask verify-goldens` enforces
this mechanically:

- Diff `tests/golden/**` between `HEAD` and the merge-base with `main` (falling back to
  `origin/main`, then to `HEAD` itself when neither resolves — e.g. on `main` or a detached
  checkout, where the only meaningful comparison left is the working tree), plus the
  working-tree diff against `HEAD` (covers uncommitted edits).
- `git diff --name-status` reports one of `A`/`M`/`D`/`R…`; only `A` (a brand new golden
  file) is allowed. `M`, `D`, and renames are violations.
- `GOLDEN_UPDATE=1` bypasses the check (for the rare deliberate golden refresh, done by a
  human/reviewed commit, not by an agent silently unblocking its own PR).
- No `tests/golden/` directory yet → nothing to check, the command passes.

`classify(&[Change]) -> Vec<String>` is the pure rule (fed literal `Change{status, path}`
fixtures in tests); `run()` is the thin git-shelling wrapper around it.

## oracle

```
cargo test -p xtask goldens::
cargo xtask verify-goldens
```

## acceptance

- Unit tests: an `A` change produces no violation; `M`/`D`/`R…` each do.
- `cargo xtask verify-goldens` passes on the current repo (no `tests/golden/` yet).
- Setting `GOLDEN_UPDATE=1` turns a would-be failure into a pass (exercised once
  `tests/golden/` exists; until then this is dead code path, not a dead feature).

## forbidden

- No golden-file content or format policy here — this packet only enforces
  read-only-ness of whatever ends up under `tests/golden/**`.
- Do not add a `tests/golden/` directory or any fixtures in this packet.
- No edits under `crates/**`.
