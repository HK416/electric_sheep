## spec

- `hash::canonical_order(&Graph<N>) -> Result<Vec<NodeId>, Diagnostic>` — the ranking that was
  private to `canonical_hash`, lifted out so normalization and hashing read the same order and
  cannot drift apart.
- **`canonical_hash` bug fix (encoding changed).** The old two-pass upstream/downstream
  fingerprint left genuine ties, and ranking those by a tie-break made the hash depend on node
  ids — `hash_independent_of_node_ids` (B.7.1, gate 2) failed on a five-node graph where two
  nodes tie but their parents do not. Node colours are now refined to a fixpoint, and nodes,
  edges and boundary ports are encoded **by colour as sorted multisets** instead of by rank, so
  no tie-break exists to be unstable. `CANON_TAG` is unchanged because no hash has been stored
  anywhere yet; the counterexample is pinned by `hash::tests::ties_whose_parents_differ_still_
  hash_stably` and by the checked-in proptest regression seed.
- `norm::canon_graph` / `canon_task` / `canon_observation` / `canon_learning` — relabel nodes
  to `NodeId(0)..` in canonical order and sort the edge list. Nothing semantic is stripped:
  the graph boundary is an argument list, so its order stays as authored. Deployment IR and
  Evaluation IR carry no graph, so their normalization is the identity and has no function.
  No new trait (INV-17).
- The five IR modules expose their proptest generators as
  `#[cfg(any(test, feature = "testing"))] pub mod testing`, with the names unified as
  `arbitrary_task_ir` / `arbitrary_observation_ir` / `arbitrary_learning_graph` /
  `arbitrary_deployment_ir` / `arbitrary_evaluation_ir`; `es_ir::testing` re-exports all of
  them plus the P25 helpers (`shuffle_*_ids`, `*_edits`, `arbitrary_layout`,
  `arbitrary_unit`).
- `codes.rs` owns every diagnostic code: the `// TODO(P27-merge)` local constants of the five
  IR modules (`TASK-001`, `OBS-040..043`, `LRN-001..030`, `DEP-001..040`, `EVAL-001..006`)
  move into `CODES` with a severity, a title and a spec section, and the modules refer to
  `codes::*`. No code number had to be renumbered — the local blocks did not collide.

## acceptance

The five Appendix B.7 properties hold, for every IR they apply to:

- `hash_independent_of_node_ids` — Task, Observation, Learning (Deployment and Evaluation have
  no node ids). Plus the spec 11.2 separation: a relabelling moves `task_graph_hash` and only
  `task_graph_hash`.
- `hash_independent_of_ui` — a layout sidecar rides alongside the IR and never reaches a hash,
  because no hash entry point takes one. `TODO(P28)`: switch to an `.esgraph` round trip once
  the writer/parser exists.
- `roundtrip_preserves_hash` — serde_json (`float_roundtrip`) for all five IRs, every `*_hash`
  they expose.
- `param_change_changes_hash` — one-step edits (a numeric parameter, an added node, a dropped
  edge, a renamed output) for all five IRs, under `prop_assume!(edited != original)`.
- `unit_algebra_laws` — `mul` commutes and `div` inverts it over the algebraic units. The
  opaque units of `docs/design/ir-types.md` are excluded and separately asserted to reject
  algebra with `TYPE-010`.

Plus: `codes::CODES` stays unique, sorted and well-formed, and every exported constant has a
row.

## forbidden

Any file outside `context`, and in particular `src/cross.rs`, `src/serial.rs`,
`src/factory.rs`, `tests/cross_*.rs`, `tests/serial_*.rs` (P26 / P28 / P29 own them) and
`Cargo.toml`. A `Canonical` trait or any other new extension point (INV-17). Reordering a
graph boundary in `canon` — that is an argument list, not a set. `HashMap` (spec 3.4).
Changing the `canonical_hash` byte encoding: it would invalidate every stored hash.
