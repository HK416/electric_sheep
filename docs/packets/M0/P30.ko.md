# P30 — `SceneDesc`와 안정 id(stable id)

Spec: spec 5.3(해시 체인, `asset_hash` → `scene_hash`), spec 3.1(좌표계·단위·쿼터니언 규약), spec 17.2(백엔드 시맨틱 매핑), spec 18.2 / spec 18.3(액추에이터와 센서), spec 4.2(레이어 2). Spec 28.2 Wave 4. 리뷰 등급 B.

## context (범위)

```
crates/es-assets/src/scene.rs
crates/es-assets/src/lib.rs
docs/packets/M0/P30.md
```

## spec (사양)

- `SceneDesc { name, bodies, joints, actuators, sensors, tendons, cameras, assets, options }`
  — 모든 임포터가 생성하고 모든 `PhysicsBackend`가 소비하는, 백엔드 중립적 씬 기술(description)이다.
  데이터만 담으며, 여기서는 물리 연산도 파일 읽기도 하지 않는다.
- `Body { id, name, parent, pose (relative to parent), inertial: Option<BodyInertial>, geoms,
  sites }`, `Joint { id, name, body, kind: Free|Ball|Hinge|Slide|Fixed, axis, anchor, range,
  damping, armature, stiffness, friction_loss, spring_ref }`, `Geom { shape:
  Plane|Sphere|Capsule|Cylinder|Box|Ellipsoid|Mesh|HeightField, pose, friction, contype,
  conaffinity, condim, density, mass, margin, gap, solref, solimp, material, rgba,
  visual_only }`, `Site`, `Camera`, `Actuator { kind: Motor|Position|Velocity|General, target:
  Joint|Tendon|Site, gear, ctrl_range, force_range }`, `Sensor { kind, target, noise, cutoff }`,
  `Tendon { kind: Fixed{joints+coefs} | Spatial{sites}, range, stiffness, damping }`,
  `AssetRef { path, hash }`, `PhysicsOptions { timestep, gravity, integrator, cone, jacobian,
  solver, iterations, impratio }`.
- 단위와 좌표계는 spec 3.1의 것이며 `es-math`(`Vec3`, `Quat`, `Pose`, `Inertia`)가 담당한다:
  Z-up 오른손 좌표계, m / rad / kg / s, `w >= 0`인 xyzw 쿼터니언. 이 타입들은 재사용할 뿐 다시
  정의하지 않는다.
- `scene_id(kind, path)`는 요소가 `StableId`를 얻는 유일한 경로다: 이는
  `StableId::from_path("<kind>/<name path>")`이며, 여기서 body 경로는 `world`부터 아래로
  이어지는 body 이름들을 `/`로 이어붙인 체인이다. 이 스킴은 모듈 문서에 기술되어 있다. id는
  이름에 의존할 뿐 요소 순서나 인덱스에는 의존하지 않는다.
- `SceneDesc::scene_hash()`는 로컬 `Canon` writer가 작성한 정규 인코딩(canonical encoding)에
  대한 blake3 값이다: id 기준 정렬된 엔티티, 리틀엔디언 정수, 길이 접두 문자열, IEEE 비트로
  표현되는 `f64`(단 `-0.0`은 `0.0`으로, 모든 `NaN`은 하나의 패턴으로 정규화). `es-ir`의
  `CanonWriter`는 재사용하지 않는다 — `es-assets`는 레이어 2이고 `es-ir`는 레이어 6이다.
- `AssetRef::from_path`는 `scene_hash`에 반영되는 자산별 `asset_hash`를 계산한다(spec 5.3).
  이 패킷에서는 *경로* 자체의 다이제스트이며, P31 / P35에서 파일 내용 다이제스트로 교체된다.
- `SceneDesc::validate() -> Result<(), SceneError>`: id는 유일해야 하고, 모든 body의 parent가
  존재해야 하며, 모든 joint / actuator / sensor / tendon 참조가 해석 가능해야 하고, body
  트리는 비순환이어야 한다.

```
cargo test -p es-assets scene
```

## acceptance (수용 기준)

- `bodies`나 `joints`의 순서를 바꿔도 `scene_hash`는 변하지 않는다; 어떤 필드든 값을 바꾸면
  변한다.
- `0.0`과 `-0.0`은 동일하게 해시된다; `AssetRef`를 추가하면 `scene_hash`가 변한다.
- `validate()`는 각각에 대응하는 잘못된 씬에 대해 `DuplicateId`, `MissingParent`,
  `BodyCycle`, `DanglingRef`를 반환하고, 올바른 트리에 대해서는 `Ok`를 반환한다.
- 주어진 이름 경로에 대한 `scene_id` 출력은 프로세스 간에 안정적이다(이는
  `StableId::from_path`이며, P13 자체 테스트로 고정되어 있다).

## forbidden (금지)

`context` 밖의 모든 파일. `crates/es-ir/**`(인접 패킷의 소관). 루트 `Cargo.toml`,
`clippy.toml`, `rustfmt.toml` 수정. trait 추가(`INV-17`: 7개 확장 지점은 고정되어 있으며
여기에는 해당하는 것이 없다). 어디에서든 `HashMap` / `HashSet` 사용(spec 3.4). 질량 속성
계산, geom으로부터의 관성 계산, 순기구학(forward kinematics), 그 밖에 백엔드가 소관하는
어떤 것도 계산하는 것 — 이 패킷은 파일에 적힌 내용을 그대로 저장할 뿐이다.
