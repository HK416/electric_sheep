# P23 — Deployment IR + `SafetyEnvelope` schema

Spec: spec 9 (all), spec 5.1, spec 8.5, Appendix B.4, `INV-12`. Review class A (safety).

## context

```
crates/es-ir/src/deployment.rs
crates/es-ir/tests/            (none needed; the oracle is the module's own test mod)
docs/packets/M0/P23.md
```

## spec

- `DeploymentIr { schema_version, robot, action, safety, execution, deadlines, watchdogs,
  fallback, rate }` — every field spec 9.2 lists. `action` is the deployment-side reduction of
  spec 8.5 `ActionSpec` (space, dim, horizon, execute_chunk); Learning IR owns the authoring
  form.
- `SafetyEnvelope` (spec 9.3): per-joint `position` + `position_soft_margin`, `velocity_max`,
  `acceleration_max`, `torque_max`, optional `jerk_max`, `action_rate` (1st and 2nd difference
  per tick), `workspace` (box / cylinder / convex hull), `ee_velocity_max`, `min_self_distance`,
  `min_env_distance`, `contact_force_max`. `Vec` sized by `n_joints()`; the const-generic
  `SafetyEnvelope<NJ>` of Appendix B.4 is the `es-safety` runtime mirror, not this type.
- `Watchdog` / `WatchdogSet` / `FallbackPolicy` exactly as spec 9.4, minus the `NanInf`
  watchdog: non-finite rejection is unconditional in `SafetyEnvelope::contains`, so it cannot
  be configured away (`INV-12`).
- Durations are `Micros(u64)`; rates are `es_core::time::TickRate`. No `f64` time (spec 3.4).
- `DeploymentIr::validate(&self) -> Vec<Diagnostic>` and `deployment_hash()` over a
  `CanonWriter` (every field, `f64` canonicalized).

## acceptance

- A 7-DoF fixture validates with zero diagnostics; serde round-trip is equality-preserving.
- An inverted position limit reports `DEP-012`; a zero or `NaN` limit reports `DEP-013` /
  `DEP-011`; a joint-count mismatch reports `DEP-010`.
- Deadlines that cannot be met report `DEP-021` and the watchdog that now exceeds its deadline
  reports `DEP-022`; a duplicate watchdog reports `DEP-024`; an out-of-limits retract
  trajectory or an empty controller id reports `DEP-030`.
- `deployment_hash` is stable across calls and changes when any limit, workspace or execution
  mode changes.
- `testing::arbitrary_deployment_ir()` (proptest, `cfg(test)` — `proptest` is a dev-dependency
  and P23 does not own `Cargo.toml`) always validates clean and always hashes.
- No field, flag or variant can disable the envelope; the `contains` test widens limits instead.

## forbidden

Any file outside `context` — in particular `lib.rs`, `codes.rs`, `graph.rs`, `types.rs`,
`hash.rs`, `Cargo.toml` and the sibling IR modules. Any runtime behaviour: clamping,
projection, filtering, counters, the `SafetyPlane` itself (`es-safety`, layer 8). Any policy,
tensor or runtime type (that would let `es-safety` reach `es-policy`, spec 4.2 rule 8).
`DEP-031` (envelope exceeds robot capability) — it needs the robot description, so it belongs
to the cross-IR pass (P26). `DEP-114` (runtime support) — compiler, spec 11.6. New `DEP-` codes
live as local `pub const` with a `TODO(P27-merge)` until the dictionary merge.
