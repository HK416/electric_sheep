# P14 — 잡 시스템 + 결정적 분할

Spec: §3.4 (결정적 스케줄링 = 정적 분할, 디바이스 파생 분기 없음), §18.4
(순서 무관 병합), §28.2 Wave 2. 검토 등급 C.

## context (범위)

```
crates/es-core/src/job.rs
crates/es-core/src/lib.rs
docs/design/job-partitioning.md
docs/packets/M0/P14.md
```

## spec (사양)

- `partition_static(n_items, n_workers) -> Vec<Range<usize>>` — 두 인자에
  대한 순수 함수다. 디바이스 조회 없음, `available_parallelism` 없음, 부하
  분산 없음, work stealing 없음. 빈 범위는 산출되지 않는다.
- `JobSystem::new(n_workers)` — 워커 수는 항상 명시적이다(spec 3.4는 디바이스
  속성에서 파생된 알고리즘을 금지한다).
- `par_for_each_chunk(&mut [T], f)` — `f(chunk_index, range, chunk)`,
  스코프드 스레드(scoped threads).
- `par_reduce(&[T], map, merge) -> Option<R>` — 청크별 `map` 결과는 완료
  순서가 아니라 항상 청크 인덱스 순서로 병합된다. `merge`는 호출자가
  제공하는 클로저이며 부동소수점에 특화되어 있지 않다; `es-math`의
  `DeterministicAcc`가 나중에 꽂힌다.

설계 노트: `docs/design/job-partitioning.md`.

## oracle (오라클)

```
cargo test -p es-core --lib job::
```

## acceptance (수용 기준)

- `partition_static`은 `(n_items, n_workers)`에 대한 proptest 스윕에 걸쳐
  `0..n_items`를 오름차순으로 정확히 한 번씩 덮는다.
- `par_reduce`는 `1..=8`의 모든 워커 수에 대해 순차 fold와 같으며, 20회
  반복 실행에서 동일하다(스케줄링 독립성).
- `par_for_each_chunk`는 모든 원소를 정확히 한 번씩 방문한다.

## forbidden (금지)

`context` 밖의 어떤 파일도 안 된다. work-stealing 풀, rayon, 디바이스에서
파생된 워커 수, 부동소수점 특화 누산기(그것은 `es-math`, INV-17
`DeterministicAcc`의 몫이다) 금지.
