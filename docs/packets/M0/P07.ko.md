# P07 — `Scalar` trait + `DoubleF32`

Spec: §3.3 (정밀도), §4.2 확장 지점 규칙, Appendix C.1 / INV-17.

## context (범위)

```
crates/es-math/src/scalar.rs
crates/es-math/src/lib.rs
crates/es-math/Cargo.toml
docs/packets/M0/P07.md
```

## spec (사양)

`Scalar`는 허용된 일곱 확장 지점 중 하나다(INV-17). §3.3이 요구하는 타입
파라미터로, `F64Native` / `DoubleFloat` / `F32`에 해당하며 여기서는 `f64` /
`DoubleF32` / `f32`다.

- 봉인된(sealed) 트레이트다(`sealed::Sealed` 상위 트레이트): 세 표현이 전체
  집합이므로, 네 번째 구현은 사용자 확장이 아니라 스펙 변경이다.
- 요구되는 표면: `Add`/`Sub`/`Mul`/`Div`/`Neg`, `sqrt`, `abs`,
  `PartialOrd`/`PartialEq`, `from_f64`/`to_f64`, `ZERO`/`ONE`/`EPSILON`,
  `is_finite`.
- `DoubleF32`는 `|lo| ≤ ½ ulp(hi)`를 만족하는 `f32`(`hi`, `lo`)의 오차 없는
  변환(error-free-transformation) 쌍이다: Dekker/Knuth `two_sum` + `two_prod`,
  Bailey의 double-double `add`/`mul`/`div`/`sqrt`.
- `two_prod`는 `mul_add`가 사용되는 **유일한** 곳이며, 그곳에서는 필수적이다:
  `err = fma(a, b, -p)`가 곱의 분할을 정확하게 만드는 요소다. `f32::mul_add`는
  Rust에서 융합이 보장된 단일 반올림 연산이므로, 이는 모든 호스트에서
  결정적이다. 크레이트 내 다른 어떤 곳도 `mul_add`를 사용해서는 안 된다(§3.4는
  숨겨진 축약(contraction)을 금지한다).

## oracle (오라클)

```
cargo test -p es-math scalar::
```

## acceptance (수용 기준)

- `f32`, `f64`, `DoubleF32` 모두 `Scalar`를 구현한다; 다른 구현은 존재하지
  않으며 크레이트 외부에서는 추가할 수 없다.
- proptest: `DoubleF32::from_f64(x).to_f64()`는 `x`를 상대오차 `2^-47` 이내로
  왕복시킨다(이 표현은 53비트가 아니라 약 48비트의 유효자릿수를 담는다), 그리고
  `DoubleF32`의 add/mul은 `f64` 참값과 비교했을 때 `f32` 결과보다 정확도가
  떨어지는 경우가 없다.
- proptest: `two_sum` / `two_prod`는 오차가 없다 — `f64`에서 정확히 `a + b == s
  + e`이고 `a * b == p + e`다.
- `cargo clippy -p es-math --all-targets -- -D warnings`가 깨끗하다; `unsafe`
  없음.

## forbidden (금지)

- 일반화된 수치 타워(`num-traits`) 금지, 수십 개 메서드를 가진 `Float` 스타일
  트레이트 금지, `Scalar`에 초월함수 금지(그것은 `approx`, P08의 몫이며 `f32`
  전용이다).
- `approx/`, `conventions.rs`, `reduce.rs`, `simd.rs`(P08–P12)는 건드리지
  않는다.
- 루트 `Cargo.toml` 수정 금지.
