## spec

`xtask` is a plain Rust binary (no `clap`; a hand-rolled `std::env::args` dispatcher is
enough for a handful of subcommands) invoked as `cargo xtask <command>`. This packet lays
the skeleton every later Wave 0 packet plugs into:

- `main.rs` resolves the workspace root from `CARGO_MANIFEST_DIR` (xtask's own manifest
  lives at `<root>/xtask`), dispatches on `argv[1]`, and maps `Ok`/`Err` to `ExitCode`.
- The first real check, `cargo xtask context-budget` (§1.5): for every directory under
  `crates/`, recursively sum line counts of `src/**/*.rs` (directories named `tests` or
  `benches` are skipped) and print a table with `code` and `total` columns per crate.
  `total` is every line outside an excluded inline test module; `code` further drops
  blank lines and comment-only lines (`//`, `///`, `//!`). An inline test module — a
  `#[cfg(test)]` or `#[cfg(any(..., test, ...))]` attribute followed by `mod name { ... }`
  — is excluded entirely (both columns) by tracking brace depth from the `mod` line to
  its matching close, ignoring braces inside `//` line comments and `"..."` string
  literals. The budget is judged on `code`: a crate over 6,000 `code` lines is `WARN`,
  over 10,000 is `FAIL`; the command's own exit code is failure iff any crate is `FAIL`.
- Subsequent packets (P02-P06) each add one module and one `main.rs` match arm; none of
  them re-architect the dispatcher.

## oracle

```
cargo test -p xtask context_budget::
cargo xtask context-budget
```

## acceptance

- `cargo xtask context-budget` runs against the current `crates/*` and prints one row per
  crate with its `code`/`total` line counts and `OK`/`WARN`/`FAIL` status (status from
  `code`).
- Unit tests cover the `OK`/`WARN`/`FAIL` threshold boundaries (6,000 and 10,000) without
  touching the filesystem.
- Unit tests cover the line-counting function directly: an inline `#[cfg(test)] mod
  tests { ... }` with nested braces is excluded, a `#[cfg(any(test, feature =
  "testing"))] pub mod testing { ... }` is excluded, and braces inside string/comment
  literals don't confuse the brace-depth tracking.
- No crate in the current repo is `FAIL` (the command exits 0).

## forbidden

- No `clap` or other CLI-parsing dependency — a `match` on `argv[1]` is enough for this
  many subcommands.
- Do not implement layering, spec-ref, golden, or scope checks here (P02-P04); this packet
  only owns the dispatcher shell and `context-budget`.
- No edits under `crates/**` or the root `Cargo.toml`.
