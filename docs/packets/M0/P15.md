# P15 — Time model types

Spec: §18.1 (integer ticks, no float time accumulation, enforced by the type), §3.4,
§28.2 Wave 2. Review class A.

## context

```
crates/es-core/src/time.rs
crates/es-core/src/lib.rs
docs/packets/M0/P15.md
```

## spec

- `PhysTick(u64)` — physics tick counter. Checked / saturating tick arithmetic, `Ord`, serde.
- `TickRate` — exact rational Hz (`num / den`, both non-zero). `TickRate::hz(1000)`,
  `TickRate::rational(num, den)`. No `f64` field anywhere.
- `SimTime { tick, rate }` — time is *always* a tick count plus a rate. `f64` appears only at
  the edge, in `as_secs_f64()`, which splits into an exact integer part plus a fractional
  remainder so exactly representable times stay exact.
- `Duration`-like arithmetic on ticks (`add_ticks`, `checked_sub`, `ticks_since`).
- Accumulating `f64` seconds is impossible with these types — there is no `+= f64`.

## oracle

```
cargo test -p es-core --lib time::
```

## acceptance

- `SimTime::new(PhysTick(1_000_000), TickRate::hz(1000)).as_secs_f64() == 1000.0` exactly.
- `as_nanos()` is exact for rates dividing 1e9 (1 kHz -> 1_000_000_000_000 ns).
- serde round trip for `PhysTick`, `TickRate`, `SimTime`.
- `TickRate::rational(n, 0)` is an error, not a panic.

## forbidden

Any file outside `context`. `f64` stored in any type. Wall-clock / `Instant` access.
