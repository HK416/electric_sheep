## spec

- `EvaluationIr { schema_version, task, observation, episodes, suites, metrics, acceptance,
  augmentation, replay }` — the spec 10.2 document.
- `PerturbationSuite { name, perturbations }` and `Perturbation { kind, stream }`, with
  `PerturbationKind` covering every spec 10.2 kind with typed parameters. `stream` is the
  `stream` coordinate of `TaskRng(seed_base, suite_id, episode_idx, stream)` (spec 10.4), so
  a cell's perturbation sequence cannot depend on the policy.
- `MetricSpec` — the spec 10.3 metrics (including the Safety Plane counter
  `envelope_violation_rate` and `chunk_underrun_rate`) plus the spec 12.4 performance set,
  exposed as `MetricSpec::PERFORMANCE_SET`. No single `step/s` variant.
- `AcceptanceCriterion { suite, metric, comparator, threshold, aggregation }`; `suite: None`
  is the spec's bare `envelope_violation_rate: "<= 0.01"` form.
- `EpisodeBatch { n_episodes, seeds: SeedPlan::{Base, Explicit} }` — the episode batch domain
  of spec 5.1, deterministic per spec 10.4.
- `AugmentationPolicy` (INV-15): `Disabled` (the `Default`) or `AllowList { nodes,
  justification }`. No `Enabled` catch-all exists.
- `EvaluationIr::validate(&self) -> Vec<Diagnostic>` using `EVAL-001 .. EVAL-006`, declared
  locally with `// TODO(P27-merge)` until `codes.rs` grows an `EVAL-` block.
- `EvaluationIr::evaluation_hash(&self) -> Result<[u8; 32], Diagnostic>` via `CanonWriter`.
- `EvaluationReport` / `CellResult` / `MetricValue` / `AcceptanceResult` — the spec 10.5
  `report.json` and `evaluation.lock` schema. Types only.

## acceptance

- The spec 10.2 fixture validates clean and round-trips through serde unchanged.
- An acceptance criterion naming an undeclared metric or suite yields `EVAL-001`; a duplicate
  episode seed or a repeated perturbation stream yields `EVAL-004`; `n_episodes == 0` or a
  seed-list length mismatch yields `EVAL-003`; a backwards range yields `EVAL-005`; a
  non-finite threshold or parameter yields `EVAL-002`; an unjustified allow-list yields
  `EVAL-006`.
- Changing any condition — threshold, comparator, aggregation, suite scope, perturbation
  parameter, stream, metric list, episode count, seed base, augmentation policy, replay
  policy, schema version — changes `evaluation_hash`.
- `arbitrary_evaluation_ir()` (proptest, `#[cfg(test)]`) always validates clean and hashes.

## forbidden

Any file outside `context`. Editing `lib.rs`, `codes.rs`, `graph.rs`, `types.rs`, `hash.rs`
or `Cargo.toml` (P18/P19/P27 own them, and four sibling packets are writing the other four
IRs). Running a suite, sampling a perturbation or computing a metric (that is `es-eval`,
layer 10). An `AugmentationPolicy::Enabled` variant or any other way to switch augmentation
back on wholesale (INV-15). A single `step/s` metric (spec 12.4). `HashMap` (spec 3.4).
