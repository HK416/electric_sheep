## spec (사양)

- `hash::canonical_order(&Graph<N>) -> Result<Vec<NodeId>, Diagnostic>` — 이전에는
  `canonical_hash`에 비공개였던 순위 계산을 분리하여, 정규화와 해싱이 같은 순서를 읽고
  서로 어긋날 수 없게 한다.
- **`canonical_hash` 버그 수정(인코딩 변경).** 기존의 2-pass upstream/downstream
  fingerprint는 진짜 동점(tie)을 남겼고, 이를 tie-break로 순위화하면 해시가 node id에
  의존하게 되었다 — `hash_independent_of_node_ids`(B.7.1, gate 2)는 두 노드가 동점이지만
  그 부모는 동점이 아닌 5-노드 그래프에서 실패했다. 이제 node colour를 fixpoint까지
  정제하고, 노드·엣지·boundary port를 rank가 아니라 **colour별 정렬된 multiset**으로
  인코딩하므로 불안정해질 tie-break 자체가 존재하지 않는다. 어디에도 해시가 아직 저장된
  적이 없으므로 `CANON_TAG`는 변경하지 않는다; 반례는
  `hash::tests::ties_whose_parents_differ_still_hash_stably`와 커밋된 proptest 회귀
  시드로 고정되어 있다.
- `norm::canon_graph` / `canon_task` / `canon_observation` / `canon_learning` — 정규 순서로
  노드를 `NodeId(0)..`로 재라벨링하고 edge 목록을 정렬한다. 의미론적인 것은 아무것도
  제거되지 않는다: 그래프 boundary는 인자 목록이므로 저작된 순서를 그대로 유지한다.
  Deployment IR과 Evaluation IR은 그래프를 갖지 않으므로 그 정규화는 항등(identity)이며
  함수가 없다. 새로운 trait는 없다(INV-17).
- 다섯 개의 IR 모듈은 각자의 proptest generator를
  `#[cfg(any(test, feature = "testing"))] pub mod testing`으로 노출하며, 이름은
  `arbitrary_task_ir` / `arbitrary_observation_ir` / `arbitrary_learning_graph` /
  `arbitrary_deployment_ir` / `arbitrary_evaluation_ir`로 통일한다; `es_ir::testing`은
  이들 전부와 P25 헬퍼(`shuffle_*_ids`, `*_edits`, `arbitrary_layout`,
  `arbitrary_unit`)를 재노출한다.
- `codes.rs`가 모든 진단 코드를 소관한다: 다섯 IR 모듈의 `// TODO(P27-merge)` 로컬
  상수(`TASK-001`, `OBS-040..043`, `LRN-001..030`, `DEP-001..040`, `EVAL-001..006`)는
  severity, title, spec 절(section)과 함께 `CODES`로 이동하며, 각 모듈은 `codes::*`를
  참조한다. 로컬 블록들이 서로 충돌하지 않았으므로 어떤 코드 번호도 재번호화할 필요가
  없었다.

## acceptance (수용 기준)

다섯 개의 Appendix B.7 속성이, 적용 대상인 모든 IR에 대해 성립한다:

- `hash_independent_of_node_ids` — Task, Observation, Learning(Deployment와 Evaluation은
  node id가 없다). 더하여 spec 11.2의 분리: 재라벨링은 `task_graph_hash`만 변화시키고
  다른 어떤 것도 변화시키지 않는다.
- `hash_independent_of_ui` — layout sidecar는 IR과 함께 다니지만 해시에는 결코
  도달하지 않는다, 어떤 해시 진입점도 이를 인자로 받지 않기 때문이다. `TODO(P28)`:
  writer/parser가 생기면 `.esgraph` 라운드트립으로 전환한다.
- `roundtrip_preserves_hash` — 다섯 IR 전부에 대해 serde_json(`float_roundtrip`), 그것들이
  노출하는 모든 `*_hash`.
- `param_change_changes_hash` — 다섯 IR 전부에 대한 one-step 편집(수치 파라미터, 노드
  추가, edge 제거, 출력 이름 변경), `prop_assume!(edited != original)` 하에서.
- `unit_algebra_laws` — 대수적 단위(algebraic unit)에 대해 `mul`은 교환하고 `div`는
  그것을 역연산한다. `docs/design/ir-types.md`의 불투명 단위는 제외되며, 별도로
  `TYPE-010`으로 대수 연산을 거부하는지 검증된다.

더하여: `codes::CODES`는 유일하고 정렬되어 있으며 well-formed 상태를 유지하고, export된
모든 상수는 대응하는 행(row)을 갖는다.

## forbidden (금지)

`context` 밖의 모든 파일, 특히 `src/cross.rs`, `src/serial.rs`,
`src/factory.rs`, `tests/cross_*.rs`, `tests/serial_*.rs`(P26 / P28 / P29 소관)와
`Cargo.toml`. `Canonical` trait나 그 밖의 새로운 확장점(INV-17). `canon`에서 그래프
boundary의 순서를 바꾸는 것 — 그것은 집합이 아니라 인자 목록이다. `HashMap`(spec 3.4).
`canonical_hash`의 바이트 인코딩을 바꾸는 것: 저장된 모든 해시를 무효화하게 된다.
