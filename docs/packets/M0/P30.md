## spec

- `SceneDesc { name, bodies, joints, actuators, sensors, tendons, cameras, assets, options }`
  — the backend-neutral scene description every importer produces and every `PhysicsBackend`
  consumes. Data only: no physics is computed here, and no file is read here.
- `Body { id, name, parent, pose (relative to parent), inertial: Option<BodyInertial>, geoms,
  sites }`, `Joint { id, name, body, kind: Free|Ball|Hinge|Slide|Fixed, axis, anchor, range,
  damping, armature, stiffness, friction_loss, spring_ref }`, `Geom { shape:
  Plane|Sphere|Capsule|Cylinder|Box|Ellipsoid|Mesh|HeightField, pose, friction, contype,
  conaffinity, condim, density, mass, margin, gap, solref, solimp, material, rgba,
  visual_only }`, `Site`, `Camera`, `Actuator { kind: Motor|Position|Velocity|General, target:
  Joint|Tendon|Site, gear, ctrl_range, force_range }`, `Sensor { kind, target, noise, cutoff }`,
  `Tendon { kind: Fixed{joints+coefs} | Spatial{sites}, range, stiffness, damping }`,
  `AssetRef { path, hash }`, `PhysicsOptions { timestep, gravity, integrator, cone, jacobian,
  solver, iterations, impratio }`.
- Units and frames are the spec 3.1 ones, carried by `es-math` (`Vec3`, `Quat`, `Pose`,
  `Inertia`): Z-up right-handed, m / rad / kg / s, quaternions xyzw with `w >= 0`. These types
  are reused, never redefined.
- `scene_id(kind, path)` is the only way an element gets a `StableId`: it is
  `StableId::from_path("<kind>/<name path>")`, where a body path is the `/`-joined chain of
  body names from `world` down. The scheme is documented in the module docs. Ids depend on
  names, never on element order or index.
- `SceneDesc::scene_hash()` is blake3 over a canonical encoding written by a local `Canon`
  writer: entities sorted by id, little-endian integers, length-prefixed strings, `f64` as
  IEEE bits with `-0.0` normalised to `0.0` and every `NaN` to one pattern. `es-ir`'s
  `CanonWriter` is not reused — `es-assets` is layer 2 and `es-ir` is layer 6.
- `AssetRef::from_path` computes the per-asset `asset_hash` that feeds `scene_hash`
  (spec 5.3). In this packet it is the digest of the *path*; P31 / P35 replace it with the
  file content digest.
- `SceneDesc::validate() -> Result<(), SceneError>`: ids unique, every body parent present,
  every joint / actuator / sensor / tendon reference resolvable, body tree acyclic.

## acceptance

- Reordering `bodies` or `joints` does not change `scene_hash`; changing any field does.
- `0.0` and `-0.0` hash the same; an added `AssetRef` changes `scene_hash`.
- `validate()` returns `DuplicateId`, `MissingParent`, `BodyCycle` and `DanglingRef` on the
  corresponding malformed scenes, and `Ok` on a well-formed tree.
- `scene_id` output for a given name path is stable across processes (it is
  `StableId::from_path`, pinned by P13's own test).

## forbidden

Any file outside `context`. `crates/es-ir/**` (a neighbouring packet owns it). Editing the root
`Cargo.toml`, `clippy.toml` or `rustfmt.toml`. Adding a trait (`INV-17`: the 7 extension points
are fixed, and none of them is here). `HashMap` / `HashSet` anywhere (spec 3.4). Computing mass
properties, inertia from geoms, forward kinematics or anything else a backend owns — this
packet stores what the file said and nothing more.
