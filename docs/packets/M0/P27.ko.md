# P27 — `Diagnostic` 타입 + 진단 코드 사전

Spec: spec 5.4 (`TYPE-014`), spec 7.2 (`OBS-021`, `OBS-034`), spec 6.6 (`DET-*`),
spec 11.1 (semantic checks), spec 28.2 Wave 3. Review class A.

## context (범위)

```
crates/es-ir/src/diag.rs
crates/es-ir/src/codes.rs
crates/es-ir/src/lib.rs
docs/packets/M0/P27.md
```

## spec (사양)

- `Diagnostic { code, severity, message, node, port, hint }`, 빌더 스타일
  (`Diagnostic::error(code, msg).at(node).port(name).hint(text)`), spec의 여러 줄 형식을
  그대로 반영하는 `Display`:

  ```
  ERROR TYPE-014  time alignment is not specified

    at node 7, port "camera_front"
    <message>

    hint: <hint>
  ```
- `DiagCode` — 문자열 newtype, `Severity { Error, Warning, Info }`.
- `codes::CODES` — 진단 코드마다 `CodeEntry { code, severity, title, section }` 하나씩,
  spec에 인쇄된 모든 코드에 더해 spec 5.4와 spec 11.1이 요구하는 검사들이 보고 가능하려면
  필요한 코드까지 포함한다. 코드의 severity는 이 테이블에서 나온다.

## oracle (오라클)

```
cargo test -p es-ir --lib -- diag:: codes::
```

## acceptance (수용 기준)

- `CODES`의 모든 항목은 고유하며 `^[A-Z]{2,7}-\d{3}$`에 매칭한다(`FACTORY-0xx`가 현재
  사용 중인 가장 긴 접두사이다).
- `codes.rs`의 모든 `pub const` 코드 문자열은 `CODES`에 항목을 갖는다.
- `Diagnostic::error`는 severity를 테이블에서 선택한다(`DEP-114`는 error 생성자 경로로
  만들어져도 warning이다).
- `Display`는 위 블록 형식을 그대로 재현하며, 없는 `node` / `port` / `hint`는 생략한다.

## forbidden (금지)

`context` 밖의 모든 파일. spec의 어떤 section도 요구하지 않는 검사를 위한 코드를 지어내는 것.
검사 자체를 실행하는 것 — 이 패킷은 컴파일러 패스가 아니라 어휘를 제공한다. 지역화된
메시지 텍스트(소스는 영어 전용).
