# P08 — 초월함수 minimax 다항식 (`es_math::approx`)

Spec: §3.2, §3.4, Appendix D `DET-010`. 설계 문서(선행 작성):
`docs/design/transcendental.md`.

## context (범위)

```
crates/es-math/src/approx/mod.rs
crates/es-math/src/approx/coeffs.rs
crates/es-math/src/lib.rs
docs/design/transcendental.md
docs/packets/M0/P08.md
```

## spec (사양)

고정된 평가 순서를 가진 `sin`, `cos`, `exp`, `ln`, `atan2`, `sqrt`, `rsqrt`의
`f32` 구현이다. 그래야 커널이 모든 호스트에서(그리고 P09에서 GPU에서도) 동일한
비트를 얻는다.

- 계수는 `approx/coeffs.rs`에 십진 리터럴로 존재하며, 계수마다 `pub const`
  하나에 설계 문서가 요구하는 출처 주석을 단다. 자릿수 구분자는 없다(P09의
  리터럴 비교를 깨뜨리기 때문이다); `clippy::unreadable_literal`은 그 파일에서만
  허용한다.
- 다항식마다 하나의 식으로 작성한 Horner 형태다. 재결합 없음, `mul_add` 없음,
  `fast-math` 없음, 룩업 테이블 없음, 디바이스 속성에 따른 분기 없음.
- 범위 축소는 설계 문서에 표로 정리된 그대로이며, `atan2`의 사분면 보정이 2
  ULP 이내를 유지하기 위해 필요로 하는 `PI`/`PIO2`/`PIO4`의 `_LO` 동반 상수를
  포함한다.
- IEEE 특수값을 명시적으로 처리한다(`NaN`, `±inf`, `±0`, 0 이하에 대한 `ln`).
- 주 정의역에서 목표는 ≤ 2 ULP다; 그 밖에서는 값이 합리적이지만 오차 한계가
  없다.

## oracle (오라클)

```
cargo test -p es-math approx:: -- --nocapture
```

테스트는 함수별로 측정된 최대 ULP를 출력하고 2 ULP를 넘으면 실패한다.

## acceptance (수용 기준)

- 조밀한 선형 스윕 + 결정적 의사난수 스윕, 함수당 주 정의역에서 ≥ 200k개
  지점을, `f32`로 반올림된 `f64` `std` 구현과 대조한다.
- 모든 함수에 대해 측정된 최대 ULP ≤ 2다; `docs/design/transcendental.md`의
  표가 출력된 수치와 일치한다. 측정값: `sin` 1, `cos` 1, `exp` 1, `ln` 1,
  `atan2` 2, `sqrt` 0, `rsqrt` 1.
- 특수값: `sin(NaN)`, `exp(-inf) == 0`, `exp(inf) == inf`, `ln(0) == -inf`,
  `ln(-1)`은 NaN, `atan2(0, 0) == 0`, `rsqrt(0) == inf`.

## forbidden (금지)

- `src/approx/mod.rs`에서 `f32::sqrt`(설계 문서가 허용하는, 올바르게 반올림되는
  유일한 IEEE 기본 연산) 이외의 `std` 초월함수 호출은 없다 — `f64` `std`
  함수는 참조 오라클로서 테스트 모듈에만 등장한다.
- Payne–Hanek 축소 없음, `f64` 폴백 경로 없음, 타겟별 특수화 없음.
- `scalar.rs`, `conventions.rs`, `reduce.rs`, `simd.rs`는 건드리지 않는다.
