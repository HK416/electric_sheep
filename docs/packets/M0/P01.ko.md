# P01 — `xtask` 골격

Spec: §1.6 (저장소 구조 — `xtask/`는 모든 검증의 단일 진입점), §1.5 (컨텍스트 예산).

## context (범위)

```
xtask/Cargo.toml
xtask/src/main.rs
xtask/src/context_budget.rs
docs/packets/M0/P01.md
```

## spec (사양)

`xtask`는 순수 Rust 바이너리다(`clap` 없음 — 서브커맨드 몇 개에는 손으로 짠
`std::env::args` 디스패처로 충분하다). `cargo xtask <command>`로 호출한다. 이 패킷은
이후의 모든 Wave 0 패킷이 꽂히는 골격을 놓는다:

- `main.rs`는 `CARGO_MANIFEST_DIR`로부터 워크스페이스 루트를 해석하고(xtask 자신의
  매니페스트는 `<root>/xtask`에 있다), `argv[1]`로 분기하며, `Ok`/`Err`를 `ExitCode`로
  매핑한다.
- 첫 실질 점검인 `cargo xtask context-budget`(§1.5): `crates/` 아래 모든 디렉터리에
  대해 `src/**/*.rs`의 줄 수를 재귀적으로 합산하고(`tests`, `benches`라는 이름의
  디렉터리는 건너뜀) 크레이트별로 `code`, `total` 열을 가진 표를 출력한다. `total`은
  제외 대상 인라인 테스트 모듈을 뺀 모든 줄이고, `code`는 여기서 빈 줄과 주석 전용 줄
  (`//`, `///`, `//!`)을 추가로 제외한다. 인라인 테스트 모듈 — `#[cfg(test)]` 또는
  `#[cfg(any(..., test, ...))]` 속성 다음에 오는 `mod name { ... }` — 은 `mod` 줄부터
  대응하는 닫는 중괄호까지 중괄호 깊이를 추적하여(`//` 줄 주석과 `"..."` 문자열 리터럴
  내부의 중괄호는 무시) 두 열 모두에서 완전히 제외된다. 예산 판정은 `code` 기준이다:
  크레이트가 `code` 6,000줄을 초과하면 `WARN`, 10,000줄을 초과하면 `FAIL`이며, 명령
  자체의 종료 코드는 하나라도 `FAIL`인 크레이트가 있으면 실패다.
- 후속 패킷(P02-P06)은 각각 모듈 하나와 `main.rs`의 match 분기 하나를 추가할 뿐,
  디스패처를 재설계하지 않는다.

## oracle (오라클)

```
cargo test -p xtask context_budget::
cargo xtask context-budget
```

## acceptance (수용 기준)

- `cargo xtask context-budget`는 현재 `crates/*`에 대해 실행되며, 크레이트별로
  `code`/`total` 줄 수와 `OK`/`WARN`/`FAIL` 상태(상태는 `code` 기준)를 한 행씩
  출력한다.
- 단위 테스트가 파일시스템에 접근하지 않고 `OK`/`WARN`/`FAIL` 임계값 경계(6,000과
  10,000)를 다룬다.
- 단위 테스트가 줄 수 계산 함수를 직접 다룬다: 중첩된 중괄호를 가진 인라인
  `#[cfg(test)] mod tests { ... }`가 제외되고, `#[cfg(any(test, feature =
  "testing"))] pub mod testing { ... }`가 제외되며, 문자열/주석 리터럴 내부의
  중괄호가 중괄호 깊이 추적을 혼동시키지 않는다.
- 현재 저장소의 어떤 크레이트도 `FAIL`이 아니다(명령은 0으로 종료한다).

## forbidden (금지)

- `clap`이나 그 외 CLI 파싱 의존성 금지 — 이 정도 개수의 서브커맨드에는 `argv[1]`에
  대한 `match`로 충분하다.
- 레이어링, spec-ref, golden, scope 검사는 여기서 구현하지 않는다(P02-P04); 이
  패킷은 디스패처 뼈대와 `context-budget`만 소유한다.
- `crates/**`나 루트 `Cargo.toml` 아래는 수정하지 않는다.
