# P26 — Cross-IR check rules

Spec: spec 11.1 (the `Cross-IR Check` stage), spec 5.1 (IR boundaries), spec 7.4
(`ObservationSpec` <-> Observation IR), spec 8.4 / 8.5 (policy contract, action modelling),
spec 9.2 / 9.3 / 9.5 (Deployment IR, envelope, sim-real identity), spec 10.4 (evaluation
determinism), spec 11.6, `INV-14`, `INV-15`. Review class B.

## spec

- `IrBundle<'a> { task, observation, learning, deployment, evaluation: Option<_> }` and
  `check(&IrBundle) -> Vec<Diagnostic>`: every rule spec 11.1 states *across* an IR boundary.
  Each IR's own `validate` runs first and answers for itself; `check` answers only for the
  boundaries.
- Rules, in the order spec 11.1 lists the boundaries:
  1. `Observation::task_ref` is the Task IR's `task_hash` (`XIR-001`), and every Observation
     source node (`ImageInput` / `StateInput` / `LanguageInput`) reads a channel the Task IR
     declares (`XIR-002`) with the type it declares (`TYPE-001..TYPE-020` via
     `PortType::compatible`) — Task declares, Observation implements (spec 7.4).
  2. `Observation::outputs` and `PolicyContract::inputs` name the same tensors (`XIR-010`) and
     agree on elem, shape, unit and frame; an image output advertises the geometry the graph
     actually propagates (`TYPE-020`, `INV-14`); a policy input is Normalized, Dimensionless or
     Token (`TYPE-011`); `TemporalWindow::n_steps` equals `observation_window` (`XIR-011`).
     The clock and the `ImageSpec` are the crossing point: a `TimeRef::Tick` tensor port
     legitimately consumes a sensor clock, and a tensor port need not restate the `ImageSpec`.
  3. `Learning` <-> `Deployment`: `action_dim` against the deployed action contract
     (`XIR-020`), execution mode (`XIR-021`), `horizon` / `execute_chunk` (`XIR-022`),
     `replanning_hz` in an integer relation with `dt_ctrl` (`XIR-023`), `runtime.deadline_ms`
     inside the watchdog's inference budget (`XIR-024`), and `LRN-052` when the measured
     latency exceeds that budget, or exceeds the control period without chunk buffering.
  4. Task `ActionSpec` against the policy contract and the deployed action: `dim` (`XIR-030`),
     space (`XIR-031`), `control_rate_hz` against `rate.control` (`XIR-032`).
  5. `Deployment.envelope` <-> robot capability: `DEP-031` when the envelope covers more joints
     than the Task IR's `JointState` channel declares for that robot.
  6. `Evaluation` <-> `Task` / `Observation`: a reference that *is* a digest must be the
     bundle's digest (`XIR-040`); `INV-15` — an `Augment` node that is not `training_only`
     (so it cannot be switched off structurally) must be named in the evaluation allow-list
     (`XIR-050`), and the allow-list must name real `Augment` nodes (`XIR-051`).
- `XIR-0xx` are declared locally with `// TODO(P27-merge)` until `codes.rs` grows an `XIR-`
  block; `LRN-052`, `DEP-031` and the `TYPE-*` codes come from `codes.rs`.

## acceptance

- The valid bundle — 7-DoF + gripper Franka-like robot, one 640x480 sRGB camera resized to
  224x224, ACT-shaped learning graph, 100 Hz control with a 50/20 chunk — produces no
  diagnostics, and each of the five IRs validates clean on its own.
- One violation fixture per rule asserts the exact code: `XIR-001`, `XIR-002`, `TYPE-002`
  (declaration), `XIR-010`, `TYPE-002` (contract), `TYPE-011`, `TYPE-020`, `XIR-011`,
  `XIR-020`, `XIR-021`, `XIR-022`, `XIR-023`, `XIR-024`, `LRN-052`, `XIR-030`, `XIR-031`,
  `XIR-032`, `DEP-031`, `XIR-040`, `XIR-050`, `XIR-051`.
- A bundle with `evaluation: None` checks the first five rules and stays silent about the
  sixth.
- An Evaluation reference written as an authoring path is not a hash and is not checked.
- `cross.rs` stays within one context window (599 source lines).

## not checkable yet

`DEP-031` in its full form — the envelope's *values* against the robot's torque, velocity and
position capability — needs a robot capability description. `RobotRef` carries a name, a target
and a joint count, and no IR carries a capability table, so only the envelope's width is
checkable here. Revisit when spec 11.6 capability data lands.

## forbidden

Any file outside `context`. Editing `codes.rs` (P27 is merging codes), `lib.rs`, `Cargo.toml`,
or any of the five IR modules — a mismatch found here is reported, never patched in the IR.
Depending on an IR module's `testing` helpers (the fixture is built by hand, so a neighbour's
idea of consistency cannot hide a boundary bug). Re-implementing a check an IR already makes
about itself. `HashMap` (spec 3.4). New traits or extension points (`INV-17`).
