## spec

### `es-physics-core` (layer 3)

- `PhysicsBackend` — one of the seven extension points of `INV-17`, and the only trait this
  packet adds. Object safe (`Box<dyn PhysicsBackend>`), so `es backend compare` can pick one at
  runtime (spec 17.2):

  ```rust
  fn capabilities(&self) -> &Capabilities;
  fn load(&mut self, scene: &SceneDesc, cfg: &LoadConfig) -> Result<ModelInfo, PhysicsError>;
  fn model_info(&self) -> Option<&ModelInfo>;
  fn reset(&mut self, envs: Option<&[u32]>, state: Option<&StateView<'_>>) -> Result<(), PhysicsError>;
  fn set_ctrl(&mut self, ctrl: &[f64]) -> Result<(), PhysicsError>;
  fn step(&mut self, n_substeps: u32) -> Result<StepReport, PhysicsError>;
  fn state(&self) -> StateView<'_>;
  fn set_state(&mut self, state: &StateView<'_>) -> Result<(), PhysicsError>;
  ```

- `Capabilities { name, determinism: DeterminismTier, batch: BatchSupport { max_envs,
  gpu_resident }, joints / actuators / sensors / contact: BTreeSet<Feature>, float:
  FloatPrecision, supports_reset_subset, supports_state_get_set, quirks: Vec<BackendQuirk> }`.
  `DeterminismTier` is the spec 3.5 ladder 0..4; an external backend never declares tier 1
  (spec 4.3). `BackendQuirk { feature, description }` is how an approximate mapping is
  *declared* instead of hidden (spec 17.2).
- `Requirements::from_scene(&SceneDesc)` collects the features a scene uses;
  `check_requirements(&Requirements, &Capabilities) -> Vec<Unsupported>` is what the compiler
  calls before a run (spec 11.6). Empty vector means the backend can run the scene.
- `LoadConfig { n_envs, rate: Option<TickRate>, seed }`, `ModelInfo { nq, nv, nu, nsensordata,
  nbody, n_envs, rate, qpos / dof / actuator / sensor / body: BTreeMap<StableId, IndexRange> }`,
  `StateView<'a> { n_envs, tick, qpos, qvel, act, sensordata, xpos, xquat }` (env-major
  slices), `StepReport { tick: PhysTick, failures: Vec<(u32, FailureKind)> }`.
- Time is integer ticks throughout: no method takes seconds, the step size is a `TickRate`
  fixed at load, and `TickRate::period_secs_f64` is called once, at the backend's own edge
  (spec 18.1, spec 3.4).
- Divergence is data, not a panic: the backend detects non-finite state itself and reports it
  in `StepReport::failures` (spec 18.5).

### `es-physics-backend` (layer 4)

- `MuJoCoCpuBackend`: MuJoCo (CPU) through a Python subprocess. `python/mujoco_ref.py` is
  stdlib + `mujoco`, embedded with `include_str!` and run as `python -c`, speaking
  line-delimited JSON (`load` / `reset` / `set_ctrl` / `step` / `state` / `set_state` /
  `quit`). `ES_PYTHON` overrides the interpreter, otherwise `python` then `python3`.
  `MuJoCoCpuBackend::is_available()` runs `python -c "import mujoco"` and explains what failed.
- Declared capabilities: determinism tier 3 (physics meaning — it *is* MuJoCo), `float: F64`,
  `gpu_resident: false`, `max_envs: 1`. `n_envs > 1` works (the script holds one `MjData` per
  env and loops) but is adapter-side emulation, so it is not declared as a batch capability:
  a task that requires a batch is sent to another backend at compile time (spec 11.6).
- `scene_to_mjcf(&SceneDesc) -> Result<String, PhysicsError>`: bodies, hinge / slide / ball /
  free joints, primitive geoms, `motor` / `position` / `velocity` actuators on joints,
  `jointpos` / `jointvel` sensors, and the full `<option>` (timestep, gravity, integrator,
  cone, jacobian, solver, iterations, impratio). Anything else is `PhysicsError::Unsupported`
  naming the item — spec 17.2 says declare, never guess. Quaternions are converted to MJCF's
  wxyz; angles are written in radians.
- `docs/api-notes/mujoco.md` pins the `mujoco` version, the exact calls and fields used, and
  the JSON protocol.

### Deviations from the packet brief, and why

- `set_ctrl` and `set_state` return `Result`: the buffer length is validated at the boundary
  (`ShapeMismatch`), and an out-of-process backend can fail on the write itself.
- `model_info` returns `Option<&ModelInfo>` rather than `&ModelInfo`: before `load` there is no
  model, and a panicking accessor is not something a trait should oblige every backend to have.
- `LoadConfig` carries a `TickRate`, not a timestep in seconds, so spec 18.1 is enforced by the
  type rather than by convention.
- The emitter writes the whole `<option>`, not just `timestep` and `gravity`: dropping
  `integrator` or `cone` would silently change the physics, which is the failure spec 17.2
  exists to prevent.

## oracle

```
cargo test -p es-physics-core -p es-physics-backend
```

MuJoCo-dependent tests print `SKIP <name>: <reason>` and pass when `is_available()` fails, so a
machine without the optional `mujoco` package does not fail CI. With it installed they run for
real; `ES_PYTHON=<interpreter>` selects a venv.

## acceptance

- `check_requirements` reports every unmet requirement, once each, in a stable order, and
  nothing for a met one.
- `PhysicsBackend` is object safe: a `NullBackend` test double is exercised through
  `Box<dyn PhysicsBackend>`.
- `scene_to_mjcf` round-trips `tests/fixtures/mjcf/pendulum.xml` and `arm2.xml` through
  `es_assets::parse_mjcf` with the body, joint, geom, actuator and sensor counts and kinds
  preserved; every unmappable item (mesh geom, tendon, site sensor, general actuator) is
  refused with its name in the message.
- Protocol encode / decode is unit tested against canned JSON lines with no Python involved,
  including `f64` bit-exact round trip and malformed-reply handling.
- With MuJoCo installed: the pendulum lifted to 0.3 rad and stepped 100 ticks at 1 ms moves
  towards the hanging position with finite state and no reported failures; two runs from the
  same state are bit-identical; `n_envs = 2` steps two independent envs and a subset reset
  touches only its own env.

## forbidden

Any file outside `context`. `crates/es-assets/**` (a neighbouring packet owns `gltf.rs`,
`urdf.rs` and `fuzz.rs`). The root `Cargo.toml`, `clippy.toml`, `rustfmt.toml`. Any trait
beyond `PhysicsBackend` (`INV-17`: the seven extension points are fixed). `HashMap` / `HashSet`
(spec 3.4). Floating-point time accumulation anywhere in the step loop (spec 18.1). Panicking
on divergent env state instead of reporting it (spec 18.5). Declaring determinism tier 1 from
an external backend (spec 4.3). Implementing physics: this crate maps onto an engine, it is not
one (spec 17.4 is M4+ and out of scope).
