## spec

- `ElemType`, `Shape` (per-sample dims only — the batch axis belongs to the domain, spec 5.2),
  `Unit`, `UnitPowers`, `Frame`, `Align`, `TimeRef`, `PortType` exactly as Appendix B.1.
- Unit algebra over `m^a · kg^b · s^c · rad^d`: `mul`, `div` (named unit → powers → named unit),
  `checked_add` (enum equality required). Opaque units reject `mul` / `div` with `TYPE-010`.
- `PortType::compatible` — elem / shape / unit / frame / time / image, one diagnostic per class.
- `PortType::is_policy_input` — `Normalized | Dimensionless | Token` only (`TYPE-011`).
- `TimeRef::join` — the combination rule; unspecified alignment is `TYPE-014`.
- `PortType::canonical(&mut CanonWriter)` so node params carrying a type hash reproducibly.
- Graph skeleton shared by the five IRs: `NodeId`, `PortRef`, `Edge`, `Graph<N>`, `IrNode`,
  `topo_order` (cycle → `GRAPH-001`), `validate_ports`.
- `CanonWriter` + `canonical_hash` (node-id and node-order independent) + `HashChain`
  (Appendix B.6) with `execution_hash` and `diff`.

## acceptance

- `Length / Time == Velocity`, `Velocity * Time == Length`, `mul` commutes, `div(mul(a,b),b) == a`
  for every dimensional unit; `Quaternion * Length` is `TYPE-010`.
- `checked_add(Depth, Length)` fails although both are metres.
- `PortType::compatible` returns `TYPE-014` for differing `TimeRef`s and `Ok` across `Policy`.
- `topo_order` on a cycle yields `GRAPH-001`; on a DAG it is a valid order.
- proptest `hash_independent_of_node_ids` and `param_change_changes_hash` (Appendix B.7) pass.

(P20–P24). Normalization passes and the remaining three property tests (P25). Cross-IR rules

New single-implementation traits beyond the seven extension points (INV-17) — `IrNode` is an
internal helper trait with one impl per node kind, not an extension point.
