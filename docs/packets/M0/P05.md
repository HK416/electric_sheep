## spec

External APIs an agent's training data is stale on — `ash` (Vulkan bindings), Slang, the
`torch`/`tch` C++ surface, and the LeRobot dataset/checkpoint schema — get one pinned
digest file each under `docs/api-notes/`, so implementation packets cite a checked-in
signature instead of a hallucinated or version-drifted one. This packet only stubs the
index: `docs/api-notes/README.md` states the convention (one file per library, its pinned
version in the filename or a leading heading, verified against `cargo check`/the actual
installed version before being trusted) and carries no library content yet — the digests
themselves are separate, later packets (each one gated on the library it documents
actually being pulled in).

## oracle

```
test -f docs/api-notes/README.md
```

## acceptance

- `docs/api-notes/README.md` exists and explains: what goes here, one file per library,
  pin the exact version, and that a digest must be written (or refreshed) before, not
  after, code claims to use that library's API.
- No per-library digest file is added by this packet — that's out of scope until a packet
  actually needs `ash`/Slang/`torch`/LeRobot signatures.

## forbidden

- No fabricated API signatures — this packet is prose about the convention, not content
  for any specific library.
- No edits under `crates/**` or `xtask/**`.
