# P40 — 텔레메트리 프로토콜 스켈레톤

사양: spec 23 (에디터는 실행 중인 프로세스의 클라이언트이며, 프로토콜은 백엔드 중립),
spec 25.1 (보안: 토큰 인증, QUIC TLS, 기본값 localhost), spec 25.3 (버전 관리: 핸드셰이크
협상, N-1 지원), spec 12.4 (9개 성능 지표), spec 9.6 (임베디드 런타임 텔레메트리 링
버퍼), spec 13.1 (학습 루프 이벤트).

## spec (사양)

- `protocol.rs`: `PROTOCOL_VERSION`; `Hello` / `HelloAck` 핸드셰이크 구조체;
  `negotiate(client, server) -> Option<u32>`(공통으로 지원하는 최고 버전 — spec 25.3은
  서버가 현재 버전과 그 직전 버전을 함께 제공하도록 요구하며, `negotiate` 자체는 호출자가
  `server`로 넘기는 목록이 무엇이든 그에 대해 제네릭하다); `Message` enum(`Hello`,
  `HelloAck`, `Subscribe`, `Frame`, `Ping`, `Pong`, `Bye`); `Frame { tick: PhysTick,
  wall_ns, stream: StreamId, payload: Payload }`; `Payload`(`Scalar`, `Scalars`, `Tensor`,
  `Image`, `Event`, `Metrics`); spec 12.4의 지표 집합을 이름 있는 `Option<f64>` 필드로
  담는 `PerfMetrics`(`p50 / p95 end_to_end_latency` 행은 두 개의 필드가 된다), 단일
  `step/s` 수치는 결코 사용하지 않는다.
- 인코딩: 길이 접두(length-prefixed) 방식(`codec` 바이트 + `u32` LE 길이 + 본문), 본문은
  `serde_json`, 이후 바이너리 코덱을 추가 variant로 넣을 수 있도록 `Codec` enum을 둔다.
  `encode`/`encode_with`, `decode`/`decode_with_max`. 설정 가능한 최대치
  (`DEFAULT_MAX_FRAME_BYTES` = 64 MiB)를 넘는 본문과 알 수 없는 codec/wire-version 태그는
  JSON 본문을 건드리기 전에 거부한다.
- `ring.rs`: `RingBuffer<T>` — 생성 시점에 고정되는 용량(`Vec::with_capacity` +
  `resize_with`가 유일한 할당), 가장 오래된 항목을 덮어쓰는 `push`, `iter_newest`(최신순),
  `drain_since(seq)`(비파괴적 — 링 버퍼는 리더가 여러 개일 수 있음; 아직 보유 중인 가장
  오래된 시퀀스로 클램프), `dropped()` 카운터.
- `lib.rs`: 얇은 Python 어댑터(spec 23.1: LeRobot / Isaac Lab / Newton)가 내보낼 JSON
  프레임 형태를 설명하는 doc comment — `stream`, `tick`, `payload`만 필수이며 ES 고유의
  것은 없다.
- 네트워크 의존성 없음(zenoh/quinn/tokio 없음): 이 패킷은 스키마와 인메모리 링 버퍼로
  구성된다. 전송(Transport)은 `es-transport`(레이어 11)가 담당한다.

## acceptance (수용 기준)

- `negotiate`는 목록이 겹칠 때 공유되는 최고 버전을, 클라이언트 버전이 서버의 N-1과 같을
  때는 그 클라이언트 버전을, 목록이 서로소일 때는 `None`을 반환한다.
- 모든 `Message` variant는 `encode`/`decode`를 거쳐 바이트 단위로 동일하게 왕복하며,
  `decode`는 소비한 바이트 수를 정확히 보고한다.
- `decode_with_max`는 최대치를 초과하는 본문을 `serde_json`을 호출하지 않고 거부한다.
  알 수 없는 codec 바이트는 길이를 신뢰하기도 전에 거부된다. 잘린 버퍼는 패닉이 아니라
  `Incomplete`이다.
- `PerfMetrics`는 spec 12.4의 모든 지표 이름을 포함한 채로 직렬화되고 왕복한다. 설정되지
  않은 지표는 `0.0`이 아니라 반드시 `None`으로 역직렬화된다. `step/s` 또는 그 비슷한
  이름의 필드는 없다.
- `RingBuffer`: 용량을 초과해 push하면 가장 오래된 항목을 덮어쓰고 `dropped()`를
  증가시킨다. `iter_newest`는 최신순으로 값을 낸다. `drain_since`는 오래된(stale)
  시퀀스를 아직 보유 중인 범위로 클램프하며, `next_seq`를 넘는 시퀀스에 대해서는
  아무것도 반환하지 않는다.
- `push`는 `with_capacity` 이후 힙 할당을 전혀 수행하지 않으며, 이는
  `es_core::alloc_count::assert_no_alloc`으로 확인한다(이 크레이트의 `[dev-dependencies]`가
  `es-core`의 `alloc-count` 기능을 켜서 카운팅 할당자가 이 크레이트의 테스트 바이너리에
  실제로 설치되도록 한다. 이 조건이 더 이상 성립하지 않게 되더라도, 테스트는 관측할 수
  없는 환경에서 실패하는 대신 공허하게(vacuously) 계속 통과한다).

## forbidden (금지)

`context` 밖의 모든 파일. 루트 `Cargo.toml`. 전송 계층(소켓, QUIC, TLS — spec 25.1,
`es-transport`, 레이어 11). 바이너리 코덱(`Codec` enum은 자리만 마련해 둘 뿐이다).
`crates/es-assets/**`(진행 중인 다른 패킷 소관). `HashMap`(결정성, spec 3.4 — 이
크레이트는 `BTreeMap`만 사용한다). 일곱 확장점(INV-17)을 넘어서는 새로운 단일 구현
트레이트. 커밋 수행.
