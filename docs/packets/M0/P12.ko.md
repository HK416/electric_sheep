# P12 — SIMD `f64xN` + 디스패치

Spec: §2.2 (`wide`/`multiversion`), §3.4 (결정적 실행 계약), §5.3
(`hardware_capability`).

## context (범위)

```
crates/es-math/src/simd.rs
crates/es-math/src/lib.rs
crates/es-math/Cargo.toml
docs/packets/M0/P12.md
```

## spec (사양)

- `pub type F64xN = wide::f64x4;`이며 `pub const LANES: usize = 4`다.
  호출자는 레인 수를 한 곳에만 쓴다.
- `&[f64]`에 대한 `dot(a, b) -> f64`와 `axpy(alpha, x, y)`.
- **계약은 처리량이 아니라 결정성이다.** `dot`은 `LANES`개의 독립적인 레인
  누산기를 유지하고, 전체 청크를 순서대로 처리하며, 나머지(tail)를 레인
  0부터 순서대로 더한 다음, 고정된 순서 `l0 + l1 + l2 + l3`로 레인들을
  환원한다. 테스트의 스칼라 참조 구현은 동일한 결합 순서를 따르므로 둘은
  비트 단위로 일치한다.
- `simd_level() -> SimdLevel`은 런타임 디스패치 헬퍼다: `Sse2`/`Avx`/`Avx2`/
  `Neon`/`Scalar`를 보고하는 `std::arch` 기능 감지 스텁이다. 이는 **보고
  전용**이다 — §5.3 실행 해시의 `hardware_capability`에 공급된다. 레벨별 함수
  복제는 없는데, `wide`의 add/mul은 축약 없는 순수 IEEE 연산이므로 AVX2
  복제본이 SSE2 것과 같은 비트를 만들어 결정성 계약이 신경 쓰는 어떤 것도
  얻지 못하기 때문이다. `multiversion`은 의도적으로 의존성에서 제외했다:
  아직 아무도 측정하지 않은 성능 이득을 위해 proc-macro와 `unsafe`
  전개(`#![forbid(unsafe_code)]`)를 추가하게 되기 때문이다. 벤치마크가 격차를
  보여주면 다시 검토한다.

## acceptance (수용 기준)

- proptest, 길이 0–512의 무작위 `f64` 슬라이스: `dot`은 모든 나머지 길이
  `n % LANES`를 포함해 스칼라 참조와 **비트 단위로**(`to_bits()` 동등성)
  일치한다.
- proptest: `axpy`는 스칼라 참조와 비트 단위로 일치한다.
- 빈 슬라이스의 `dot`은 `0.0`이다; 길이가 다르면 패닉한다.
- `simd_level()`은 값을 반환하며 CI 호스트에서 패닉하지 않는다.
- 크레이트 어디에도 `unsafe`가 없다(크레이트 루트에
  `#![forbid(unsafe_code)]`).

## forbidden (금지)

- `multiversion` 없음, `std::arch` 인트린식 없음, `#[target_feature]` 없음,
  `unsafe` 없음.
- `dot`/`axpy`에 FMA(`mul_add`) 없음 — 스칼라 참조와 비교한 결과를 바꾸고
  축약을 숨기게 된다(§3.4).
- rayon / 스레딩 없음: 스레드 간 환원은 이 패킷이 아니라 `BinnedAcc`(P11)의
  몫이다.
- `scalar.rs`, `approx/`, `conventions.rs`, `reduce.rs`는 건드리지 않는다.
