# P04 — `check-scope` (diff ↔ 패킷 범위)

Spec: §1.2 (작업 패킷: `context`/`spec`/`oracle`/`acceptance`/`forbidden`), §1.7 (실패
모드 표: "조용한 범위 확장" → `xtask check-scope`가 diff를 패킷 범위와 대조).

## context

```
xtask/src/scope.rs
xtask/src/main.rs
docs/packets/M0/P04.md
```

## spec

`cargo xtask check-scope <packet.md>` reads one packet file, extracts the glob list under
its `## context` heading (either a fenced code block or a `-`/`*` bullet list, one glob per
line, inline backticks stripped), and checks that every file the working tree currently
differs on is covered by at least one glob:

- Changed files = `git diff --name-only HEAD` (staged + unstaged relative to `HEAD`) union
  untracked files from `git status --porcelain --untracked-files=all`.
- Glob syntax is the `.gitignore` subset actually used by packet files: `**` (any depth,
  including across `/`), `*` (any run of non-`/` characters), `?` (one non-`/` character),
  and literal characters otherwise. No brace or bracket classes — no packet needs them.
- Any changed file matching zero globs fails the check and is printed as `out of scope:
  <path>`.

`parse_context_globs` and `path_matches_any` (glob → regex) are pure and unit-tested
without touching git; `run()` is the thin `git`-shelling wrapper.

## oracle

```
cargo test -p xtask scope::
cargo xtask check-scope docs/packets/M0/P04.md
```

## acceptance

- Unit tests cover: fenced-block parsing, bullet-list parsing, `**` matching nested paths,
  a literal filename matching only itself, and a single `*` not crossing a `/`.
- Running `check-scope` against a packet whose `## context` covers the actual diff passes;
  against one that does not, it fails and names the offending path(s).

## forbidden

- No `glob` or `globset` crate — the four-token subset above is short enough to hand-roll
  against `regex` (already a dependency for P02/spec-refs).
- Do not special-case `.gitignore`-style negation (`!pattern`) — no packet in this repo
  needs it.
- No edits under `crates/**`.
