# P10 — convention types + serde round-trip harness

Spec: §3.1 (좌표계·단위 규약).

## context

```
crates/es-math/src/conventions.rs
crates/es-math/src/lib.rs
docs/packets/M0/P10.md
```

## spec

The §3.1 table, as types, so a convention violation is a compile or test error rather than a
silent frame mismatch:

| §3.1 row | type |
|---|---|
| right-handed, Z-up, X-forward | `axis::UP`, `axis::FORWARD`, `axis::LEFT` on `Vec3` |
| m / rad / kg / s | `units` module: SI is the storage unit, `DEG_TO_RAD` / `RAD_TO_DEG` are the only conversions, applied at I/O boundaries |
| quaternion xyzw, unit norm, w ≥ 0 | `Quat { x, y, z, w }`, `normalize` canonicalises to w ≥ 0 |
| inertia: body-frame symmetric 3×3, principal-axis decomposition cache | `Inertia` — six unique components plus the cached principal moments and principal-axis rotation |
| — | `Pose { position, orientation }` |

- `f64` storage. `Scalar`-generic only where it is free; it is not free here (serde bounds,
  monomorphised constants), so these are concrete. Physics backends pick their own scalar at
  the kernel boundary.
- `serde` `Serialize`/`Deserialize` on all of them, field-named, stable.
- This is *not* a linear algebra library: `Vec3` gets add/sub/neg/scale/dot/cross/norm/
  normalize, `Quat` gets `Mul`/conjugate/rotate/normalize, and nothing else until a caller
  needs it.
- The principal-axis cache is computed once in `Inertia::new` by a fixed-sweep cyclic Jacobi
  rotation (deterministic: no convergence-dependent loop count) and stored.

## oracle

```
cargo test -p es-math conventions::
```

## acceptance

- proptest: `Quat::normalize` always yields `w ≥ 0` and `|q| == 1` within `8·f64::EPSILON`,
  and is a fixed point to within 2 ULP per component. It is **not** bitwise idempotent —
  `norm()` of an already-normalised quaternion is only 1.0 to a rounding, so a second
  division moves the last bit. Anything that hashes a rotation normalises once and hashes
  that. (`proptest-regressions/conventions.txt` keeps the seed that found this.)
- proptest: `q` and `-q` normalize to the same quaternion (canonicalisation is the point).
- serde round-trip through JSON for `Vec3`, `Quat`, `Pose`, `Inertia`, bitwise equal.
- `Inertia`: reconstructing `R · diag(principal) · Rᵀ` returns the original components within
  `1e-9`; principal moments are sorted descending.
- Axis constants match §3.1 (`UP == +Z`, `FORWARD == +X`, right-handed:
  `FORWARD × LEFT == UP`).

## forbidden

- No matrix type, no `Mat3`/`Mat4`, no transform hierarchy, no camera/image types
  (`ImageSpec` is §7, `es-ir`).
- No Euler angle conversions (they need a convention argument nobody has specified yet).
- No `from_axis_angle` or any other constructor needing `sin`/`cos`: `es_math::approx` is
  `f32`-only and a host `f64::sin` at layer 0 is platform-dependent (§3.4). Add it when a
  caller exists, with an explicit precision contract.
- `serde_json` must carry the `float_roundtrip` feature, or the round trip is not bit-exact
  (its default float parser can land 1 ULP off).
- No `nalgebra`, `glam`, or any other linear algebra dependency.
- Do not touch `scalar.rs`, `approx/`, `reduce.rs`, `simd.rs`.
