# P34 — URDF importer + `package://` resolution

Spec: spec 3.1 (Z-up SI convention, quaternions xyzw `w >= 0` — URDF already matches, no axis
conversion), spec 17.2 (backend semantic mapping — a `<transmission>` is a declared actuator,
not a transduction model), spec 18.2 (actuators), spec 5.3 (`asset_hash -> scene_hash`).
Spec 28.2 Wave 4, `P34 URDF + package://`. Review class A. Builds on P30 (`SceneDesc`) and
follows the id / attribute-parsing scheme P32/P33 set for MJCF.

## spec

- `pub fn parse_urdf(xml: &str, resolver: &PackageResolver) -> Result<Import, UrdfError>`,
  same `Import { scene, warnings }` shape as `mjcf::parse_str`.
- `<link>`: `<inertial>` (`mass`, `origin xyz/rpy`, `ixx..izz`) to `BodyInertial`; each
  `<visual>` / `<collision>` `<geometry>` (`box size`, `cylinder radius/length`, `sphere
  radius`, `mesh filename/scale`) with `<origin xyz rpy>` becomes a `Geom`, `visual_only`
  distinguishing the two.
- `<joint type="...">`: `fixed` -> `JointKind::Fixed`, `floating` -> `Free`, `revolute` /
  `continuous` -> `Hinge` (`continuous` never carries a range), `prismatic` -> `Slide`,
  `planar` -> `UrdfError::Unsupported`. `<origin>` becomes the child body's pose relative to
  its parent; `<axis>` and the joint anchor are in the child body frame (URDF's joint frame
  *is* the child link's origin, so `anchor = 0`). `<limit lower/upper>` -> `range`; `effort`
  feeds a referencing `<transmission>`'s `force_range`, `velocity` has no home in `SceneDesc`
  and is a warning. `<dynamics damping/friction>` -> `damping` / `friction_loss`. `<mimic>` is
  a warning (unsupported), not an error.
- `<transmission>` -> one `Actuator` (`ActuatorKind::Motor`, `gear[0] =
  mechanicalReduction`, default 1.0) per `<actuator>` child, targeting the named joint. A
  transmission referencing an unknown joint is `UrdfError::UnknownJoint`.
- RPY to quaternion: fixed-axis (extrinsic) X, then Y, then Z — `q = qz * qy * qx` — normalised
  to `w >= 0` (spec 3.1). No axis remapping: URDF is already right-handed Z-up SI.
- Kinematic tree: every link is a `Body`; the link that is no joint's `<child>` is the root
  (`parent == None`). Zero or more than one such link is `UrdfError::NoRoot` /
  `MultipleRoots`, not a guess. A link claimed as `<child>` by two joints is
  `MultipleParents`.
- `<gazebo>`, `<material>` (robot-level) and any other unrecognised element become a
  `Warning`, never a parse failure.
- `PackageResolver { pub roots: BTreeMap<String, PathBuf> }`: `resolve("package://pkg/x") ->
  Result<PathBuf, UrdfError>` joins `pkg`'s root with the rest of the path, or
  `UnknownPackage { package, known }` listing every root it does have. `file://` and plain
  paths pass through unchanged. `PackageResolver::from_env()` reads `ROS_PACKAGE_PATH`
  (`;`-separated on Windows, `:` elsewhere), recursing into each directory for a
  `package.xml` and reading its `<name>` — a directory that is itself a package is not
  searched further. A referenced mesh's `AssetRef.hash` is `blake3` of the *resolved path
  string*: P31 (or a later packet) replaces it with the content hash once a file is actually
  read. A non-unit `<mesh scale>` is a warning: `Shape::Mesh` carries no scale field yet.

## acceptance

- `arm2.urdf`: 3 bodies, `base_link` is the root (`parent == None`), masses/limits/rpy match
  the fixture's literal values, `shoulder`'s range is exactly `[-pi/2, pi/2]`.
- `mixed_joints.urdf`: `fixed` / `continuous` / `prismatic` all map to the right `JointKind`
  (`continuous` has `range == None` even though the fixture omits limits), the transmission's
  actuator carries `gear[0] == 50` and `force_range == Some((-10, 10))` from the joint's
  `effort`, the `package://robo_pkg/...` mesh resolves to one deduplicated `AssetRef`, and
  `<gazebo>` shows up in `warnings` rather than failing the parse.
- `two_roots.urdf` fails with `UrdfError::MultipleRoots`; `malformed.urdf` fails with
  `UrdfError::Xml`, neither panics.
- Reordering `<link>` / `<joint>` elements in a document does not change `scene_hash()`
  (ids are name-derived, not order-derived — spec 5.3).
- `PackageResolver::resolve` and `::from_env` are unit-tested against temp directories:
  resolution success, an unknown package listing its known roots, `from_env` reading
  `ROS_PACKAGE_PATH` and finding a `package.xml`'s `<name>`.

## forbidden

Any file outside `context`. `crates/es-physics-*/**`, `src/gltf.rs`, `tests/gltf_*.rs`,
`tests/fixtures/gltf/**` (owned by concurrent packets). Opening or hashing mesh file
*contents* (P31 owns content hashing). `xacro` expansion (spec 4.1 keeps that a Python
preprocessing step, not this importer's job). Adding a trait (`INV-17`). `HashMap` /
`HashSet` (spec 3.4) — `BTreeMap` only.
