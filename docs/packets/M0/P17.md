# P17 — Pools + bump arena + allocation-zero assertion

Spec: §3.4 (deterministic, allocation-free hot loops), §28.2 Wave 2. Review class B.

## context

```
crates/es-core/src/pool.rs
crates/es-core/src/arena.rs
crates/es-core/src/alloc_count.rs
crates/es-core/src/lib.rs
docs/packets/M0/P17.md
```

## spec

- `Pool<T>` — dense `Vec` slots with a free list and generational `Handle<T>`;
  `insert / get / get_mut / remove / contains / len`. A stale handle never resolves.
  `Handle<T>` is `Copy + Ord` regardless of `T`.
- `BumpArena` — capacity fixed at construction (pointers stay stable, no hidden growth
  allocation), 16-byte aligned backing store, `alloc<T: Copy>` / `alloc_slice<T: Copy>` through
  `&self`, and `reset(&mut self)` — `&mut self` is what makes reset sound, since every
  handed-out reference is dead by then.
- `AllocCounter<A>` — a `GlobalAlloc` wrapper counting allocations per thread, installed as
  `#[global_allocator]` under `cfg(test)` or feature `alloc-count`.
- `assert_no_alloc(f)` — panics if the global allocator was hit inside `f`; a no-op when the
  counter is not installed.

## oracle

```
cargo test -p es-core --lib -- pool:: arena:: alloc_count::
```

## acceptance

- `assert_no_alloc(|| arena.alloc(...))` passes; `assert_no_alloc(|| Vec::<u8>::with_capacity(1))`
  panics (`#[should_panic]`).
- Pool: a stale handle after `remove` gives `None`; slot reuse bumps the generation.
- Arena: `used()` accounts for alignment padding, an over-capacity allocation panics, and
  `reset()` returns `used()` to 0 and reuses the same memory.

## forbidden

Any file outside `context`. Growing the arena. `unsafe` outside `arena.rs` / `alloc_count.rs`
without a `// SAFETY:` comment. A general-purpose allocator abstraction trait (INV-17).
