# P02 — layering check (§4.2 rule 9종)

Spec: §4.2 (크레이트 레이어링), Appendix B.8 (LAYERS 테이블 + 레이어링 검사).

## context

```
xtask/src/layering.rs
xtask/src/main.rs
docs/packets/M0/P02.md
```

## spec

`cargo xtask layering` runs `cargo metadata --no-deps --format-version 1` from the
workspace root, and for every workspace package checks its *direct* declared dependency
names (which is enough: rule 1 only needs to hold edge-by-edge for transitivity to hold
package-wide) against the Appendix B.8 `LAYERS` table and the numbered rules in §4.2:

1. A crate depends only on strictly lower layers; no same-layer dependency.
2. `es-physics-cpu` and `es-physics-gpu` never depend on each other.
3. Layers ≤ 2, except `es-gpu`, must not depend on `ash` or `gpu-allocator`.
4. Nothing depends on `es-editor`.
5. Only `es-transport` may depend on `cust`, `cudarc`, or any crate named `hip*`.
6. `es-ir` must not depend on `es-compile`, any `es-physics-*`, `tch`, `torch*`, or `ort`.
7. `es-ir` must not depend on `egui*` or `winit`.
8. `es-safety` must not depend on `es-policy` (INV-11).

An `es-*` workspace crate not present in the `LAYERS` table is itself an error (the table
must be kept in sync with the crate list); a crate the table lists but that does not exist
yet in `crates/` is not an error — Wave 0 predates most of the tree.

The rule evaluation (`check_layering`) is a pure function over `&[Pkg]` (`Pkg { name,
deps }`); `cargo metadata` parsing is a thin, separately-testable-by-inspection shim around
it so the rule logic itself never has to shell out in tests.

## oracle

```
cargo test -p xtask layering::
cargo xtask layering
```

## acceptance

- Unit tests feed a fake `&[Pkg]` dependency graph and assert each of the 8 rules both
  fires on a violating fixture and stays quiet on a compliant one.
- `cargo xtask layering` against the live workspace exits 0 with the current `crates/*`.
- An unknown `es-*` crate name (not in `LAYERS`) is reported as an error, not silently
  skipped.

## forbidden

- No dependency on the `cargo_metadata` crate — the fields this check needs
  (`packages[].name`, `packages[].dependencies[].name`) are read directly off `cargo
  metadata`'s JSON with `serde_json`.
- Do not fail the build on missing crates; only on present-but-misplaced or present-but-
  unlisted ones.
- No edits under `crates/**`.
