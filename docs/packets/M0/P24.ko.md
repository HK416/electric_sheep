# P24 — Evaluation IR 스키마

Spec: spec 10 (전체), spec 12.4(9개 지표 집합), spec 5.1(IR 경계), `INV-15`.
리뷰 클래스 B.

## context (범위)

```
crates/es-ir/src/evaluation.rs
docs/packets/M0/P24.md
```

`crates/es-ir/src/lib.rs`는 이미 `pub mod evaluation;`을 선언하므로, 이 패킷은 그
파일을 건드리지 않는다.

## spec (사양)

- `EvaluationIr { schema_version, task, observation, episodes, suites, metrics, acceptance,
  augmentation, replay }` — spec 10.2 문서 그대로.
- `PerturbationSuite { name, perturbations }`와 `Perturbation { kind, stream }`, 그리고
  spec 10.2의 모든 kind를 타입이 지정된 파라미터로 포괄하는 `PerturbationKind`. `stream`은
  `TaskRng(seed_base, suite_id, episode_idx, stream)`(spec 10.4)의 `stream` 좌표이므로,
  셀의 perturbation 시퀀스는 정책에 의존할 수 없다.
- `MetricSpec` — spec 10.3 지표들(Safety Plane 카운터인 `envelope_violation_rate`와
  `chunk_underrun_rate` 포함)과 `MetricSpec::PERFORMANCE_SET`으로 노출되는 spec 12.4
  성능 집합. 단일 `step/s` 변형은 존재하지 않는다.
- `AcceptanceCriterion { suite, metric, comparator, threshold, aggregation }`; `suite: None`은
  spec의 단순 `envelope_violation_rate: "<= 0.01"` 형식에 해당한다.
- `EpisodeBatch { n_episodes, seeds: SeedPlan::{Base, Explicit} }` — spec 5.1의 episode
  배치 도메인이며, spec 10.4에 따라 결정적이다.
- `AugmentationPolicy`(INV-15): `Disabled`(`Default`) 또는 `AllowList { nodes,
  justification }`. `Enabled` 캐치올은 존재하지 않는다.
- `codes.rs`에 `EVAL-` 블록이 추가되기 전까지 `// TODO(P27-merge)`로 로컬 선언된
  `EVAL-001 .. EVAL-006`을 사용하는 `EvaluationIr::validate(&self) -> Vec<Diagnostic>`.
- `CanonWriter`를 통한 `EvaluationIr::evaluation_hash(&self) -> Result<[u8; 32], Diagnostic>`.
- `EvaluationReport` / `CellResult` / `MetricValue` / `AcceptanceResult` — spec 10.5의
  `report.json`과 `evaluation.lock` 스키마. 타입만 정의한다.

## oracle (오라클)

```
cargo test -p es-ir evaluation
```

## acceptance (수용 기준)

- spec 10.2 fixture는 깨끗하게 검증되고 serde를 통해 변경 없이 라운드트립된다.
- 선언되지 않은 지표나 suite를 지정한 acceptance criterion은 `EVAL-001`을 낸다; 중복된
  episode seed나 반복된 perturbation stream은 `EVAL-004`를 낸다; `n_episodes == 0`이거나
  seed 목록 길이 불일치는 `EVAL-003`을 낸다; 역방향 range는 `EVAL-005`를 낸다; 비유한
  threshold나 파라미터는 `EVAL-002`를 낸다; 근거 없는 allow-list는 `EVAL-006`을 낸다.
- threshold, comparator, aggregation, suite 범위, perturbation 파라미터, stream, 지표
  목록, episode 수, seed base, augmentation policy, replay policy, schema version 중
  어느 조건을 바꾸어도 `evaluation_hash`가 변한다.
- `arbitrary_evaluation_ir()`(proptest, `#[cfg(test)]`)는 항상 깨끗하게 검증되고
  해시된다.

## forbidden (금지)

`context` 밖의 모든 파일. `lib.rs`, `codes.rs`, `graph.rs`, `types.rs`, `hash.rs`,
`Cargo.toml` 수정(P18/P19/P27 소관이며, 나머지 네 개 IR은 다른 네 패킷이 작성 중이다).
suite 실행, perturbation 샘플링, 지표 계산(그것은 레이어 10의 `es-eval` 몫이다).
`AugmentationPolicy::Enabled` 변형이나 augmentation을 통째로 다시 켜는 그 밖의 방법
(INV-15). 단일 `step/s` 지표(spec 12.4). `HashMap`(spec 3.4).
