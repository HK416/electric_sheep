# P16 — Failure semantics types

Spec: §18.5 (`EnvHealth = Ok | Diverged | Poisoned | Quarantined`, a quarantined env is
excluded from reduction, the quarantine-rate threshold is 5%, and a Safety Plane fallback is
*not* a failure), §28.2 Wave 2. Review class A.

## context

```
crates/es-core/src/failure.rs
crates/es-core/src/lib.rs
docs/packets/M0/P16.md
```

## spec

- `EnvHealth` — `Ok | Diverged | Poisoned | Quarantined`; `participates_in_reduction()` is
  false only for `Quarantined` (§18.5: masking a quarantined env must not break determinism).
- `FailureKind` — `NanDetected`, `Diverged`, `DeadlineMiss`, `SensorDrop`, `ActuatorFault`,
  `ChunkUnderrun`, `SafetyViolation`, `BackendUnsupported`.
- `FailureAction` — `Record | Fallback | Quarantine | AbortEpisode | AbortRun`.
- `FailureKind::default_action()` — total, exactly one action per kind.
- `FailurePolicy` — `BTreeMap` overrides plus `quarantine_rate_limit` (default 0.05);
  `action_for(kind)` resolves the override first, then the default.
- `Error` (`thiserror`) — the crate error type: `InvalidTickRate`, `InvalidStableId`,
  `Failure { kind, detail }`.

A Safety Plane fallback leaves the env `Ok` and records the event (§18.5), so the default
action for `SafetyViolation` is `Fallback`, never `Quarantine`.

## oracle

```
cargo test -p es-core --lib failure::
```

## acceptance

- serde round trip for every `FailureKind`, `FailureAction`, `EnvHealth`, and `FailurePolicy`.
- `FailureKind::ALL` is exhaustive (a `match` in `default_action` checks it at compile time)
  and every kind maps to exactly one default action.
- `FailurePolicy::default().action_for(k) == k.default_action()` for all kinds; an override
  wins.

## forbidden

Any file outside `context`. Anything that would let a failure disable the Safety Plane
(INV-12) — `FailureAction` has no `Disable` / `Bypass` variant and never will.
