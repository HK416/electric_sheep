# P06 — CI 계층 구성

Spec: §26.2 (CI 계층 — PR 단계 < 10분), §1.6 (`xtask/`가 모든 검증의 단일 진입점).

## context

```
.github/workflows/ci.yml
.gitattributes
xtask/src/main.rs
docs/packets/M0/P06.md
```

## spec

CI has one entry point: `cargo xtask ci`. The GitHub Actions workflow does nothing but set
up the toolchain and call it, so "what CI checks" lives in one place (`xtask`), not
duplicated into YAML.

- `cmd_ci` in `xtask/src/main.rs` runs, in order, short-circuiting on the first failure:
  `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test
  --workspace`, then the three in-process checks from P01-P03
  (`context-budget`, `layering`, `check-spec-refs`, `verify-goldens`) — this is exactly the
  §26.2 PR-tier item list (단위, 레이어링, clippy, fmt; the IR/determinism-specific items
  in that row land once the crates they check exist).
- `.github/workflows/ci.yml`: `ubuntu-latest`, stable Rust (`dtolnay/rust-toolchain`) with
  `rustfmt`+`clippy` components, `Swatinem/rust-cache@v2` for the target-dir cache, full
  git history (`fetch-depth: 0`, required for `verify-goldens`'s merge-base diff), one
  step: `cargo xtask ci`. Budget is the §26.2 PR row's "< 10 minutes"; caching is what
  keeps a from-scratch Rust build under that on `ubuntu-latest`.
- `.gitattributes` (`* text=auto eol=lf`): normalizes line endings repo-wide so `git diff`
  in `verify-goldens`/`check-scope` and the `pre-commit`/`commit-msg` hooks see the same
  bytes on Windows and Linux checkouts.

## oracle

```
cargo xtask ci
```

(Runs the exact sequence CI runs; a clean local run is the oracle for "CI will pass".)

## acceptance

- `cargo xtask ci` executes all seven steps in order and stops at the first failure
  (non-zero exit propagates immediately; later steps do not run).
- `.github/workflows/ci.yml` triggers on push-to-main and on pull requests, and its only
  logic step is `cargo xtask ci`.
- A fresh clone with `.gitattributes` in place checks out `xtask/**`, `docs/**`, and
  `crates/**` with `LF` endings on any platform.

## forbidden

- No duplicate check logic in the workflow YAML — if a check needs a new step, it goes
  into `cmd_ci`, not a new `run:` line.
- No merge-tier/nightly/weekly/release CI here (§26.2's other four tiers) — Wave 0 ships
  the PR tier only.
- No edits under `crates/**`.
