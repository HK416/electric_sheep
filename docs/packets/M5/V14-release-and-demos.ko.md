# M5 V14 — 놓기, 그리고 시연 4배

설계 노트: `docs/design/visible-learning.ko.md` **7.22절**, 그리고 7.19(V11, 제어 주기),
7.20(V12, 짝맞춤 수정과 시연 50개 집합), 7.21(V13, GroupNorm 백본이자 이 패킷이 비교되는 기준),
5.4(성공 술어가 왜 x 전용인가). 스펙: §6.2(`max_episode_steps`), §9.3(위치 클램프), §10.4, §1.4.
의존: V11, V12, V13.

## 두 질문

V13의 정책 — 상태에 큐브 포즈를 담은 IR 소유 그래프, V12의 시연 50개로 20,000 스텝 학습 — 은
**큐브를 쥐고 118 ~ 124 mm 들어 올려 학습 시드 16개 중 3개에서 통까지 옮기고, 900스텝 예산이 끝날
때까지 거기서 들고 있는다**. 홀드아웃은 0 / 16. 실패 히스토그램은 `violation.position`이 지배하고,
개루프 잔차가 가장 큰 관절은 그리퍼다.

여기서 두 가지가 따라오며 이 패킷은 각각 하나씩이다.

1. **시간을 주면 정책은 놓는가?** 900스텝 예산이 답을 가리고 있었다. 옮긴 세 에피소드는 예산이
   끝나는 순간에도 여전히 큐브를 올바른 위치에 들고 있었다. 1부는 예산을 1,800 제어 스텝(36 s)으로
   올리고 V13의 가중치를 그대로 다시 돌린다.
2. **변수 하나: 시연 50개 → 200개.** 다른 것은 움직이지 않는다. V13의 중단 규칙이 다음 단일 변수로
   해상도 또는 시연 개수를 지목했고, 이것이 그 둘 중 두 번째다.

## 1부 — 예산, V13 자신의 가중치 위에서

`max_episode_steps`는 손으로 적는 값이 아니다. `tests/fixtures/visible-learning/task.toml`은
`regenerate_visible_learning_documents`가 생성하므로, 바뀌는 것은 생성기의 상수
(`(max_steps, timeout_s)` 900/18.0 → **1800/36.0** — Task IR의 `Timeout` 리프가 경과 초를
비교하므로 둘이 함께 움직인다)이고 그 다음이 재생성이다.

Task IR 하위의 모든 해시가 움직이고 **가중치는 움직이지 않는다**: V13의 `model-20000.safetensors`를
`es policy pack`으로 재생성된 문서 기반 번들에 다시 담는다. 비교가 무엇인지에 대한 정직한 진술이
그것이다 — 같은 함수, 다른 에피소드 예산.

## 2부 — 시연 200개

V12의 수집 명령 그대로, 50 Hz, `PACE = 0.5` 전문가, `--episodes 200 --seed 1`(50을 넘는 시드는 같은
`Randomization` 스트림의 새 추출이지 반복이 아니다). 그다음 베이크, 그다음 V2의 손잡이로 V13 그래프:
`--batch 8 --lr 1e-4 --seed 0 --device cuda --resident-gpu`, 20,000 스텝, 그리고 20,000에서도 손실이
떨어지고 있으면 40,000까지.

평가는 학습 시드 1–16과 홀드아웃 101–116, **900스텝 예산**에서 한다. 1부의 답이 "1,800에서도 어떤
에피소드도 놓지 않는다"이므로 1,800은 아무것도 사지 못하고, 900이 V13의 표가 서 있는 예산이다.

## 오라클

1. **픽스처는 생성이지 타이핑이 아니다.** `cargo test -p es --test cli -- --ignored
   regenerate_visible_learning_documents`가 씬과 상수로부터 모든 문서를 바이트 단위로 재현하고,
   그 결과 위에서 `cargo xtask ci`(골든, spec-refs, 레이어링, 컨텍스트 예산)가 통과한다.
2. **가중치는 움직이지 않았다.** 재생성된 번들에 대한 `es policy pack`이 V13과 같은 텐서 86개,
   같은 `weights_hash`와 `lowering_hash`를 찍고 `task_hash` / `observation_hash` / `policy_hash`는
   다르게 찍는다.
3. **놓기를 에피소드마다 측정.** 평가된 모든 에피소드의 `.estraj` 기록을 3차원 통 부피
   `cube_in_the_bin`(`crates/es/tests/cli.rs`)과 그리퍼 자신의 열림 임계값(0.6 rad, Task IR의 값)에
   대해 읽어 들어 올림 / 운반 / 놓음과 각각의 틱을, 하네스의 판정과 나란히 놓는다.
4. **관절별 `violation.position`.** `events.json`은 프레임당 `ViolationKind` 비트셋만 담고 관절
   인덱스는 담지 않으므로, `.estraj`의 위치를 Deployment IR의 소프트 경계
   (`[lower + margin, upper - margin]`, `SafetyPlane::clamp` 2단계가 명령을 자르는 바로 그 구간)에
   대해 재생해서 분해한다.
5. **결정론.** 최종 체크포인트에서 홀드아웃 스위트를 두 번 돌리고, 두 보고서는 마지막 자리까지
   일치해야 한다.
6. **중단 규칙.** 변수 하나. 홀드아웃 `success_rate ≥ 0.5`(불변)이면 6-스위트 스윕과 쇼케이스 영상
   둘을 연다. 그 아래면 패킷은 멈추고, 다음 패킷을 고를 수 있도록 에피소드별 운반/놓기 표를 보고한다.

### 2 — 1부: 정책은 놓지 않고, 18초를 더 줘도 달라지지 않는다

`es eval run --frames`, nominal 스위트, 16 에피소드, 예산 1,800.

| | 학습 시드 1–16 | 홀드아웃 101–116 |
|---|---|---|
| `success_rate`(하네스) | 1 / 16 | **0 / 16** |
| 큐브가 테이블에서 떨어짐 | 3 / 16 | 3 / 16 |
| **큐브를 통 내부 부피까지 옮김** | **3 / 16**(03 @ 917, 11 @ 147, 15 @ 172) | **2 / 16**(01 @ 143, 04 @ 142) |
| **통 안에서 큐브를 놓음** | **0 / 16** | **0 / 16** |
| 1800틱 시점에 큐브가 여전히 통 안 | 3 / 16 | 2 / 16 |
| `envelope_violation_rate` | 0.4227 | 0.5457 |
| `episode_length` | 1691.5 | 1800.0 |

옮긴 에피소드는 모두 남은 구간 전체 — 883 ~ 1,653 제어 스텝, 17.7 ~ 33.1 s — 동안 큐브를 통
내부에 든 채 유지하며 그리퍼는 0.078 ~ 0.093 rad, 즉 30 mm 큐브를 문 채 멈춘 턱이다. **단 한
에피소드도 손을 열지 않는다.** 추가된 900스텝은 어느 스위트의 판정도 바꾸지 않았고, 유지가
무한하다는 것만 증명했다.

유일한 `success`는 V13이 보고한 그 에피소드다: 학습 시드 3(`nominal-02`), 64틱, 1.8 mm 들어 올림.
운반이 아니다.

### 3 — 1부: `violation.position`은 그리퍼이고 오직 그리퍼다

`.estraj`의 위치를 Deployment IR의 소프트 경계에 대해 재생한 관절별 결과:

| 관절 | 학습 시드, 소프트 경계 밖 틱 | 홀드아웃 |
|---|---|---|
| `shoulder_pan` / `shoulder_lift` / `elbow_flex` / `wrist_roll` | 0 | 0 |
| `wrist_flex` | 23 (0.1%) | 18 (0.1%) |
| **`gripper`** | **27,064 중 10,145 (37.5%)** | **28,800 중 14,690 (51.0%)** |
| 하네스 `violation.position` | 9,265 | 13,380 |

그리퍼의 소프트 구간은 `[-0.1245, 1.6953]` rad이고 고정된 틱들은 **하한**에서 1 mrad 이내에 있다.
정책은 에피소드의 절반 동안 봉투가 허용하는 것보다 세게 턱을 닫으라고 명령하고 안전 평면이 거기서
자른다 — "절대 열지 않는다"를 반대편에서 본 것과 같은 사실이다.

| | V12 / V13 (50) | **V14 (200)** |
|---|---|---|
| 시연, `es loop collect --episodes N --seed 1` | 50 / 50 `Success` | **200 / 200 `Success`** |
| 프레임 | 9,038 | **35,918** |
| 수집 / 베이크 벽시계 | 50 s / 1 s | **208 s / 8 s** |

20,000에서도 손실이 떨어지고 있으므로 40,000이 최종 체크포인트이고 둘 다 패킹했다.

### 5 — 2부: 성공 표, V13과 나란히

예산 900, nominal 스위트, `es eval run --frames`.

| | V13, 50개, 20k | **V14, 200개, 40k** |
|---|---|---|
| `success_rate`, 학습 시드 1–16 | 1 / 16 | **1 / 16** |
| `success_rate`, 홀드아웃 101–116 | 0 / 16 | **0 / 16**(두 번, 동일) |
| **통까지 운반, 학습** | **3 / 16** | **8 / 16** |
| **통까지 운반, 홀드아웃** | **0 / 16** | **9 / 16** |
| **통 안에서 놓음** | 0 / 16 | **0 / 16** |
| `envelope_violation_rate`, 학습 / 홀드아웃 | 0.5396 / 0.6392 | **0.1587 / 0.2060** |
| `violation.position`, 학습 / 홀드아웃 | 5,655 / 7,542 | **657 / 1,357** |
| `episode_length`, 학습 / 홀드아웃 | 847.75 / 900 | 855.125 / 900 |

40,000 체크포인트의 홀드아웃 두 번은 마지막 자리까지 일치하므로, 이 숫자는 스케줄이 아니라 정책의
것이다.

홀드아웃 `success_rate`가 0이고 수용 임계값 0.5 아래이므로 **중단 규칙이 발동한다**: 6-스위트 스윕
없음, 쇼케이스 영상 없음, 이 패킷에서 두 번째 변수 없음.

### 판정

시연 4배는 플랜 V가 측정한 단일 변수 이동 중 가장 크다. 홀드아웃 운반이 **0 / 16에서 9 / 16으로**
올라가고 봉투 위반율은 3분의 1로 떨어진다. `violation.position`은 7,542 프레임에서 1,357로 떨어진다.
정책은 이제 한 번도 본 적 없는 시드의 절반 이상에서 큐브를 찾고, 쥐고, 약 125 mm 들어 올려 통 위에
올린다.

그리고 하네스는 여전히 **0 / 16**이다. 과제에 마지막으로 필요한 한 가지가 정책이 한 번도 해 본 적
없는 그 한 가지 — **손을 여는 것** — 이기 때문이다. 두 부에서 평가한 96 에피소드 동안, 900스텝에서도
1,800스텝에서도 놓음은 0이다. 실패는 도달도, 파지도, 일반화도, 예산도 아니다. 에피소드 내내 닫으라고
명령되고 안전 평면이 거기서 자르는 관절 하나다.
