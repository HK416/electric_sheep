# P-M4-S9-S10 — refuse before writing, and reject a bad `control_rate_hz`

Closes review should-fixes **S-9** and **S-10** (`docs/reviews/M4.md`).

## spec

- §14.4 (external conversion) — an unmapped item with `severity: error` *blocks execution*.
  A refusal that has already written `task.toml`, `observation.toml` and `provenance.json`
  leaves a directory indistinguishable from a successful import except by exit code, which
  the next command in a pipeline does not see.
- §6.3 / §5.3 — `control_rate_hz` divides the episode length into the `Terminate(Timeout)`
  threshold and lands in `TaskConfig`, so it reaches `task_hash`. A `0.0` puts `+inf` there;
  a `NaN` is refused only much later, by `CanonWriter`, as an opaque IR error.

Pass/fail content:

- `cargo test -p es --test cli import_roboverse` —
  `import_roboverse_writes_nothing_when_an_unmapped_item_blocks_it`: the `unknown_checker`
  fixture exits 1 and the `--out` directory does not exist afterwards (the same assertion
  `import_usd_refuses_a_referenced_layer_by_prim_path` already makes for `import usd`).
  `import_roboverse_exits_1_on_an_unmapped_checker` still passes: the unmapped items are
  printed before the refusal.
- `cargo test -p es-data --test roboverse control_rate` —
  `a_nonpositive_or_nonfinite_control_rate_is_a_convert_error`: `0.0` and `-30.0` through the
  JSON path, `NaN` and `+inf` through the in-memory struct (`serde_json` refuses a
  non-finite literal itself), each a `ConvertError`; `30.0` and a missing value still convert.

## acceptance

- `roboverse_import` computes the `blocked` predicate immediately after printing the unmapped
  items and returns 1 before `create_dir_all`; on success it returns 0. The help text states
  that nothing is written on a refusal.
- `ConvertError::ControlRate(f32)` — `convert` refuses any `Some(hz)` that is not finite and
  greater than zero. `None` keeps the existing default-plus-warning behaviour.
- No new trait (INV-17), `BTreeMap` only, English-only.

## forbidden

- The conversion itself (checker mapping, camera mapping, randomization, provenance) and the
  unmapped/warning taxonomy — unchanged.
- `crates/es-eval`, `crates/es-env`, `crates/es-ir`, `crates/es-usd`, `crates/es-script`,
  `crates/es-gpu`, `crates/es-render`, `crates/es-core`, `python/` — other packets.
- `tests/fixtures/roboverse/` — the new cases are built in the test from `reach.json`, so no
  fixture is added or edited.
