# P-M4-R11 — the oracle tier runs every reference oracle a CPU runner can run

The `Reference oracle tier (spec 1.4, 28.7)` job fails on every push to `main` (run 34780514440
at `c0fd56b`, run 34797187557 at `d341599`). Its test step fails on any `^SKIP` line, and it
installs only `mujoco` and `torchvision`, so fifteen tests still skip:

- 9 GPU lowering tests in `crates/es-compile/tests/observation_gpu.rs` — `no slangc`; they also
  need a Vulkan device the runner does not have;
- 2 `newton_*` tests in `crates/es-physics-backend/src/newton.rs` — `newton` not installed;
- 3 diffusers oracles in `crates/es-policy/src/reference.rs` — `diffusers` not installed;
- 1 `a_real_lerobot_act_checkpoint_reproduces_its_actions` — `ES_ACT_CHECKPOINT` unset.

A job that is red on every push signals nothing. P-M1-R7 designed it to fail on any skip before
the newton (M2), diffusers and ACT (M4) oracles and the GPU lowering tests existed; none of them
was added to its install list.

Spec: §1.4 (reference oracles are mandatory; a skip is not a pass), §26.2 (the PR tier's
< 10 min budget — untouched, this job runs on push and dispatch only), §12.4 (what cannot run
here is `Target / Status: unverified`, not green). INV-16: safetensors only, no pickle.

## spec

- **Install what runs on a CPU.** `install reference oracles` adds `diffusers==0.40.0`
  (`docs/api-notes/torch.md`), `newton==1.6.0` and `warp-lang==1.17.0`
  (`docs/api-notes/newton.md`: the same wheel runs CPU-only through warp). `mujoco==3.13.0` and
  `torchvision==0.29.0` (with the `torch==2.14.0` it pulls) stay as they are.
- **LeRobot gets its own interpreter.** lerobot 0.6.1 resolves to torch 2.11.0, torchvision
  0.26.0 and numpy 2.2.6 (`docs/api-notes/lerobot-act.md`) and would downgrade the torch 2.14
  that generates the goldens. A new step creates `$RUNNER_TEMP/lerobot-venv` with
  `torch==2.11.0+cpu torchvision==0.26.0+cpu lerobot==0.6.1` and downloads the checkpoint with
  the api-note's snippet — pinned revision, `*.safetensors` / `*.json` only, pickle assertion —
  into `$RUNNER_TEMP`, outside `target/`, so `rust-cache` never stores 200 MB of weights.
- **The ACT oracle runs in its own step,** with `ES_PYTHON` and `ES_ACT_CHECKPOINT` pointed at
  that venv and checkpoint; the main step skips it by name. The step fails unless the log has a
  `RAN act_checkpoint` line, which a skip never prints.
- **GPU skips are recognised by their exact reason, not by keyword.** The main step still fails
  on every `SKIP` line except the two forms `observation_gpu.rs` prints when it cannot run:
  `SKIP <test>: no slangc (…)` and `SKIP <test>: no Vulkan device (…)`. `cargo xtask ci`'s
  broader keyword list (`gpu`, `vulkan`, `render`, `slangc`, `device`) is deliberately not
  reused here: a newton or torch skip carries a Python error text that may contain "device",
  and would then pass silently. The GPU tests run on a GPU host under
  `ES_REQUIRE_GPU=1 cargo xtask ci` (renderer-14, RTX 4090: all of them ran) and stay
  `Target / Status: unverified` on this runner.
- `mjwarp` stays excluded by name, as in P-M1-R7: it needs CUDA. The `ci` job does not change.

## oracle

The job only runs on GitHub. Before the push it is reproduced on renderer-14 as the runner sees
it: GPU hidden (`CUDA_VISIBLE_DEVICES=`, `VK_ICD_FILENAMES=/nonexistent`), no slangc on `PATH`,
no `ES_*` variables, and venvs built with `pip` from exactly the step's commands. The filter
itself is exercised on two synthetic logs. Then:

```
python -c "import yaml; print(list(yaml.safe_load(open('.github/workflows/ci.yml'))['jobs']))"
cargo xtask check-scope docs/packets/M4/P-M4-R11.md
gh run watch <run id of the push> --exit-status
```

## acceptance

- Reproduction, main step: exits 0; newton, diffusers, MuJoCo, torch and golden oracles all
  ran; the only skips are the nine `observation_gpu.rs` GPU tests.
- Reproduction, ACT step: exits 0 with `RAN act_checkpoint`.
- The filter exits 1 on a log with a `SKIP newton_pendulum: …` line next to the GPU lines, and 0
  on the GPU lines alone.
- On the push, both jobs of the `CI` workflow are green.
- `.github/workflows/ci.yml` parses and lists the jobs `ci` and `oracles`; the `ci` job's steps
  are byte-for-byte unchanged.

## forbidden

- The `ci` job (PR gate): steps, triggers, `timeout-minutes`.
- Installing `mujoco_warp`, adding a GPU or self-hosted runner, or calling the GPU oracles
  verified on this runner.
- Letting the main step ignore every skip, or dropping `continue-on-error: false`.
- `crates/**` — no test or message changes; the filter matches the messages as they are.
