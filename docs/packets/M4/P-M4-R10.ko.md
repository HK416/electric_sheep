# P-M4-R10 — Python 바이트코드와 Windows에서 빌드된 `es_native` 확장의 추적 중단

커밋 `ac74fa8`(P-M4-R8)은 선언된 범위 옆에 빌드 산출물 다섯 개를 추가했다:
`python/es/__pycache__/{__init__,builder,math,selfcheck}.cpython-312.pyc`와
`python/es/es_native.pyd`(3.1 MB, `crates/es-py`의 Windows x86_64 pyo3 빌드). 이들 중 어느 것도
P-M4-R8의 `context`에 없고, git에서 이들을 읽는 것도 없으며, 모두 머신별 산출물이다.
`es_native.pyd`는 §26.1의 1차 플랫폼인 Linux에서 로드되지 않는다 — Linux에서는
`maturin develop`이 대신 `es_native.abi3.so`를 쓴다. `es`를 import하는 인터프리터는 모두
`.pyc` 파일을 다시 쓰므로, 깨끗한 체크아웃도 Python 오라클을 돌리는 것만으로 dirty가 된다;
Linux 검증 호스트에서는 `cargo xtask check-scope`가 이들을 범위 밖으로 보고하는 것으로 드러났다.

Spec: 사양 §1.2(패킷의 diff는 context 안에 머문다), §2.4(Python은 런타임 경로 밖에 둔다;
확장은 플랫폼별 maturin 빌드다), §26.1(Linux x86_64가 1차 플랫폼).

## context (범위)

```
.gitignore
python/es/__pycache__/*.pyc
python/es/es_native.pyd
docs/packets/M4/P-M4-R10.md
docs/packets/M4/P-M4-R10.ko.md
```

## spec (사양)

- 다섯 파일은 `git rm --cached`로 인덱스에서 빠진다. 디스크의 작업 사본은 그대로 남으므로,
  기존 로컬 venv는 계속 자신의 `es_native`를 import한다.
- `.gitignore`에 Python 섹션이 추가된다: `__pycache__/`, `*.py[cod]`, `python/es/es_native*.pyd`,
  `python/es/es_native*.so` — 바이트코드 캐시와 `maturin develop --release --features python`의
  두 플랫폼 산출물(Windows `.pyd`, Linux `.abi3.so`). 네이티브 패턴은 트리의 모든 `*.so`/`*.pyd`가
  아니라 `es_native`로 한정된다.
- 저장소에서 이 파일들을 읽는 빌드나 테스트는 없다. `crates/es-py/tests/python_example.rs`는 이미
  maturin으로 `es`를 설치하도록 요구하고, `python/es/README.md`도 이미 그 단계를 문서화하므로
  둘 다 바뀌지 않는다.

## oracle (오라클)

```
git ls-files -- '*.pyc' '*.pyo' '*.pyd' '*.so' '**/__pycache__/**'
git check-ignore --no-index python/es/__pycache__/x.cpython-312.pyc python/es/es_native.pyd python/es/es_native.abi3.so
cargo xtask check-scope docs/packets/M4/P-M4-R10.md
cargo xtask ci
```

변경 전에는 첫 명령이 다섯 파일을 나열하고 두 번째 명령은 1로 종료한다.

## acceptance (수용 기준)

- 첫 명령은 아무것도 출력하지 않는다; 두 번째 명령은 세 경로를 모두 출력하고 0으로 종료한다.
- `check-scope`와 `cargo xtask ci`가 통과한다: 제거된 파일에 의존한 빌드나 테스트는 없었다.
- Linux 호스트에서 `maturin develop`과 `es`를 import하는 전체 `cargo test` 실행 후, 호스트 로컬
  ignore 규칙이나 `PYTHONPYCACHEPREFIX` 없이도 `git status --short`가 깨끗하다.

## forbidden (금지)

- 제거된 파일의 작업 사본을 지우거나, `crates/es-py/**` 또는 `python/es/*.py`를 바꾸는 것 —
  확장이나 빌더의 동작 변화 없음.
- 과거 커밋에서 `.pyd`를 없애기 위한 히스토리 재작성(`main`에 force-push); 그것은 `ac74fa8`의
  히스토리에 남는다.
- `.github/workflows/ci.yml` — P-M4-R11의 범위.
