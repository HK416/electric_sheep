# P-M4-S11 — `es_math::approx::tan`, 그리고 호스트 `libm`을 벗어난 골든 카메라 경로

## spec (사양)

S-11: `es-render/src/view.rs:26`는 `fy`를 `f64::from(height) * 0.5 / (fovy_rad * 0.5).tan()`으로
계산했다. 그 `tan`은 호스트 `libm`이며 아무것으로도 고정되어 있지 않고, `fx`/`fy`는 골든
카메라 경로 위에 있다 — `cornell.rs:99` → `ViewParams` → 모든 광선 방향 → 모든 골든 픽셀.
`scene.rs:269-271,295,317`은 구, 타원체, 캡슐, 실린더 정점에 `f64::sin`/`cos`를 썼는데, 이는
CPU 레퍼런스가 순회하는 *동시에* `Renderer::upload_tris`가 GPU로 업로드하는 것이므로, `libm`
차이가 있으면 다른 호스트에서 두 경로가 서로 어긋날 것이다. `es_math::approx`에는 `tan`이
없었다.

1. **`es_math::approx::tan(x: f32) -> f32`.** `reduce_quadrant`를 변경 없이 재사용한다 —
   `sin`/`cos`와 같은 Cody–Waite 축소이며, 미러와 동기화된 상태를 유지할 축소는 하나뿐이다.
   `tan`은 주기가 π이므로 `quadrant & 1`만 중요하다: 짝수는 커널을 그대로 반환하고, 홀수는
   `-1.0 / kernel`을 반환한다. 커널은 Cephes `tanf.c`의 `r²`에 대한 6항 minimax
   (`TAN_C0..TAN_C5`)이며, Horner 식 하나로 되어 있고 `mul_add`도 재결합도 없다.
   `sin(x) / cos(x)`가 **아니다**: 그 몫은 먼저 구현되고 측정되어 **3 ULP**(커널 오차 두
   개에 나눗셈까지)로, 2 ULP 목표를 넘었다. 주 정의역은 극점을 벗어난 `|x| ≤ 6.5`로 —
   `tan'(x) = 1 + tan²(x)`가 축소의 잔차 인자 오차를 증폭시키므로 `sin`/`cos`보다 좁다.
   유한하지 않은 입력은 `sin`/`cos`와 마찬가지로 `NaN`을 낸다.
2. **Slang 미러.** `slang/approx.slang`에 `es_tan_kernel` / `es_tan`과 여섯 개의 `TAN_C*`
   리터럴을 같은 순서, 같은 리터럴 텍스트로 추가한다. `slang_mirror.rs`는 상수를 자동으로
   집어내며, 그 Horner 스팟체크 목록에 `tan` 식이 추가되어 재결합된 미러는 여전히 실패한다.
3. **`Intrinsics::from_fovy`.** `fovy_rad`는 `f64`로 유지된다(`es_assets::scene::Camera`가
   그렇게 저장하기 때문이다); 한 번 캐스트한 뒤에는 끝까지 `f32`이며, 순서는 고정된다 —
   절반, `approx::tan`, 나눗셈. `cx`/`cy`는 무의미했던 `f64::from(w) as f32` 왕복을 잃는다
   (제거된다).
4. **테셀레이션.** `ellipsoid_tris`와 `capsule_tris`는 `approx::{sin, cos}`를 거쳐 단위
   방향을 `f32`로 계산한 뒤, 정확히 `f64`로 확장하고 `f64` 반지름으로 스케일한다. 경도
   각도는 `phi_of`로 옮겨졌으며, 이는 `seg == SPHERE_SEGMENTS`를 세그먼트 0으로 접어서
   이음매가 `sin(2π)` 잔차가 아니라 동일한 비트로 닫히게 한다 — `f32`에서 그 잔차는
   ~1e-7로, 대체된 `f64` 잔차보다 아홉 자릿수 더 크다.

## oracle (오라클)

```
cargo test -p es-math approx:: -- --nocapture
cargo test -p es-render -- --nocapture
cargo xtask verify-goldens
```

새 테스트들이며, 수정 전 코드에 대해 먼저 작성되었다:

- `es-math approx::tests::tan_ulp_within_target` — 조밀 + 의사난수 스윕, 밴드당 ≥ 200k점,
  `f32`로 반올림한 `f64::tan`을 참조로 삼는다. 참조값이 `1e3`을 넘는 지점(극점의 ~1e-3
  이내)은 건너뛰고 개수만 센다. `[-1.5, 1.5]`와 `[-6.5, 6.5]`에서 ≤ 2 ULP를 단언한다;
  `[-1e3, 1e3]`은 기록용으로만 출력하고 단언하지 않는다.
- `es-math approx::slang_mirror::*` — 기존의 한 쌍이며, 이제 `tan` 리터럴과 `tan` Horner
  식도 다룬다.
- `es-render view::tests::intrinsics_come_from_approx_tan_in_f32` — `fy`가
  `(h as f32 * 0.5) / approx::tan(fovy as f32 * 0.5)`와 비트 단위로 같음을 단언한다. 연산
  *과* 그 순서를 함께 고정한다.
- `es-render scene::tests::curved_shapes_upload_the_vertices_the_cpu_reference_traverses` —
  구 + 캡슐 + 실린더 씬: `to_floats()`(GPU가 받는 것)의 모든 정점이 `tris[i].v`
  (`cpu::rasterize`가 순회하는 것)의 대응 성분과 비트 단위로 같고, 모두 유한하며,
  테셀레이션을 반복해도 `==`임을 단언한다.

측정값 (x86-64 Windows, debug; GPU 테스트는 RTX 4060에서 실행됨):

| 주장 | 결과 |
|---|---|
| `approx::tan` 최대 ULP, `[-1.5, 1.5]` / `[-6.5, 6.5]` | **2** / **2** |
| `approx::tan` 최대 ULP, `[-1e3, 1e3]` (기록만) | 3 |
| `sin`/`cos`/`exp`/`ln`/`atan2`/`sqrt`/`rsqrt` | 변화 없음: 1/1/1/1/2/0/1 |
| CPU 레퍼런스 vs 골든 4개 | 비트 동일 |
| GPU `Rs` `Rgb8` / `SegmentationId` vs 골든 | 비트 동일 |
| GPU `Rs` `Depth32` / `Normal` vs 골든 | 0 ULP / 0 ULP |
| GPU `Pt` 1 spp vs CPU | 0 ULP, 정규화 0 |

**골든은 재생성되었다**, `cargo test -p es-render --test render -- --ignored
generate_goldens`(CPU 레퍼런스로만, GPU로는 절대 하지 않음)를 실행한 뒤
`GOLDEN_UPDATE=1 cargo xtask verify-goldens`로. 원인: `approx::tan(0.6)`은 호스트의
`0.68413681`에 대해 `0.68413687`로, 1 ULP 차이이며, 이는 64×64 / `fovy = 1.2`에서 `fy`를
`46.774269`에서 `46.774265`로 옮긴다 — 이 역시 1 ULP다. 광선 방향의 서브픽셀 변화이므로,
차이는 실루엣 에지에 국한된다:

| 파일 | 차이 |
|---|---|
| `cornell_rs_rgb8.bin` | 12288 바이트 중 57개 차이; 최대 델타 183, 빨간 벽/흰 상자 에지에서 |
| `cornell_rs_depth.bin` | 4096 floats 중 1604개 차이; 최대 절대값 4.05e-6 m, 최대 17 ULP |
| `cornell_rs_seg.bin` | 4096 픽셀 중 19개가 이웃 geom을 취함 |
| `cornell_pt1spp.bin` | **변화 없음, 바이트 단위로 동일** |
| `.json` 사이드카 4개 | 변화 없음 |

테스트를 통과시키려고 골든을 편집한 것은 없다: 세 `.bin` 파일은 선언된 생성기에 의해 다시
만들어졌을 뿐이며, GPU는 여전히 이를 정확히 재현한다.

## forbidden (금지)

- `crates/es-gpu`에 대한 어떤 변경(다른 패킷이 소유), 또는 다시 읽는 것 이상의
  `es-render/src/renderer.rs` 변경.
- `tan`을 위한 `sin(x) / cos(x)`, 또는 두 번째 범위 축소: `reduce_quadrant`가 두 파일이
  미러링하는 유일한 축소다.
- `approx`에서의 `mul_add`, 재결합, 조회 테이블, 또는 디바이스 속성에 따른 분기(§3.2 계약).
- 한쪽에서만 계수를 편집하거나 `coeffs.rs`의 리터럴을 재포맷하는 것 — 미러 테스트는 리터럴
  텍스트를 바이트 단위로 비교한다.
- `SPHERE_SEGMENTS` / `SPHERE_RINGS` / `CAP_RINGS` 또는 Cornell 씬을 바꾸는 것: 둘 다 S-11과
  무관한 이유로 골든을 무효화한다.
- GPU 경로로부터 골든을 재생성하거나 `.bin`을 손으로 편집하는 것.
