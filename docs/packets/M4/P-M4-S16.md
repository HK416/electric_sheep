## spec

IR-C put `es-ir` at **6,205** code lines, over the 6,000 target (5,842 at M3). Rule 1 forbids a
second layer-6 crate that `es-ir` could depend on, so the split goes **down**, into the existing
layer-2 `es-ir-types` — the same move `P-M0-R4` made for `types` / `image` / `diag` / `codes`.
Two blocks qualify, both already free of `Graph`, `IrNode` and `NodeId`:

| moved to | from | code lines |
|---|---|---|
| `es_ir_types::expr` | `task.rs` spec 6.3 parameter enums (`JointQuantity`, `ArithOp`, `CmpOp`, `LogicOp`, `ReduceOp`, `NormKind`, `MathFunc`, `Aggregation`, `TerminationKind`, `ActionSpace`, `Distribution`) and the spec 6.5 `Expr` + `Expr::eval` | 184 |
| `es_ir_types::chain` | `hash.rs` `HashChain`, `DatasetHash`, `HardwareCapability`, `ChangedComponent`, `CHAIN_TAG` — digests only | 89 |

`es-ir` re-exports both at their original paths (`pub use es_ir_types::expr::{..}` in `task`,
`pub use es_ir_types::chain::{..}` in `hash`), so `es_ir::task::Expr`, `es_ir::CmpOp`,
`es_ir::HashChain` and every other path still resolve and **no downstream crate changed**.
Three functions widened from private to `pub` because their callers are now across the crate
boundary: `JointQuantity::unit`, `MathFunc::is_transcendental`, `Distribution::canonical`.
`Distribution::canonical` inlines the two-line body of `task.rs`'s private `wf64s` rather than
export a helper.

What deliberately did **not** move, and why the review's other candidates were dropped:

- `canonical_hash` / `canonical_order` / `norm.rs` need `Graph<N>`.
- IR-C `control.rs` validates against a `TaskIr` and hashes itself as a `Graph<ControlNode>` —
  it cannot go below the graph.
- `serial.rs`'s TOML mirrors are typed on `TaskIr` / `ObservationIr` / `LearningGraph`.
- The `testing` generators are already **excluded** from the count: `context-budget` drops
  `#[cfg(any(test, feature = "testing"))] mod` bodies, so moving them would score zero.

## acceptance

- `es-ir` ≤ 6,000 code lines with headroom; `es-ir-types` well inside its own budget.
- `cargo test -p es-ir -p es-ir-types --features es-ir/testing` green, including the
  hash-chain `diff` suite and the Appendix B.7 property tests, which exercise the moved code
  through the re-exports.
- `cargo xtask layering` clean: `es-ir` (6) → `es-ir-types` (2) is a downward edge.
- `cargo fmt --check` and `clippy -D warnings` clean for both crates.
- No behavior change: only `pub` visibility widened, no type, variant, field, encoding or hash
  input was altered.

## forbidden

Anything outside `context`. Moving `graph.rs`, `norm.rs`, `serial.rs`, `control.rs`,
`factory.rs` or an entire IR module. Creating a new crate. Changing any canonical encoding,
hash tag or `SCHEMA_VERSION`. Renaming a moved item, or dropping a re-export and asking a
downstream crate to change its `use`. Adding a new trait (INV-17).
