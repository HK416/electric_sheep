# P-M4-S15 — ACT 체크포인트 다운로드를 리비전에 고정, `*.safetensors`/`*.json`만

M4 리뷰 should-fix S-15(`docs/reviews/M4.md`)를 닫는다: `docs/api-notes/lerobot-act.md:18-20`은
`allow_patterns`도 `revision`도 없는 `snapshot_download`를 문서화하고 있었으므로, 상류의
`lerobot/act_aloha_sim_transfer_cube_human`에 `.bin`/`.ckpt`가 추가되면 `model.safetensors`
옆에 그대로 내려받아질 것이고, `ACTPolicy.from_pretrained`(`act_ref.py:88`,
`lerobot.policies.pretrained` 경유)가 safetensors 파일보다 pickle로 로드 가능한 파일을
선호할 수 있다 — 리뷰가 찾은 유일한 살아 있는 INV-16 노출면이다(`crates/es-policy/python/
*.py`와 `crates/es-policy/tests/act_checkpoint.rs`를 grep해도 다른
`snapshot_download`/`hf_hub_download` 호출은 없었다: `act_ref.py`는 이미 채워진 디렉터리를
읽기만 한다).

Spec: `INV-16`(가중치는 `safetensors`로, pickle 기반 로딩은 절대 안 됨), 사양 §1.4(오라클은
조용히 잘못된 파일과 비교하기 시작해서는 안 된다).

## context (범위)

```
docs/api-notes/lerobot-act.md   (download snippet: allow_patterns, revision, post-download check)
docs/packets/M4/P-M4-S15.md     (new)
```

## spec (사양)

- `allow_patterns=["*.safetensors", "*.json"]`는 다운로드를 lowering이 읽는 두 파일 종류로
  제한한다; 해석된 리비전의 트리에는 `README.md`, `demo.gif`, `training_curves.png`도
  있지만 어느 것도 매치되지 않는다.
- `revision="ba73b2766f1371cdc133ca4efb97eb090d744625"`는
  `docs/api-notes/lerobot-act.md`의 키 이름, shape, 기본값이 검증된 바로 그 커밋을
  고정한다(2026-09-14에
  `HfApi().model_info("lerobot/act_aloha_sim_transfer_cube_human").sha`로 해석됨).
  리포지토리에 대한 미래의 커밋이 오라클이 비교하는 대상을 조용히 바꿀 수 없다.
- 다운로드 후의 assertion(`*.bin`/`*.pt`/`*.ckpt`/`*.pkl`에 대한 `Path(path).rglob`)은 같은
  불변식에 대한 두 번째의 독립적인 검사다 — 이중 안전장치다: `allow_patterns`는 서버 측
  필터라서(미러나 `huggingface_hub`의 버그가 원리적으로 이를 우회할 수 있다), assertion은
  실제로 디스크에 내려온 것을 검사한다.
- 오늘 기준 `crates/es-policy/python/*.py`나 `crates/es-policy/tests/act_checkpoint.rs`에는
  다른 `snapshot_download`/`hf_hub_download` 호출이 없다 — `act_ref.py`의
  `ACTPolicy.from_pretrained(path)`는 `ES_ACT_CHECKPOINT`가 이미 가리키는, 이 스니펫(또는
  CI의 대응물)이 미리 채워둔 디렉터리에 대해 실행된다. 거기서 바꿀 것은 없다.

## oracle (오라클)

```
<venv>/Scripts/python.exe -c "<the updated snippet from docs/api-notes/lerobot-act.md>"
ES_PYTHON=<venv>/Scripts/python.exe \
  ES_ACT_CHECKPOINT=target/lerobot-cache/act_aloha_sim_transfer_cube_human \
  cargo test -p es-policy act -- --nocapture
```

## acceptance (수용 기준)

- `docs/api-notes/lerobot-act.md`의 다운로드 스니펫은 고정된 리비전에 대해 깨끗하게
  실행되며, 스냅샷 디렉터리에 금지된 확장자가 없음을 단언한다.
- `cargo test -p es-policy act -- --nocapture`는 고정 리비전 체크포인트에 대해 여전히
  `RAN act_checkpoint: lerobot 0.6.1 torch 2.11.0+cpu shape [100, 14] max_abs 0e0
  max_rel 0e0`(또는 그에 준하는 것)을 출력한다 — S-15가 gate 5를 퇴행시켜서는 안
  된다(spec §8.9, M4 리뷰).
- 고정된 리비전은 이 패킷과 `docs/api-notes/lerobot-act.md`에 기록되어 있다.

## forbidden (금지)

- `crates/es-policy/src/**` — lowering이나 런타임 변경 없음; 이것은 다운로드 위생(hygiene)
  수정이다.
- 다운로드 관련 줄을 넘어서는 `crates/es-policy/tests/act_checkpoint.rs`, 혹시 그런 줄이
  거기 있더라도(현재는 없다) — 그 파일의 SKIP/FAIL 분기는 다른 패킷의 소유다.
- 다른 패킷의 범위(`es-env`, `es-eval`, `es-data`, `es-usd`, `es-script`, `es-gpu`,
  `es-render`, R8의 `crates/es-core/src/id.rs` / `python/es/selfcheck.py`).
