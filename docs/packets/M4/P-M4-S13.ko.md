# P-M4-S13 — Task IR가 지원하지 않는 `schema_version`을 거부한다

Spec: 사양 6.1(Task IR 범위), 사양 5.3(버전은 해시 입력이다). `docs/reviews/M4.md`의
**S-13**을 닫으며, 그 안의 "Human decision — Task IR `schema_version` 1 → 2"에 수용
규칙으로 답한다.

## context (범위)

```
crates/es-ir/src/task.rs
crates/es-ir-types/src/codes.rs
docs/design/ir-types.md
docs/design/ir-types.ko.md
docs/packets/M4/P-M4-S13.md
```

## spec (사양)

`task.rs`는 IR-C를 위해 `SCHEMA_VERSION`을 `2`로 올리고 `self.schema_version`을
`task_hash`에 해싱해 넣지만, `TaskIr::validate`는 그것을 전혀 살펴보지 않았다: `99`라고
주장하는 파일이 깨끗하게 검증되어, 이 빌드가 읽을 수 없는 스키마에 고정된 해시를
얻었다. `DeploymentIr::validate`는 이미 자신의 것(`DEP-001`)을 거부한다.

규칙은, 그 필드를 해싱하는 것이 이미 함의하는 바에 맞춰 선택되었다:

```
accept  1 ..= SCHEMA_VERSION       reject  0, and anything > SCHEMA_VERSION   -> TASK-002
```

- `0`은 버전이 아니라 기록되지 않은 필드다.
- 이 빌드의 버전을 넘어서는 버전은 이 빌드가 볼 수 없는 노드와 필드를 담고 있다; 이를
  역직렬화하면 그것들을 조용히 떨어뜨리게 되고, 그 결과로 나온 `task_hash`는 결코
  검증된 적 없는 무언가를 가리키게 된다.
- 지원되는 이전 버전들은 **마이그레이션 단계 없이** 계속 읽을 수 있다. 버전 그 자체가
  해시 입력이기 때문에 자신의 해시를 유지한다 — 이는 우연이 아니라 그 자체가 속성이다.

`TASK-002`("지원하지 않는 Task IR schema version", Error, 사양 6.1)가 `codes::CODES`에
합류한다. 이 검사는 모든 경로가 거쳐 가는 단 하나의 가드인 `TaskIr::validate`에 자리
잡는다: `task_from_toml`과 `serde_json` 둘 다 이후 검증되는 `TaskIr`을 만들어내므로,
규칙의 두 번째 사본 없이도(그리고 새 `SerialError` variant 없이도) 로드 경로가 모두
커버된다.

## oracle (오라클)

```
cargo test -p es-ir --features testing task::tests::unsupported_schema_versions_are_rejected
cargo test -p es-ir-types codes
```

첫 번째는 `0`과 `SCHEMA_VERSION + 1` 각각이 정확히 `[TASK-002]`를 보고하는지,
`1 ..= SCHEMA_VERSION` 전체가 깨끗하게 검증되는지, 그리고 `task_to_toml`로 쓰고
`task_from_toml`로 다시 읽은 `SCHEMA_VERSION + 1` task도 `TASK-002`를 보고하는지를
단언한다. 두 번째는 기존의 codes-registry 스위트다: `every_exported_constant_has_an_entry`와
`codes_are_sorted`가 이제 `TASK-002`도 다룬다.

## acceptance (수용 기준)

- 새 테스트가 통과한다; `cargo test -p es-ir -p es-ir-types --features es-ir/testing`은
  초록색이다(기존 픽스처 중 범위를 벗어난 버전을 쓴 것은 없었다).
- `cargo check --workspace --all-targets --features es-ir/testing`가 통과한다: 하류의
  어떤 크레이트도 이제 거부되는 `TaskIr`을 만들지 않는다.
- `cargo xtask check-spec-refs`가 새로운 `6.1` 참조를 해석한다.
- `cargo fmt --check`와 `clippy -D warnings`가 두 크레이트 모두에서 깨끗하다.

## forbidden (금지)

`context` 바깥의 무엇이든. `SCHEMA_VERSION`, `task_hash`가 섞어 넣는 것, 정규
인코딩(canonical encoding)을 바꾸는 것. 마이그레이션/업그레이드 경로를 추가하는
것(이는 별도의 결정이며, `ir-types.md`에 "마이그레이션 없음"으로 기록되어 있다).
`serial.rs`에 같은 검사를 두 번째 가드로 추가하는 것. `DeploymentIr`, `ObservationIr`,
`LearningGraph`, `EvaluationIr`의 버전 처리를 건드리는 것.
