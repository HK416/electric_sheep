# P-M4-S15 — pin the ACT checkpoint download to a revision, `*.safetensors`/`*.json` only

Closes M4 review should-fix S-15 (`docs/reviews/M4.md`): `docs/api-notes/lerobot-act.md:18-20`
documented a `snapshot_download` with no `allow_patterns` and no `revision`, so a `.bin`/`.ckpt`
added upstream to `lerobot/act_aloha_sim_transfer_cube_human` would land on disk next to
`model.safetensors`, and `ACTPolicy.from_pretrained` (`act_ref.py:88`, via `lerobot.policies.
pretrained`) may prefer the pickle-loadable file over the safetensors one — the only live
INV-16 surface the review found (grep of `crates/es-policy/python/*.py` and
`crates/es-policy/tests/act_checkpoint.rs` found no other `snapshot_download`/`hf_hub_download`
call: `act_ref.py` only reads a directory that is already populated).

Spec: `INV-16` (weights via `safetensors`, never pickle-based loading), spec §1.4 (the oracle
must not silently start comparing against the wrong file).

## spec

- `allow_patterns=["*.safetensors", "*.json"]` restricts the download to the two file kinds the
  lowering reads; the resolved revision's tree also has `README.md`, `demo.gif`,
  `training_curves.png`, none of which match.
- `revision="ba73b2766f1371cdc133ca4efb97eb090d744625"` pins the exact commit
  `docs/api-notes/lerobot-act.md`'s key names, shapes and defaults were verified against
  (resolved via `HfApi().model_info("lerobot/act_aloha_sim_transfer_cube_human").sha` on
  2026-09-14). A future commit to the repo cannot silently change what the oracle compares
  against.
- The post-download assertion (`Path(path).rglob` over `*.bin`/`*.pt`/`*.ckpt`/`*.pkl`) is a
  second, independent check of the same invariant — belt and suspenders: `allow_patterns` is a
  server-side filter (a mirror or a `huggingface_hub` bug could in principle bypass it), the
  assertion checks what actually landed on disk.
- No other `snapshot_download`/`hf_hub_download` call exists in `crates/es-policy/python/*.py`
  or `crates/es-policy/tests/act_checkpoint.rs` today — `act_ref.py`'s `ACTPolicy.from_pretrained
  (path)` runs against a directory `ES_ACT_CHECKPOINT` already points at, populated by this
  snippet (or CI's equivalent) beforehand. Nothing there to change.
