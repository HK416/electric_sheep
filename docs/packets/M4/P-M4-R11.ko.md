# P-M4-R11 — 오라클 계층이 CPU 러너에서 돌 수 있는 모든 레퍼런스 오라클을 실행한다

`Reference oracle tier (spec 1.4, 28.7)` job은 `main`에 대한 모든 push에서 실패한다
(`c0fd56b`의 run 34780514440, `d341599`의 run 34797187557). 테스트 스텝은 `^SKIP` 줄이 하나라도
있으면 실패하는데, job은 `mujoco`와 `torchvision`만 설치하므로 여전히 15개 테스트가 SKIP된다:

- `crates/es-compile/tests/observation_gpu.rs`의 GPU lowering 테스트 9개 — `no slangc`; 러너에
  없는 Vulkan 장치도 필요하다;
- `crates/es-physics-backend/src/newton.rs`의 `newton_*` 테스트 2개 — `newton` 미설치;
- `crates/es-policy/src/reference.rs`의 diffusers 오라클 3개 — `diffusers` 미설치;
- `a_real_lerobot_act_checkpoint_reproduces_its_actions` 1개 — `ES_ACT_CHECKPOINT` 미설정.

모든 push에서 빨간 job은 아무 신호도 주지 못한다. P-M1-R7은 newton(M2), diffusers와 ACT(M4)
오라클, GPU lowering 테스트가 생기기 전에 이 job을 어떤 SKIP에도 실패하도록 설계했고, 그 뒤
어느 것도 설치 목록에 추가되지 않았다.

Spec: 사양 §1.4(레퍼런스 오라클은 필수다; SKIP은 통과가 아니다), §26.2(PR 계층의 < 10분 예산 —
건드리지 않는다, 이 job은 push와 dispatch에서만 돈다), §12.4(여기서 돌 수 없는 것은 초록이 아니라
`Target / Status: unverified`다). INV-16: safetensors만, pickle 없음.

## spec (사양)

- **CPU에서 도는 것을 설치한다.** `install reference oracles`에 `diffusers==0.40.0`
  (`docs/api-notes/torch.md`), `newton==1.6.0`과 `warp-lang==1.17.0`
  (`docs/api-notes/newton.md`: 같은 wheel이 warp를 통해 CPU 전용으로 돈다)을 추가한다.
  `mujoco==3.13.0`과 `torchvision==0.29.0`(그리고 그것이 끌어오는 `torch==2.14.0`)은 그대로다.
- **LeRobot은 자기 인터프리터를 갖는다.** lerobot 0.6.1은 torch 2.11.0, torchvision 0.26.0,
  numpy 2.2.6으로 해석되며(`docs/api-notes/lerobot-act.md`) 골든을 생성하는 torch 2.14를
  다운그레이드할 것이다. 새 스텝이 `$RUNNER_TEMP/lerobot-venv`를
  `torch==2.11.0+cpu torchvision==0.26.0+cpu lerobot==0.6.1`로 만들고, api-note의 스니펫 —
  고정된 revision, `*.safetensors`/`*.json`만, pickle 단언 — 으로 체크포인트를 `target/` 밖인
  `$RUNNER_TEMP`에 받으므로 `rust-cache`가 200 MB의 가중치를 저장하지 않는다.
- **ACT 오라클은 자기 스텝에서 돈다.** `ES_PYTHON`과 `ES_ACT_CHECKPOINT`가 그 venv와 체크포인트를
  가리키며, 메인 스텝은 이름으로 그것을 건너뛴다. 로그에 `RAN act_checkpoint` 줄 — SKIP은 결코
  출력하지 않는 줄 — 이 없으면 스텝이 실패한다.
- **GPU SKIP은 키워드가 아니라 정확한 사유로 식별한다.** 메인 스텝은 `observation_gpu.rs`가 돌 수
  없을 때 출력하는 두 형식 — `SKIP <test>: no slangc (…)`와 `SKIP <test>: no Vulkan device (…)` —
  을 제외한 모든 `SKIP` 줄에서 여전히 실패한다. `cargo xtask ci`의 더 넓은 키워드 목록(`gpu`,
  `vulkan`, `render`, `slangc`, `device`)은 여기서 의도적으로 재사용하지 않는다: newton이나 torch의
  SKIP은 "device"를 포함할 수 있는 Python 오류 문구를 담으므로 조용히 통과해 버릴 것이다. GPU
  테스트는 GPU 호스트에서 `ES_REQUIRE_GPU=1 cargo xtask ci`로 돌며(renderer-14, RTX 4090: 모두
  실행됨) 이 러너에서는 `Target / Status: unverified`로 남는다.
- `mjwarp`는 P-M1-R7처럼 이름으로 제외된 채 남는다: CUDA가 필요하다. `ci` job은 바뀌지 않는다.

## oracle (오라클)

job은 GitHub에서만 돈다. push 전에 renderer-14에서 러너가 보는 그대로 재현한다: GPU 숨김
(`CUDA_VISIBLE_DEVICES=`, `VK_ICD_FILENAMES=/nonexistent`), `PATH`에 slangc 없음, `ES_*` 변수 없음,
스텝의 명령 그대로 `pip`로 만든 venv. 필터 자체는 두 개의 합성 로그로 확인한다. 그다음:

```
python -c "import yaml; print(list(yaml.safe_load(open('.github/workflows/ci.yml'))['jobs']))"
cargo xtask check-scope docs/packets/M4/P-M4-R11.md
gh run watch <run id of the push> --exit-status
```

## acceptance (수용 기준)

- 재현, 메인 스텝: 0으로 종료한다; newton, diffusers, MuJoCo, torch, 골든 오라클이 모두 실행되고,
  SKIP은 `observation_gpu.rs`의 GPU 테스트 9개뿐이다.
- 재현, ACT 스텝: `RAN act_checkpoint`와 함께 0으로 종료한다.
- 필터는 GPU 줄 옆에 `SKIP newton_pendulum: …` 줄이 있는 로그에서 1로, GPU 줄만 있는 로그에서
  0으로 종료한다.
- push에서 `CI` 워크플로의 두 job이 모두 초록이다.
- `.github/workflows/ci.yml`이 파싱되고 job `ci`와 `oracles`를 나열한다; `ci` job의 스텝은 바이트
  단위로 바뀌지 않는다.

## forbidden (금지)

- `ci` job(PR 게이트): 스텝, 트리거, `timeout-minutes`.
- `mujoco_warp` 설치, GPU 또는 self-hosted 러너 추가, 이 러너에서 GPU 오라클을 검증됨으로 표기.
- 메인 스텝이 모든 SKIP을 무시하게 하거나 `continue-on-error: false`를 없애는 것.
- `crates/**` — 테스트나 메시지 변경 없음; 필터는 메시지를 있는 그대로 매칭한다.
